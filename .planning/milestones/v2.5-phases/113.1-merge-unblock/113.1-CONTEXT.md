## Implementation Decisions

### D-113-Q — `OptimizedSseTransport` (the unbounded `reqwest` read)

- **D-01: Deprecate + hard cap. Do NOT retire the transport.** The deferred item assumed it had no
  consumers; it does — it is `pub use`'d at `src/shared/mod.rs:106` **and** demoed by
  `examples/t03_sse_optimized.rs` (registered in `Cargo.toml:387`, `required-features = ["sse"]`).
  Retiring it removes two public items and breaks the milestone's *"`cargo public-api` shows zero
  removed public items"* additivity claim, which Phase 113's own gate report leans on. Instead:
  keep the API, add `#[deprecated]` pointing at `StreamableHttpTransport`, and bound the read.
- **D-02: Bound via `reqwest::Response::chunk()`, NOT `bytes_stream()`.** Verified during
  discussion: `chunk()` (reqwest-0.13.2, `src/async_impl/response.rs:315`) is **not** feature-gated;
  only `bytes_stream()` is (`:354-356`, `#[cfg(feature = "stream")]`). The crate pins
  `reqwest = { default-features = false, features = ["json", "rustls", "form"] }`
  (`Cargo.toml:146`) — no `stream`. Accumulating via `chunk()` with a running total is therefore
  **authoritative and costs zero dependency-surface change**, unlike the deferred item's suggested
  `bytes_stream()` fix. `Content-Length` is an early-refusal optimisation only, never the
  authority (the 113-20 rule).
- **D-03: The ceiling is the existing `pub const DEFAULT_HTTP_SSE_BUFFERED_BYTES`**
  (`src/shared/http.rs:116`, 16 MiB) that `connect_sse` already uses. One number for every SSE read
  in the crate. Explicitly **not** a new `OptimizedSseConfig` field — that struct has all-`pub`
  fields, so adding one is `constructible_struct_adds_field` and `cargo semver-checks` runs in this
  milestone's gate.
- **D-04: `examples/t03_sse_optimized.rs` STAYS**, with `#![allow(deprecated)]` and a header comment
  naming `StreamableHttpTransport` as the replacement, plus a note on the `examples/README.md:378`
  row. The transport still ships in 2.x, so a shipped example for it is not wrong, and it is the
  only compile-check consumer. Note `make lint` runs `--lib --tests` (`Makefile:152`), not
  `--examples`, so the deprecation warning does not red the gate by itself.
- **D-05: The tripwire allowlist pin becomes `assert_eq!(WHOLE_BODY_ALLOWLIST.len(), 0)`** with the
  message rewritten: the list is now **EMPTY**, and any entry at all is a new unbounded read
  exempted rather than fixed — a human decision on the record. The entry at
  `tests/v2_bounded_reads_tripwire.rs:588-600` must be deleted **by hand**; the tripwire's
  dead-entry rule does not cover this list. Rejected: relaxing to `<= 1`; deleting the mechanism.

### D-113-U — the two POST entrypoints (PR-blocking complexity)

- **D-06: TWO extractions, restoring symmetry between the entrypoints — not one.** Reading both
  functions end to end turns up an asymmetry the deferred item does not mention:
  `handle_post_with_middleware` **already delegates** its 4-arm ingress dispatch to
  `dispatch_message_with_middleware` (`:3670`), while `handle_post_fast_path` still has that same
  `match ingress` **inline** at `:3179-3236` (~58 lines) — a large share of its cog 30. So:
  1. extract the copy-pasted v2 header gate (fast `:3123-3151` / middleware `:3573-3616`) into
     `resolve_v2_gate`;
  2. extract the fast path's inline 4-arm match into `dispatch_message_fast`, mirroring the
     middleware twin that already exists.

  Rejected: full pipeline unification into one shared entrypoint body — that is the "refactor slice
  of its own with real regression surface across every transport test" D-113-F warned against.
- **D-07: The `FastPathDispatch` / `MiddlewareDispatch` struct merge is NOT in scope.** They are
  field-for-field identical (`:2375` / `:3335`) and merging them is purely mechanical, but it
  reduces no cognitive complexity — it is cleanup riding along. Recorded as a deferred idea below.
- **D-08: The legacy-version guard asymmetry is DELIBERATE — do NOT "unify" it.** The fast path
  gates on `!is_init_request && !is_v2_request` (`:3167`); the middleware path gates on
  `!is_v2_request` only and passes `is_init_request` **into**
  `validate_protocol_version_with_error_hook` (`:3639`), whose own rustdoc reads *"A no-op for init
  requests"* (`:3303-3304`). The init check is folded inside the wrapper by design. A refactor that
  "harmonises" these two call sites silently changes behavior.
- **D-09: The gate extraction follows the file's own sibling convention** — a plain
  `resolve_v2_gate(...) -> Result<(ctx, v2_outbound), Response>` plus a thin
  `resolve_v2_gate_with_error_hook(...)` that delegates to it and adds `report_middleware_error` on
  the `Err` arm. This is field-for-field the existing
  `resolve_session_for_request` (`:2112`) / `resolve_session_with_error_hook` (`:3280`) and
  `validate_protocol_version` (`:1913`) / `validate_protocol_version_with_error_hook` (`:3305`)
  pattern. A reviewer already knows how to read it, and the fast-vs-middleware divergence lives in
  ~8 lines instead of ~30. Rejected: one function taking an optional hook parameter (breaks the
  file's convention); leaving the `Reject` arm duplicated at each call site (leaves the copy-paste
  half-copy-pasted).
- **D-10: The target is cognitive complexity `<= 20` on BOTH handlers — not merely under the
  gate's 25.** This is an explicit phase target, so the planner sizes the extractions to hit it
  rather than stopping at the first green PMAT run. Rationale: Phase 113 moved these two from
  22/21 to 30/31 while adding the v2 gate, and Phases 114–119 add more to the same entrypoints.
  Landing at 24 means Phase 114 puts CI red again and someone re-does this work.
- **D-11: Evidence = existing transport suite green + PMAT `<= 20` + a RECORDED NEGATIVE CONTROL
  per extraction.** For each extraction, deliberately break it (reorder the gate past session
  resolution; drop the middleware `Reject` hook), show a **named** test goes RED, then revert.
  This matches the house style plans 113-29…113-32 already established. It matters here because
  both handlers carry load-bearing **ordering** constraints — the v2 gate MUST run before session
  resolution (the era decides whether sessions apply at all, HTTP-01) and before legacy
  protocol-version validation (an accepted v2 request carries `MCP-Protocol-Version: 2026-07-28`,
  which the static SUPPORTED check would reject) — and that ordering is currently enforced **only
  by prose comments**. The negative control is what proves the suite actually constrains it.
  Considered and not taken: a permanent ordering tripwire test (see Deferred Ideas).

### D-113-R — the quadratic scan in `SseParser`

- **D-12: The fix is a scan-window cursor, and it is SMALLER than `deferred-items.md:942-953`
  suggests.** That sketch was written against an older shape (a per-line `drain(..=line_end)`);
  the code at `:500-535` already uses a single `consumed` cursor with one drain at the end. The
  actual change: capture `scan_start = self.buffer.len()` **before** `self.buffer.push_str(data)`
  and start the `find('\n')` search there instead of at 0. `consumed` still starts at 0 so the
  final `drain(..consumed)` and the `line_end > consumed` CRLF lookback guard are unchanged.
  Sound because the retained prefix is newline-free on entry.
- **D-13: Three-part proof.** (1) a **RED-first** 1-byte-chunk time budget that fails on today's
  code and passes after; (2) a **chunking-invariance property test** — for an arbitrary byte stream
  split at arbitrary boundaries, the emitted event sequence AND the retained tail are identical
  regardless of chunking; (3) a fuzz run over the existing `fuzz/fuzz_targets/subscription_listen_frames.rs`
  target. (2) is the property this specific optimisation can violate, and it is warranted: this
  function's one historical remote crash (T-113-67, a byte-vs-character index confusion that
  panicked on remote bytes) was found by a property test, not by review.
- **D-14: The existing `sse_parser_feed_stays_within_its_linear_time_budget` (`:1051`) cannot be
  the guard and must not be treated as one.** At its 4 KiB chunking the re-scan is single-digit
  milliseconds; a negative control (injecting a per-chunk full-buffer copy) moved it 6.7 ms → 11.7 ms
  and it still passed. Its rustdoc already says so — read it.
- **D-15: Replace the `debug_assert!(!self.buffer.contains('\n'))` at `:474` with a dedicated
  test.** After the fix this invariant is the *soundness precondition* (skipping the retained
  prefix is only correct because that prefix cannot contain a newline), but the assertion is itself
  a full scan of the retained buffer on every call — so the quadratic survives in debug builds,
  which is exactly where a 1-byte-chunk proptest runs. Delete the per-call scan; keep the invariant
  as a comment stating what it guarantees, and pin it with one explicit unit test asserting the
  buffer is newline-free after feeds of every shape (mid-line split, CRLF split across chunks,
  empty line, multi-byte character). Rejected: keeping it and running perf tests `--release`;
  cfg-gating it.
- **D-16: Give `feed` the same TWO-guard pair its sibling already has.** `take_utf8_prefix` carries
  both `..._stays_within_its_linear_time_budget` (`:894`) **and**
  `..._cost_grows_linearly_not_quadratically` (a ratio test across two input sizes). `feed` only
  ever got the budget half. Add the ratio test — it is the machine-independent one, so a slow or
  loaded CI box cannot flake it and a merely-worse-but-under-ceiling regression cannot slip through.
  **Keep** the existing 4 KiB test (it covers the many-lines-per-chunk shape — a different failure
  mode, the one fixed in `0493d9fb`), with its rustdoc amended to state plainly what it does and
  does not catch.

## Specific Ideas

- **"Not just under the gate" is the point of D-10.** Phase 113 burned 8–9 complexity points on
  these two handlers in a single phase. A phase that lands them at 24 has bought nothing; the
  target is headroom for Phases 114–119, which add to the same entrypoints.
- **Every guard in this phase must be falsifiable.** The whole reason HTTP-09 exists is that the
  previous three rounds each capped the sites that round's review named while the next review found
  another. The specific instance to remember: the existing linear-time budget test passes on the
  very quadratic shape it was written to catch, proven by negative control. A guard that cannot go
  RED is not a guard.
- **Prefer the file's own conventions over "better" ones.** The sibling-pair extraction (D-09), the
  reused 16 MiB ceiling (D-03), and the two-guard test pair (D-16) were all chosen because the
  codebase already reads that way in the immediate neighbourhood.
- **Threat-model honesty over uniform coverage** (D-18). The 18 auth reads are the same defect
  *class* but a different *trust boundary* — semi-trusted IdP, not arbitrary peer. They get
  recorded and assigned, not swept into HTTP-09 to make a number look complete.
