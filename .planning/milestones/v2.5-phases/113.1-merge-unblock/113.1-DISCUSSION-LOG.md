## OptimizedSseTransport fate (D-113-Q)

### Q1 — How should D-113-Q be closed?

| Option | Description | Selected |
|--------|-------------|----------|
| Deprecate + hard cap | Keep the public API, add `#[deprecated]`, bound the read without new deps; remove the `NOT BOUNDED` allowlist entry | ✓ |

**Notes:** Made strictly cheaper than framed once `chunk()` was confirmed not feature-gated — the cap can be authoritative with zero dependency-surface change, so option 2's only advantage (real streaming) costs a dep for a transport nobody consumes.

## D-113-R proof bar

### Q1 — What evidence closes D-113-R?

| Option | Description | Selected |
|--------|-------------|----------|
| Budget + chunking-invariance + fuzz | RED-first 1-byte budget; property test that event sequence + retained tail are chunking-independent; fuzz over `subscription_listen_frames` | ✓ |

| Fix plus existing suite | Rely on `feed_never_panics_on_arbitrary_text` and existing SSE tests | |

**User's choice:** Budget + chunking-invariance + fuzz
**Notes:** The fix is chunk-boundary-sensitive by construction, and this function's one historical remote crash (T-113-67, byte-vs-character index confusion) was found by a property test, not by review. Also established: the fix is smaller than `deferred-items.md:942-953` suggests — that sketch was written against an older per-line-drain shape.

### Q2 — What happens to the `debug_assert` full re-scan?

| Option | Description | Selected |
|--------|-------------|----------|
| Replace with a dedicated test | Delete the per-call scan; keep the invariant as a comment; pin it with one explicit unit test | ✓ |
| Keep it, test in `--release` | Leave the assertion; run perf-sensitive tests in release | |

**User's choice:** Replace with a dedicated test
**Notes:** After the fix the invariant becomes the soundness precondition, but the assertion is itself an O(n)-per-call scan — so the quadratic would survive in debug builds, which is exactly where a 1-byte-chunk proptest runs.

### Q3 — What guards should `feed` carry afterwards?
