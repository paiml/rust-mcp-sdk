<objective>
Implement the team-fs reference server (TEAM-02) with the review's path-safety fixes. A `TeamFsBackend` object-safe async trait exposes the 11 `fs__*` STORAGE operations (task completion is a protocol/server concern, so `fs__complete_task` lives in the server layer, NOT the backend trait — per the 109-02 review). A `LocalDirBackend` dev impl is backed by a real workspace directory plus a sibling `review/` directory (D-09), returns percent-encoded `file://` URLs (D-08), and — critically — replaces the review-flagged "canonicalize the parent" approach with a PURE LEXICAL normalizer that resolves `.`/`..` in memory and proves containment BEFORE any filesystem side effect, so writes to nonexistent nested parents work and no canonicalize-then-IO TOCTOU window exists. The local reference backend explicitly REJECTS symlinks (documented TOCTOU stance: race-resistant open-at traversal is out of scope for the dev backend). Wire the `team-fs` Server builder (exactly 11 tools, unknown names simply not advertised → pmcp returns "not found", never panic) and fill the HTTP-first `team-fs` dev binary. Fill the ALWAYS fuzz target over the pure lexical normalizer (the `fs_resolve` stub from 109-01).

Purpose: Ship the first reference server with dev-grade fidelity a human can open in an editor, on the storage-agnostic trait seam, with containment proven lexically (side-effect-free) by unit tests AND fuzzing.
Output: `src/fs/{backend,local,server}.rs`, `src/bin/team_fs.rs`, and the filled `fuzz/fuzz_targets/fs_resolve.rs`.
