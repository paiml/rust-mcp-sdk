<objective>
Implement the in-process small-team wiring API (D-01) as a `TeamRuntimeBuilder` + `TeamRuntime`, corrected against every 109-06 review HIGH. The builder supplies the inputs the review found missing: a `PackageResolver` (ComponentRef→AgentPackage), a `SlotResolver`, an optional completion-source OVERRIDE (the explicit injection — `AgentPackage.llm` is mandatory so there is no "no-slot fallback"), the `AgentServer` runtime seams (config, tool invoker, conversation store), a data root (for `LocalDirBackend`), an approval channel, and an enabled-server policy. `TeamRuntime::start` calls `derive_attachment` (D-05), resolves each member `ComponentRef` into an `AgentPackage` via the `PackageResolver`, and constructs each member `AgentServer` with the required seams, wiring exactly the attached servers (team-mcp iff members≥2, approval-mcp iff human_roles non-empty, plus opt-in team-fs/mem-mcp from `built_in_servers` — D-06) together in one tokio runtime over in-memory `DuplexTransport` pairs (D-04). Each attachment branch is cfg-gated on its server feature so selective feature builds compile; a requested-but-uncompiled or unknown opt-in FAILS CLOSED (error). Member LLM uses the SHARED `team::member::resolve_member_factory` (109-05). Startup is transactional (abort spawned tasks on later failure); shutdown/drop semantics are explicit. Prove "small team, one process", the team-of-one degenerate case, and a reduced-feature configuration on an injected `FixedSource` override.

Purpose: This is the library the Phase 110 `cargo pmcp team dev` CLI becomes a thin wrapper over — one definition format (TeamPackage) from laptop to platform — sharing member-LLM + package resolution with the reference dev binary, with all runtime seams made explicit.
Output: `src/compose/wiring.rs` (+ cfg gate in `compose/mod.rs`) + `tests/small_team.rs`.
</objective>
