<objective>
Consolidate the scattered error-code integer literals into ONE centralized version-gated module (VERS-06, structure-first) AND make that module the actual source of truth for the codebase's DOMINANT error-code surface: `error::ErrorCode` (a `pub struct ErrorCode(pub i32)` with 11 associated consts, referenced 210 times across 33 production files via `impl From<crate::Error> for JSONRPCError`). Also make `server/discover` (VERS-04) routable via an INTERNAL dispatch representation WITHOUT touching the public exhaustive `ClientRequest`/`Request` enums. All without touching the frozen `-32002` task-pending semantics or its locking test.

Purpose: The checker's Blocker showed `ProtocolErrorCode` (the C-style enum) is near-dead (zero external refs) while `error::ErrorCode`'s consts are the codes that actually reach the wire. If the new table were only mirrored against the dead enum, VERS-06 and ROADMAP success criterion #5 would be FALSE — three parallel representations would remain. So `error::ErrorCode`'s consts DELEGATE to `error_codes::*` (Self(error_codes::NAME)); this centralizes all 210 call sites in one change without editing any of them. The frozen task-pending `-32002` stays separate from the spec's resource-not-found rename and from `error::ErrorCode::UNSUPPORTED_CAPABILITY` (yet another `-32002` meaning — preserved by name, not reconciled).

**Reviewer concern addressed (Codex HIGH #4 — `ClientRequest::ServerDiscover` is likely not semver-minor):** adding a variant to the public EXHAUSTIVE `ClientRequest` (mod.rs:478, confirmed NOT `#[non_exhaustive]`) or to `Request` breaks downstream *exhaustive* `match` arms in the workspace crates (mcp-tester / cargo-pmcp / toolkit / agent / team-servers) even though `cargo-semver-checks` classifies `enum_variant_added` as "minor". That source-level break violates the milestone's hard 2.x-minor promise. Per the orchestrator's directive (prefer option a/b), this plan does NOT add a public variant. Instead `server/discover` is carried by a crate-private internal dispatch representation and routed by matching the raw method string BEFORE conversion into the public enum (wired in Plan 05). The public `ClientRequest`/`Request`/`parse_request` signatures stay byte-identical, so the semver gate is a HARD assertion of "minor with public enums untouched," not an experiment.

Output: New `error_codes.rs` module (standard JSON-RPC + pmcp -320xx family + frozen v1 real; v2 values structurally omitted with a non-SATD doc); `error::ErrorCode` consts delegating to it with a per-name consistency test; a public `ServerDiscoverRequest` struct + crate-private internal dispatch representation for `server/discover`; public enums UNCHANGED.
</objective>
