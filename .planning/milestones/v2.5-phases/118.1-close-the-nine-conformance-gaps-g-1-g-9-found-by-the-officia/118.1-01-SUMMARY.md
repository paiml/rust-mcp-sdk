## Issues Encountered

- **`make doc-check` is NOT invoked by `make quality-gate` — a real gap in the pre-PR gate.** `doc-check` is a standalone `.PHONY` target at `Makefile:546-551` running `RUSTDOCFLAGS="-D warnings" cargo doc --no-deps` over a 15-feature list. The `quality-gate` target chains `lint-plans`, `fmt-check`, `lint`, `build`, `test-all`, `pmcp-package-gate`, `audit`, `unused-deps`, `check-todos`, `check-unwraps`, `validate-always`, `purity-check` and `comply` — and never `doc-check`. **Consequence for every later plan in this phase:** a green `make quality-gate` does not mean CI's `Quality Gate` job will pass. Any plan touching rustdoc comments (plan 03's `#[non_exhaustive]` + constructor docs and CHANGELOG work is the obvious candidate, and plan 09's `PeerHandle::elicit` docs another) should run `make doc-check` explicitly before pushing. This is the pre-PR mirror of the repo's recurring false-green problem: the gate is green because it did not measure the thing.
- **Local `main` had silently diverged from `upstream/main`** (31 ahead / 18 behind) via the Phase 105 squash — the same PR #319-class trap D-14 was written to avoid. Resolved by verifying tree-identity first (`git diff phase-118-conformance upstream/main` empty), then `git branch -f`, with the old tip recorded for reflog recovery. Anyone else with a local checkout of this repo should expect the same divergence and re-verify before force-moving anything.
- **BSD `grep -- 'pattern'` errors out on macOS** with `grep: invalid option --` when `--` is the first argument, and the surrounding pipeline can still exit 0 — producing a *false red* in a verification command (and, in a `grep -c` position, a potentially misleading count). Acceptance checks were re-run using `grep -e 'pattern'`, which is portable. Worth knowing for later plans that shell-verify literals: this is D-19's failure mode with the polarity flipped.
- **Task 3's acceptance criterion `grep -c '\[x\] \*\*CONF-0[123]\*\*'` = 3 passed**, but note it is satisfiable by three `[x]` CONF-0[123] lines anywhere in the file; byte-unchangedness of CONF-01..03 was confirmed additionally by reading the `git diff`, where those three lines appear only as unchanged context.
