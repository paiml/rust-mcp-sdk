The one-shot seam to generalize — `src/server/streamable_http_server.rs:1937-1957`,
`fn build_sse_response_from_single_message(response: TransportMessage) -> Response`: it creates an
`mpsc::unbounded_channel`, sends exactly one message, wraps it in `UnboundedReceiverStream`, maps each
message to `Event::default().id(Uuid::new_v4().to_string()).event("message").data(json_str)` where
`json_str` comes from `crate::shared::StdioTransport::serialize_message(&msg)`, and returns
`sse.into_response()`. The framing and the serializer must NOT be re-invented — only the "exactly one
message then close" part changes.

The dispatcher branch that selects it — `src/server/streamable_http_server.rs:1974-1994`,
`fn build_response(state, response, session_id, sessions_on)`: JSON mode short-circuits first, then a
v1 session routes to the stream, then the one-shot SSE fallback. On v2, `sessions_active_for(_, Some(Era::V2))`
is `false` (pinned by `sessions_active_truth_table`) and GET answers 405 (pinned by `v2_verb_rejection`),
so v2 reaches the JSON or one-shot branch today.

The closest long-lived streaming precedent in-repo: the v1 listen stream, with
`LISTEN_KEEP_ALIVE_INTERVAL` and `X_ACCEL_BUFFERING` at `src/server/streamable_http_server.rs:2939-2945`.

The suite's client behaviour, from the pinned bundle: its stateless request helper (functions `St`
and `Ct` in `dist/index.js`) checks the response `content-type` for `text/event-stream` and drains SSE

constrains the stream to `IncompleteResult` chunks and notifications only.
