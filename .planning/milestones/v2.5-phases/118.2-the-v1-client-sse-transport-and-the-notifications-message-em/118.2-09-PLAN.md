<objective>
Make the conformance fixture actually emit MCP log records (Pitfall 11), and ship the runnable example
CLAUDE.md's ALWAYS requirements demand for a new public API.

Purpose: `extra.log(..)` can ship, be perfectly correct, and `tools-call-with-logging` stays RED,
because `examples/s54_v2_dual_conformance.rs:870` handles
`"test_tool_with_logging" | "test_logging_tool"` by emitting three `tracing::info!` lines.
**`tracing` records go to the process's subscriber, never to the MCP wire.** The SDK fix and the fixture
fix are two different changes and only one of them is in `src/`.

MEASURED requirement from the pinned suite: the scenario calls `setLoggingLevel('debug')`, then
`callTool({ name: 'test_tool_with_logging', arguments: {} })`, then sleeps **200 ms**, then requires
**at least 1** notification (`length === 0` ⇒ "No log notifications received") and **at least 3**
(`length < 3` ⇒ "Expected at least 3 log messages, got N"). The current arm's 3 × 50 ms = 150 ms spacing
is already tight inside 200 ms once dispatch latency is added.

Output: the example, its registration, and a fixture that emits on the wire inside the budget.
</objective>

The arm being replaced, `examples/s54_v2_dual_conformance.rs:870-884`:

```
"test_tool_with_logging" | "test_logging_tool" => {
    // Three info-level records, spaced so a client can receive them
    // DURING the call rather than all at completion.
    for message in ["Tool execution started", "Tool processing data", "Tool execution completed"] {
        tracing::info!("{message}");                       // <- never reaches the wire
        tokio::time::sleep(std::time::Duration::from_millis(50)).await;
    }
    Ok(CallToolResult::new(vec![Content::text("Tool with logging completed")]))
},
```

The MCP-native arm immediately ABOVE it, `:840-868` (`test_tool_with_progress`) — same file, same match,
already correct, and therefore the exact model:

```
for (index, step) in [0.0_f64, 50.0, 100.0].into_iter().enumerate() {
    if index > 0 { tokio::time::sleep(PROGRESS_INTERVAL).await; }
    extra.report_progress(step, Some(100.0), None).await?;
}
```
Note the shape: emit FIRST, sleep only BETWEEN emissions, never a trailing sleep.

`capabilities.logging = Some(LoggingCapabilities::default())` is already declared at
`examples/s54_v2_dual_conformance.rs:1729`, so no capability change is needed.
