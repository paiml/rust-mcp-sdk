# Phase 118.2 — Validation Strategy

> Per-phase validation contract for feedback sampling during execution.
> Derived from `118.2-RESEARCH.md` § Validation Architecture — read that section for full detail.

---

## Test Infrastructure

| Property | Value |
|----------|-------|
| **Framework** | Rust built-in `#[test]` / `#[tokio::test]` + `proptest` + `cargo-fuzz`, driven by `cargo test` / `cargo nextest` |
| **Config file** | `Cargo.toml` (`[[test]]` targets) + `Makefile` targets; no separate test-runner config |
| **Quick run command** | `cargo nextest run -E 'binary(<name>)'` — **`binary(..)`, never `test(/…/)`** (silent-zero-selection pitfall; bit Phase 114 seven times) |
| **Full suite command** | `make test-all` (invoked by `make quality-gate`) |
| **External oracle** | `bash scripts/run-conformance-suite.sh` (builds examples, runs both era legs, applies the gate) |
| **Estimated runtime** | quick: seconds per binary; full gate: minutes; conformance suite: ~20 min both legs |

Every verify block must assert a **non-zero test count** in its expected output.
Every wire-crossing await in a fence is `tokio::time::timeout`-wrapped — the unfixed client
**hangs** rather than fails, which would otherwise defeat RED-first demonstration.

---

## Sampling Rate

- **After every task commit:** run the plan's named `binary(...)` fence, plus `make quality-gate` (mandatory pre-commit per CLAUDE.md)
- **After every plan wave:** `make test-all`, plus `binary(v2_bounded_reads_tripwire)`, `binary(v1_severability_tripwire)`, `binary(http_peer_roundtrip)` (expect 12 run / 12 passed), `binary(era_matrix)`, plus the `full-v2` severance build (`RUSTFLAGS="-D warnings" cargo build -p pmcp --no-default-features --features full-v2`)
- **Before `/gsd:verify-work`:** full `make quality-gate` green, conformance suite re-measured with D-16 hardening in place, `cargo semver-checks` verdict recorded
- **Max feedback latency:** ~120 s for in-tree fences; the ~20-min suite runs at wave boundaries at most, once at phase end mandatorily (plans 11/12 — the external oracle IS the deliverable there, matching 118.1 precedent)

## Anti-vacuity rules this phase enforces

Beyond the non-zero-count rule above, three fences carry an explicit anti-vacuity clause because their
obvious formulation passes without exercising anything:

1. **Backpressure** (plan 01 fence 6) — asserting only that all frames eventually arrive proves nothing;
   the kernel socket buffer absorbs a small push. The fence must assert the SERVER-side producer STALLED
   (two equal `frames_written` samples `QUIET` apart, strictly between 1 and the total) before draining.
2. **Terminal errors** (plans 01/03/04) — asserting that `receive()` returns *an* error is satisfied by
   generic channel closure. Each fence asserts the specific message text, and plan 04 asserts the three
   texts (overflow, parse failure, reconnect exhaustion) are mutually distinct.
3. **Fuzz bounds** (plan 04) — asserting "the overflow latch never clears" cannot fail for any input at
   any bound; 20 000 green runs of exactly that assertion coexisted with the unbounded-growth defect it
   was meant to catch. Assert `buffered_bytes() <= max_buffer_size` after every chunk instead.
