## Trust Boundaries

| Boundary | Description | Data Crossing |
|----------|-------------|---------------|
| the transport-wide `AuthProvider` | One credential cache shared by every clone and every concurrent call on a transport — `StreamableHttpTransport` is `#[derive(Clone)]` with every field an `Arc`, so two clones are one transport | OAuth access tokens, rotating refresh tokens |
| the transport-wide session-stream handle and terminal latch | One reader identity and one diagnosis slot, mutated across an await by any caller that restarts the stream | peer SSE frames, terminal error reasons |
| the peer → `SseParser` byte path | Arbitrary peer bytes entering a buffered incremental parser | untrusted frame bytes |
| the client response router | Peer-supplied JSON-RPC `id`s correlated against locally minted ones | responses addressed to other callers |
| the per-session log level and log sink | Server-side log routing keyed by session | operator-visible log records |

### Record corrections made during this audit

Three claims of record were false and were corrected in place, per the house
rule 118.2-21 set for this phase:

1. `WINDOWS.md` entry 26 was missing two disclosures its mirror in
   `pmcp-book/src/ch12-17-…` already carried. The disclosure tripwire could not
   see this: it checks that a `CONSUMER-OBSERVABLE` entry is **cited** in the
   chapter, not that the chapter's claims are **backed** by the ledger.
2. `118.2-25-SUMMARY.md`'s Threat Flags table claimed T-118.2-25-01 was closed
   by a "guarded region reaching the vend" (it reached only the retry's vend)
   and that fence 29 covered "the post-`close()` half" (it covers a sequential
   `close()`, not a concurrent one).
3. Entry 26's own amendment said the cold-start fan-out was "Unfenced", which
   this audit's fix made false within the same day.
