# Phase 118.2 Learnings: The v1 client SSE transport and the `notifications/message` emitter

> Scope note: this phase ran 20 plans across 14 waves, including two gap-closure rounds and a
> post-verification code-review round of 15 findings. Three commits (`d01b87e2`, `2d385d60`,
> `26447f94`) landed AFTER `118.2-VERIFICATION.md` was written, so that file is stale in both
> directions — it fails the phase for two blockers that no longer exist and describes a third at a
> severity it no longer has. `118.2-UAT.md` is the current measurement.

## Decisions

### Own the terminal reason at the STREAM, not at the transport
`TerminalReason` gained a `StreamKind` stamp, and the transport-wide reading was demoted to a
derived view. The first-round design had one latch per transport with first-writer-wins, which is
correct for "what killed this transport" and wrong for "what killed MY call".

**Rationale:** one GET reader plus one detached reader per streaming POST are all entitled to write
a diagnosis. A transport-scoped answer to a per-caller question is the root shape behind BLOCKER 1
and CR-03 alike.
**Source:** 118.2-19-SUMMARY.md, 118.2-15-SUMMARY.md

### Route responses by id rather than bounding the discard
The second gap-closure round bounded a mismatched-id discard with a timeout and a cap. The
post-review round deleted that machinery entirely (`receive_bounded`, `MismatchBudget`,
`MISMATCH_DISCARD_TIMEOUT` now have zero references) and replaced it with a per-id router:
`pump_once` looks up `active_requests` and delivers into the owning caller's oneshot.

**Rationale:** plan 15 had already recorded per-id routing as "the correct shape" and deferred it.
The two intervening rounds each shipped a bound on the wrong quantity, and each introduced a new
Critical. The deferred correct shape was cheaper than the third bound would have been.
**Source:** 118.2-15-SUMMARY.md, 118.2-UAT.md, commit `d01b87e2`

### Every knob on this transport is PRIVATE, deliberately
`MIN_SSE_RECONNECT_DELAY`, `RECONNECT_BUDGET_RESET_UPTIME`, `CLIENT_RECEIVE_QUEUE_CAPACITY`,
`PUMP_RECEIVE_SLICE`, `TerminalKind`, `StreamKind`, `PostBody`, `UnmatchedBudget` — all private.

**Rationale:** a private knob is invisible to `cargo semver-checks`, so hardening never becomes a
semver event. Confirmed at HEAD: `--baseline-rev cb5d1365` reports 223 checks, 223 pass, no update
required — byte-identical to plan 21's verdict despite three further commits.
**Source:** 118.2-04-SUMMARY.md, 118.2-14-SUMMARY.md, 118.2-UAT.md test 5

### Withhold the log SINK rather than invent a tri-state level (SEP-2575)
On v2, a request that did not authorize logging via `_meta["io.modelcontextprotocol/logLevel"]`
gets no sink attached at all, reusing D-08's existing "sinkless emit is silence" semantics.

**Rationale:** no emitter change, no new state to thread, and fail-closed for every handler
including ones written before the rule existed.
**Source:** commit `26447f94`, src/server/core.rs

### `.max(MIN).min(MAX)`, never `Duration::clamp`
The review suggested `clamp`. It panics when `min > max`, and both operands are constants a later
edit could invert.

**Rationale:** a panic inside a client reader task is a worse failure than the bound being wrong.
**Source:** 118.2-14-SUMMARY.md

### `std::time::Instant`, not `tokio::time::Instant`, for security bounds
**Rationale:** the tokio clock moves under `tokio::time::pause()`, which would make a security
bound depend on whether some caller paused time.
**Source:** 118.2-14-SUMMARY.md

### `tokio::sync::watch`, not `Notify`, for the terminal wake
**Rationale:** `notify_waiters` wakes only tasks ALREADY parked, so a signal raised between two
loop iterations is lost. The same reasoning this repo had already recorded for its harness's
`close_live` signal.
**Source:** 118.2-15-SUMMARY.md

### Delete `feed_complete_body` rather than leave it caller-less
**Rationale:** a bound-bypassing entry point with no caller is exactly the attractive nuisance its
own rustdoc named.
**Source:** 118.2-03-SUMMARY.md

### Fix the test mocks to CONFORM, not to de-conform
Three mocks passed only because `dispatch_request` did not compare ids — they were asserting on the
defect. They were changed to echo the request id, which is what a conformant server does; the
missing discrimination was supplied by a NEW fence instead.

**Rationale:** de-conforming the mocks would have redded several pre-existing suites for a
property none of them was written to test.
**Source:** 118.2-15-SUMMARY.md, commit `26447f94`

### Defer CR-03 on ARCHITECTURAL grounds, not on rarity
CR-03 (the transport-wide `open_post_readers` gate) is recorded OPEN and deferred, not waived.

**Rationale:** developer decision 2026-08-18 — the architecture is moving from SSE toward stateless
calls with MCP Tasks and task-store polling for progress. The defect lives exclusively in the
POST-response SSE reader path, the v1 surface being deprecated, so the affected population shrinks
rather than grows. Rarity alone would have been the weaker argument: the trigger needs only
concurrency of 2, which is ordinary for an agent doing parallel tool calls.
**Source:** 118.2-UAT.md test 6, WINDOWS.md entry 23

## Lessons

### A fix that introduces a new Critical on the same path is not progress — and it happened twice
Round 1 closed CR-01/CR-02 and introduced BLOCKER 1 + BLOCKER 2. Round 2 closed both and introduced
CR-01/CR-02/CR-03. Each round's verification was honest about it, which is why it was caught; but
three rounds of bounding produced what one round of restructuring finally fixed.

**Context:** the shared root was always the same — a per-call or per-await bound placed on
transport-wide state. Recognising the SHAPE after round 1 would have saved round 2 entirely.
**Source:** 118.2-VERIFICATION.md, 118.2-REVIEW-closure-2.md

### A verification can go stale between being written and being read
`118.2-VERIFICATION.md` was written 2026-08-17 21:40; three commits landed the next day. It now
fails the phase for CR-01/CR-02 (gone) and overstates CR-03 as an "unbounded silent hang for the
process lifetime" (now a delayed error bounded by another reader's lifetime).

**Context:** verification artifacts need a HEAD anchor, not just a date, or the next reader
inherits a severity that has since moved.
**Source:** 118.2-VERIFICATION.md vs 118.2-UAT.md

### Tests can encode the defect as the expected behavior, and then defend it
Three `tests/log_emitter.rs` v2 wire fences asserted the pre-SEP-2575 fallback was correct. The
`s54_v2_dual_conformance` example carried an `if extra.log_level.is_some()` guard that made the
fixture pass while `src/` was wrong. Both had to be rewritten before the real fix could go green.

**Context:** plan 09 knowingly wrote that guard and named it at the guard as "the FIXTURE honouring
SEP-2575 — the SDK gap it exposes is named, not hidden". The naming worked; the guard still delayed
the fix by a full phase.
**Source:** 118.2-09-SUMMARY.md, commit `26447f94`

### `cargo test --test <name>` does NOT rebuild examples
Five separate staleness-guard failures across this phase's runs traced to the same cause. The fix
is `cargo build --features full --examples` before any run whose fences read a built example.
**Source:** session measurement during the code-review round

### A plan prediction falsified by measurement should change the fence, not the measurement
Plan 07 had two predictions falsified; plan 10's `era_matrix` flip to `completed` was falsified and
the arm was STRENGTHENED instead (it now also pins the `detail`). Plan 13's Option-A trigger was
falsified by plan 08.

**Context:** this happened often enough (4+ times in 20 plans) that "the plan predicted X" should be
treated as a hypothesis with a fence, never as a spec.
**Source:** 118.2-07, -08, -10, -13-SUMMARY.md

### An unscored scenario is unrealised exposure, not retired exposure
Kept explicitly at sign-off for the elicitation flake, the whitespace-header exposure and the
SEP-2575 pair: "ten green runs in eleven is evidence about frequency, not about the defect."
**Source:** 118.2-12-SUMMARY.md

### The `pmat` cognitive threshold used by CI is 23, not the documented 25 — and that is UNCONFIRMED
`read_sse_body` measured exactly 25, passed `--max-cognitive 25`, and was flagged by
`pmat quality-gate --checks complexity`. The DIRECTION is measured; the NUMBER is not documented in
pmat 3.15.0's help output.

**Context:** plan 17 extracted a pure classifier rather than annotating, holding the zero-`#[allow]`
rule. Anyone budgeting to 25 is budgeting to the wrong number.
**Source:** 118.2-16-SUMMARY.md, 118.2-17-SUMMARY.md

### The shell's `grep` is a ugrep shim and silently produced an EMPTY before-snapshot
Plan 18's D-17 check would have passed vacuously on an empty file. `/usr/bin/grep` is used
throughout since, and the snapshot's non-emptiness is asserted rather than assumed.

**Context:** the same class recurred during the UAT round with `diff`, under the rtk proxy.
**Source:** 118.2-18-SUMMARY.md

### `Cargo.lock` is gitignored here, so a local `cargo update` fix does not travel
`RUSTSEC-2026-0258` (h2 0.4.13, transitive via `reqwest`) was fixed locally with
`cargo update -p h2` → 0.4.16. Every other checkout keeps failing `cargo audit` until it does the
same. Plan 11 hit the identical shape with a stale local lockfile reading as a `webbrowser` audit
red.

**Context:** an audit result is a property of the local lockfile, not of the commit.
**Source:** 118.2-11-SUMMARY.md, code-review round

## Patterns

### Bound the STATE, not the AWAIT
Every defect in this phase's three closure rounds reduces to placing a per-call or per-await bound
on transport-wide state. The durable fixes all did the opposite: give the state an owner
(`StreamKind`, per-id `Pending`), then bound per owner.

**When to use:** any time a timeout, cap or budget is proposed for a resource shared across callers.
Ask what the bound is scoped to versus what the state is scoped to; if they differ, the bound will
be wrong under concurrency.
**Source:** 118.2-15, -19, -20-SUMMARY.md; commit `d01b87e2`

### Sticky write-once latch over FIFO error delivery
Terminal reader errors moved off the response FIFO onto a private sticky latch, surfaced only
behind an empty queue, first-writer-wins.

**When to use:** when an error is a property of a CHANNEL rather than of a message. One-shot
delivery restores the hazard: the reason is consumed by whichever caller was next, and everyone
after gets an unexplained hang.
**Source:** 118.2-15-SUMMARY.md

### Acquire the guard SYNCHRONOUSLY before `tokio::spawn`
`PostReaderGuard::acquire` runs before the spawn whose future holds it. Acquiring inside the task
lets the consumer observe a count of zero — which IS the race, not a smaller version of it.

**When to use:** any refcount whose purpose is "something is in flight" across a spawn boundary.
**Source:** 118.2-19-SUMMARY.md

### Arm a budget on the FIRST offence only, never per-frame
Re-arming per frame gives a peer emitting a steady drip of wrong ids an unbounded wait through a
ceiling that exists and never fires.

**When to use:** any abuse counter driven by peer-controlled input.
**Source:** 118.2-20-SUMMARY.md, `UnmatchedBudget` in src/client/mod.rs

### Lazily-memoized parse over eager parse when a short-circuit must be preserved
`PostBody` memoizes the request-body JSON in a `OnceLock` rather than parsing once eagerly, so a
v1-only server still runs zero era code and a request refused by gate/session/version/auth is
refused without parsing an attacker-sized body.

**When to use:** deduplicating repeated parses on a path that also has security-relevant early exits.
**Source:** commit `2d385d60`, src/server/streamable_http_server.rs

### Bound every hang-shaped fence with a timeout
Every fence in this phase whose defect is a hang is wrapped in `tokio::time::timeout`, so a
regression FAILS rather than wedging CI.

**When to use:** always, for concurrency fences. A wedged CI job is a worse signal than a red one.
**Source:** commit `26447f94`

### Prove a documentation correction with a NEGATIVE grep plus a POSITIVE grep
"The file was edited" is exactly the acceptance criterion that lets a false claim recur. Plan 21
proved the false clause is GONE and the replacement is PRESENT, in all three documents of record.

**When to use:** any correction to a document of record.
**Source:** 118.2-21-SUMMARY.md

### Remove a false clause in place — never strike through, never annotate beneath
An amendment written under a false claim leaves the false claim readable as current. That is the
mechanism by which this phase's "bounded by the caller's own timeout" error propagated from a plan
comment into a ledger, a requirement row AND a broken-windows entry.

**When to use:** correcting any claim that other documents may have copied.
**Source:** 118.2-21-SUMMARY.md

### Substitute-command pattern
When a documented external command breaks, diagnose whether it is access / reachability / upstream,
record the diagnosis, and land a working replacement in the same commit — rather than dropping a
step the procedure mandates.

**When to use:** any runbook step that fails for reasons outside the repo.
**Source:** 118.2-12-SUMMARY.md

## Surprises

### The estimate calibration is averaging two incompatible token scales
`estimate-calibrate` returns `factor: 0.5, sample_count: 19, confidence: high, clamped: true`. But
the samples mix scales: plans' `estimate.tokens` and early actuals are SESSION-CONTEXT figures
(88k, 86k, 121k) while plans 14-18 explicitly recorded `chars/4 over the realized diff` (5.6k, 8.2k,
21k) and said in as many words "do not compare the two figures directly".

**Impact:** `factor: 0.5` is an artifact of unit mixing, `confidence: high` is unearned, and
`clamped: true` means the raw value was out of bounds. The next `/gsd-plan-phase` will read this.
Either normalise the scale or exclude the chars/4 samples.
**Source:** .planning/estimation-calibration.json, 118.2-14/-15/-16/-17/-18-SUMMARY.md

### `make quality-gate` passes while fuzzing ZERO iterations
Reproduced again during this round: `make test-fuzz` runs `cargo fuzz` on STABLE, every target
fails to build with "the option `Z` is only accepted on the nightly compiler", the `|| echo`
arm swallows it, and the target exits 0 printing "ALL ALWAYS requirements validated".

**Impact:** CLAUDE.md's ALWAYS-fuzz requirement cannot be discharged by the gate. Any plan citing
"make validate-always exit 0" as fuzz evidence has cited nothing. Already booked as WINDOWS entry 22.
Ironically the same run prints `lint-plan-verify-commands PASSED: no verification command masks the
exit status of the thing it verifies` — that lint reads plan files, not the Makefile.
**Source:** target gate log, 118.2-21-SUMMARY.md, WINDOWS.md entry 22

### The reconnect budget could never be earned on a healthy idle stream
`budget_reset_earned` required `delivered && uptime >= 30s`. But SSE keep-alive comments are dropped
by `SseParser::process_line` at `line.starts_with(':')`, so a healthy idle stream never sets
`delivered`. Behind a 60s-idle ALB it exhausted `MAX_SSE_RECONNECT_ATTEMPTS = 2` and latched
permanently.

**Impact:** the D-03 bound designed to SURVIVE ALB-class idle timeouts was defeated by them. The
`delivered` conjunct was removed post-phase.
**Source:** commit `26447f94`, src/shared/streamable_http.rs

### Two false greens hit while MEASURING this phase, both of the shape the phase itself documents
`make test-conformance > log 2>&1; echo $?` reports the ECHO's status — the first conformance run
appeared to exit 0 while make exited 1. And `diff <(grep) <(grep) && echo IDENTICAL` printed "Files
are identical" for two files that differ, under the rtk proxy.

**Impact:** the second nearly buried a real run-to-run difference. Use `/usr/bin/` absolute paths
for comparisons and read the real exit code, never a word in the output.
**Source:** 118.2-UAT.md, deferred-items.md third-round appendix

### Node 22 was installed the whole time; `nvm`'s DEFAULT was the problem
`make test-conformance` died at module load on `globSync`. v22.22.2 is installed and `nvm use 22`
switches cleanly — but `~/.nvm/alias/default` is pinned to 20.8.1 and the repo has no `.nvmrc`.

**Impact:** a fresh shell in this repo silently gets the wrong Node. CI is unaffected
(`actions/setup-node` with 22). A one-line `.nvmrc` closes it.
**Source:** 118.2-UAT.md

### The conformance runner's two fail-closed guards are a FEATURE, and both fired
Node-version and `PMCP_REQUEST_STATE_KEY` guards each refused to run with a diagnosis naming the
cause, the consequence and the fix. Without the second, the suite would have run against a server
deriving a fresh per-process key — measuring something different from CI while looking green.

**Impact:** a rare case of an environment guard paying for itself immediately.
**Source:** 118.2-18-SUMMARY.md, 118.2-UAT.md

### Batching a `#[non_exhaustive]` attribute WITH the new fields cost one major lint instead of two
Phase 118.1's accepted D-15 delta fired `enum_variant_marked_non_exhaustive` but NOT
`enum_struct_variant_field_added`.

**Impact:** still visible at HEAD. Against the crates.io baseline the milestone carries 1 major +
1 minor, so the "additive 2.x minor" framing needs reconciling before release even though 118.2's
own phase-scoped baseline is clean.
**Source:** 118.2-UAT.md test 5

### A 1-in-9 flake redded the closing gate, and was reported rather than tuned around
`tools-call-elicitation` failed one of nine fresh runs with "Dispatch oneshot channel closed". It is
a BLOCKING_GREEN_SCENARIOS entry and was already gate-fatal before hardening, so the hardening added
no new exposure — recorded, not exempted. The D-16 gate's first RED was likewise reported in full
rather than replaced by the green re-run.

**Impact:** the gate can go red on a race that is not this phase's. Reporting only the green re-run
would have been the exact accommodation D-21 forbids, one level up.
**Source:** 118.2-11-SUMMARY.md, 118.2-18-SUMMARY.md
