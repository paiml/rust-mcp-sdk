## Deviations from Plan

### 1. [Rule 1 — a verification that measured nothing] The shell's `grep` is a ugrep shim and produced an EMPTY D-17 snapshot

- **Found during:** Task 1, the precondition.
- **Issue:** `grep -oE '\b[A-Z]{3,6}-[0-9]{2}\b' .planning/REQUIREMENTS.md | sort -u > …` wrote a
  **0-line** file. `grep` in this environment is a shell function wrapping `ugrep`, and its output
  through that pipe was empty. An empty BEFORE snapshot is the worst possible outcome for this check:
  the post-edit `diff` would then compare empty against empty only if the AFTER extraction failed the
  same way, and either way the check would pass while measuring nothing — the exact false-green shape
  this phase has been cataloguing.
- **Fix:** `/usr/bin/grep` used explicitly for every extraction, and the snapshot's **non-emptiness
  asserted** (65 tokens, md5 recorded) before proceeding. The check was additionally re-run in the
  plan's literal `\b…\b` spelling with the BEFORE side read out of `git show HEAD:` rather than off
  the working tree, so it cannot be tautological. Both forms: identical.
- **No file changed.** Recorded because the same spelling appears in this plan's `<verify>` block and
  will misfire again wherever it is copied.

### 2. [Rule 1 — Bug in this plan's own `<verify>` block] The WINDOWS.md append-only assertion is unsatisfiable as literally written

- **Found during:** Task 2.
- **Issue:** the plan asserts
  `test "$(git diff HEAD -- .planning/WINDOWS.md | grep -c '^-[^-]')" -eq 0`. `.planning/WINDOWS.md`
  is a **machine-managed ledger**: its frontmatter carries `open_count`, `waived_count`,
  `fixed_count`, `total_count` and `last_updated`, and the sanctioned `gsd-tools windows append` /
  `windows fixed` verbs update them to stay consistent with the JSON block below the table. Any append
  therefore removes and rewrites those counter lines, and the observed count is **4**, not 0.
- **Disposition — the intent satisfied, not the letter.** The check exists so an earlier disclosure
  cannot be silently rewritten by a later entry. That property was asserted directly:
  `git diff HEAD -- .planning/WINDOWS.md | grep '^-[^-]' | grep -vE '^-(open_count|waived_count|fixed_count|total_count|last_updated):'`
  is **empty**, and `grep -cE '^[+-]\| (4|5|6|8|9) \|'` is **0**, proving entries 4, 5, 6, 8 and 9 are
  byte-unchanged.
- **The alternative was worse.** Hand-editing the table to keep the counters frozen would have left
  `open_count: 9` in a ledger with 12 open entries — a wrong number in the very document
  `/gsd-ship` gates on, and a divergence between the markdown table and the JSON block. Keeping the
  ledger self-consistent beats satisfying a check whose spelling did not anticipate a
  machine-managed file.

### 3. [Rule 1 — an environment failure that looks exactly like a regression] The first `make quality-gate` run failed 5/5 on `streamable_http_oauth_integration`

  example-build step, matching this phase's recorded ENOSPC history (plan 14 deviation 2) and the
