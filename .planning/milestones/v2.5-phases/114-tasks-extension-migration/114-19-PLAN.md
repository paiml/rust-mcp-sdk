<objective>
Land the CLIENT half of the v2 tasks surface: era-aware decoding of every v2 task response shape,
`tasks_update()`, and a poll helper that reads the terminal result inline from `tasks/get` instead of
the v2-retired `tasks/result`.

Purpose: CONTEXT.md's owner steer is locked and load-bearing — *"one Rust SDK serves BOTH servers and
clients (AI agents) … the server and client halves land together in this phase, not
server-first-client-later"* (D-04, D-05, D-06). Cross-AI review measured that the plan set as first
written moved the server to v2 shapes while leaving the client on v1 decoders, which would have made
that locked steer untrue at the end of the phase and left 114-17's paired example unable to run.

**The gap, measured against the current tree (all four confirmed at `src/client/mod.rs`):**

| Site | Today | v2 needs |
|---|---|---|
| `call_tool_with_task` (~:1069) and `call_tool_with_task_and_meta` (~:1140) | `serde_json::from_value::<CreateTaskResult>(result.clone())` then `task_result.task` — a NESTED `{task:{…}}` decode | a FLAT `{taskId,status,createdAt,lastUpdatedAt,ttlMs}` decode, selected by `resultType:"task"` |
| `tasks_get` (~:1223-1235) | `let task_result: GetTaskResult = …; Ok(task_result.task)` — nested | flat `DetailedTask`, with `result`/`error`/`inputRequests` inlined per status |
| `tasks_cancel` (~:1424-1438) | `let cancel_result: CancelTaskResult = …; Ok(cancel_result.task)` — nested, returns a `Task` | an EMPTY acknowledgement; there is no `Task` in a v2 cancel response to return |
| `wait_for_task` (~:1385) | ends with `self.tasks_result(task_id).await` | `tasks/result` answers `-32601` on v2 (D-15, 114-08) — the terminal result must come from the inline `tasks/get` payload |

Output: era-aware decoding on the four sites above, `tasks_update()`, an input-supplying poll sibling,
and a raw-frame test suite that drives the exact bytes 114-11/12/14 emit.

114-17 is examples-only and consumes what lands here, so the two plans have zero file overlap and
114-17's example can be an executable assertion over production client methods rather than a
re-implemented loop.

**Not in scope:** `pmcp-agent` wiring (CLNT-03 / Phase 117, per D-06) and any change to
`wait_for_task`'s existing v1 behaviour or signature.

3. **`tasks_cancel`.** On v2 the acknowledgement is EMPTY: there is no task object to unwrap, and today's

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| server response bytes → client typed model | The client decodes untrusted bytes from a remote server; a permissive or shape-sniffing decoder is where a malicious server steers a client into the wrong branch |
| retired v2 method → client call | A client that still calls `tasks/result` on v2 leaks its own state machine into a `-32601` loop |
| task input payload → agent trust model | The spec is explicit that a task is NOT a higher-trust channel than elicitation/sampling |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-114-99 | Spoofing | a server steering a client's decode branch by crafting a task-shaped ordinary result | mitigate | On v2 the branch is chosen by the `resultType` discriminator read from the shared constant, never by shape-sniffing; test 2 is the regression guard and a recorded control proves it load-bearing |
| T-114-100 | Tampering | client-side decoder drifting from the server's emitted shapes | mitigate | The suite feeds the SAME byte literals `tests/v2_tasks_shapes.rs` and `tests/v1_tasks_golden.rs` assert, with a comment naming the counterpart so a one-sided edit is visible |
| T-114-101 | Denial of Service | unbounded client-side input round loop | mitigate | The input-supplying poller's round count is bounded, related to `DEFAULT_MRTR_ROUND_LIMIT` and pinned by a `const _: () = assert!` |
| T-114-102 | Denial of Service | hot-spin on a zero or absent `pollIntervalMs` | mitigate | The new sibling reuses `wait_for_task`'s existing `MIN_POLL_MS` floor and remaining-budget clamp verbatim rather than re-deriving a delay |
| T-114-103 | Information Disclosure | an un-negotiated tasks call leaking a request to a server that never advertised the extension | mitigate | `assert_capability` fires first on every tasks method; tests 8 and 11 assert a transport send count of exactly 0 |
| T-114-104 | Spoofing | treating a task-delivered payload as higher-trust than an elicitation | mitigate | The input-supplying poller's rustdoc states the spec rule ("a task is not a higher-trust channel") and the callback contract passes values through without executing anything server-supplied |
| T-114-105 | Repudiation | accidental semver-major on the public `ToolCallResponse` | mitigate | Variants and payload types unchanged; `cargo semver-checks check-release` no-update-required and `cargo public-api diff` zero-REMOVED are acceptance criteria |
| T-114-SC | Tampering | npm/pip/cargo installs | accept | Zero packages installed; `Cargo.toml`/`Cargo.lock` byte-unchanged |
