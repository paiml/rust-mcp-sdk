<objective>
Add the source tripwires that keep this phase's invariants from rotting: every `tasks/*` route carries an
era guard, no v2 tasks path emits `-32603` for a not-found, and the status-string identity cannot drift.

Purpose: this phase's correctness rests on gates and on a name identity, and both are the kind of thing a
future refactor removes without failing a behavioural test. The repo already has the right instrument —
`tests/v2_prohibited_error_codes.rs`'s two-kind entry model with justified allowlists, which fails on
three distinct rot conditions: a new unlisted site, a deleted guard, and a stale allowlist entry.
113-21/113-29 both record that this instrument caught real sites the behavioural tests missed.

Output: one integration test crate. No production changes.

**Why this is a separate plan from 114-15:** both are wave-10 coverage plans over disjoint files, so they
run in parallel; and a source scanner and a live-socket security matrix fail for entirely different
reasons, so keeping them apart keeps each SUMMARY's evidence legible.
</objective>

<amendment date="2026-07-29" reason="three wire values this phase reused are now graded by a PUBLISHED core schema">
**One addition. It does not change the shape of this plan — it adds a fourth tripwire subject.**

The MCP `2026-07-28` core specification published on 2026-07-29:
`modelcontextprotocol/modelcontextprotocol` now carries `schema/2026-07-28/` with
`LATEST_PROTOCOL_VERSION = "2026-07-28"`. (`ext-tasks` did **not** publish — it is still `draft/`,
so the D-18 hold remains engaged and every *tasks* wire value stays provisional. Full record:
`114-SPEC-RECHECK.md` § `### Verdict re-verification` → `#### 2026-07-29`.)

The consequence for this plan: **three values this phase reused are no longer provisional — they are
now graded by a published, authoritative schema**, and so they are exactly the kind of invariant a
tripwire should pin rather than leave to inference:

| Value | Published core declaration | Currently pinned by |
|---|---|---|
| `-32021` | `export const MISSING_REQUIRED_CLIENT_CAPABILITY = -32021;` | nothing asserts the NAME↔code binding |
| `-32602` | `export const INVALID_PARAMS = -32602;` | row 29 behaviour tests only |
| `-32002` | **absent** from the published core codes | `114-08`'s era gate, behaviourally |

**Add to Task 1's scanner (or a sibling task if that reads better) a tripwire asserting:**

1. `error_codes::MISSING_REQUIRED_CLIENT_CAPABILITY == -32021` **and** that this is the constant the
   non-declaring-client refusal emits — so a future renumbering upstream, or a re-point to a
   different constant, fails here rather than on a customer's wire.
2. `error_codes::INVALID_PARAMS == -32602`.
3. **`-32002` has no v2-reachable emission site.** `114-08` established this behaviourally and
   `114-10` counted the emission sites at 4, all v1. The published core omitting `-32002` entirely
   makes this a spec-grounded invariant, not just a pmcp policy — pin the count and the era gate.

**Explicitly do NOT** add tripwires over any *tasks* wire value (status strings, `ttlMs`,
`pollIntervalMs`, `inputResponses`, the four result shapes). Those are ext-tasks-governed, still
`draft`, still held under D-18, and pinning a provisional value as though it were authoritative is
the precise over-read `## Recorded Exception` § *What this hold does NOT permit* forbids.

**Also do NOT** pin `resultType`'s value set. The published core declares
`ResultType = "complete" | "input_required" | string` while pmcp mints `"task"` via the open
`| string` tail — that discrepancy is an **open question booked to `114-18`**, not a settled
invariant, and a tripwire would freeze a decision nobody has made yet.
</amendment>

**(a) The `-32603`-for-not-found ban.** Scan the tasks dispatch source for sites that map a store
`NotFound` onto `INTERNAL_ERROR`. Every such site must be inside a v1-only branch and must name the era

nonexistent `taskId` (MUST for `tasks/get`), and because owner mismatch deliberately surfaces as
`NotFound`, a `-32603` here would make 114-15's cross-caller probe read the wrong code to a conformant
client. Phase 118's conformance run grades exactly this.
