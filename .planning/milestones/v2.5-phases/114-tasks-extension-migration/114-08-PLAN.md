<objective>
Era-gate `tasks/list` and `tasks/result` off on v2 while keeping both fully functional for v1
(TASK-03), and correct the two rustdocs this change falsifies.

Purpose: upstream REMOVED both methods, and the spec frames `tasks/list`'s removal as a security
improvement in its own words — *"Because there is no `tasks/list`, a server cannot inadvertently leak
the existence of one caller's tasks to another."* TASK-03 and TASK-05 are the same improvement viewed
from two angles. `tasks/get` inlines the result on v2 (114-11), which is why blocking `tasks/result`
has nothing left to do — and removing it also removes the last v2-reachable `-32002` emission path.

Output: two named era predicates with truth-table rustdocs, a new message constant for the retired
condition, corrected docs on `is_v1_task_era`, and a per-method era matrix with one negative control
per gate.

**Frozen, not re-litigated:** the `-32002` `V1_TASK_PENDING` squat stays exactly as it is. The
`-32002`→`-32602` rename in the draft targets *resource*-not-found, not task-pending. ROADMAP states
verbatim that Phase 114 must not re-litigate this. This plan only ensures the existing `-32002` site
stays unreachable on v2 — which 113-29 already era-gated — and must leave
`pending_tasks_result_preserves_minus_32002` green and unedited.
</objective>
