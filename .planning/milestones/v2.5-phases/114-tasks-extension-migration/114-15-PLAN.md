  <action>
Add `tests/v2_tasks_security.rs` driving ONE live socket with `AuthPosture::Required`
(`BearerSubjects`), two distinct bearers `A` and `B`, both declaring the tasks extension.

Setup once per test: A creates a task via a real v2 `tools/call` (114-12's path) and captures the
`taskId`. Then B attempts each method with A's id.

  1. `v2_cross_caller_tasks_get_is_not_found`
  2. `v2_cross_caller_tasks_update_is_not_found`
  3. `v2_cross_caller_tasks_cancel_is_not_found`

For each, assert ALL of:
  - `error.code == -32602` (the v2 task-not-found code from 114-11);
  - the error message is **byte-identical** to the message the same method returns for a task id that
    genuinely does not exist — compute both in the test and compare, so "indistinguishable" is measured
    rather than asserted by inspection. This is PROJECT.md's standing no-info-leak decision: `NotFound`,
    never `OwnerMismatch`;
  - the message contains neither the string `owner` nor `mismatch` nor `forbidden` nor A's subject;
  - the response carries no `result`, no `status`, no `createdAt` — no fragment of A's task;
  - A's task is UNCHANGED afterwards: A polls `tasks/get` and sees the same status it had before B's
    attempt. For `tasks/cancel` this is the load-bearing half — a refusal that still cancelled would
    pass a code-only assertion.

  4. `v2_owner_isolation_holds_for_a_second_task_of_the_same_shape` — A and B each create a task; each
     can read its OWN and not the other's. Firing only the refusal direction cannot distinguish
     "isolated" from "broken for everyone", which is negative control A's whole point.
  5. `v2_a_guessed_task_id_is_not_found` — a well-formed random v4 UUID that was never minted gets the
     same answer, so the refusal is not an existence oracle in the other direction either.
  6. `task_ids_are_unguessable` — a lock on the PROPERTY the spec states, not on a format. The spec
     requires ids "generated with sufficient entropy that a third party cannot enumerate or guess
     them"; it does NOT mandate UUIDv4. Assert what the requirement actually says: minted ids are
     ≥ 122 bits of entropy in their encoded form, are not sequential (mint 32 and assert no two are
     adjacent under any total order the encoding admits), and are not derived from the owner id or a
     timestamp prefix (assert two ids minted for the SAME owner in the same second share no common
     prefix beyond a fixed literal). Today's ids ARE v4 UUIDs, so a v4 parse may be recorded as a
     supporting observation — but it must not be the assertion, because locking v4 would block a
     future move to a stronger cryptographically-random format for no security gain. `tasks/list` is
     gone on v2, so unguessability plus owner-keying is the whole enumeration defence.

Fire the refusal case before the success case in each pair. Follow the teardown order (drop sockets →
`abort()` → `await`) to avoid nextest LEAK noise (D-113-T).
