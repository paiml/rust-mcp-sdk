<objective>
Settle this repository's mandatory contract-first obligation for Phase 114 **before** any
implementation plan runs.

Purpose: `CLAUDE.md` § *Contract-First Development* and `AGENTS.md` both state, without qualification,
that all new features and bug fixes must (1) write or update the contract YAML in
`../provable-contracts/contracts/<crate>/`, (2) run `pmat comply check`, (3) implement, (4) re-run
`pmat comply check`. Cross-AI review raised this as a blocker with a specific and correct framing: a
plan cannot grant itself an exemption from a repository-level mandatory rule, and discovering the
question at the END of an 18-plan phase (in `114-18`) means the answer arrives after all the code it
was supposed to constrain.

**Measured state at planning time (2026-07-28):** the sibling path `../provable-contracts/` is
**absent** from this working tree — `ls -d ../provable-contracts` finds nothing at any of the three
plausible parent directories. `make comply` therefore runs `pmat comply check --path .` in
*project-level advisory* mode (its own Makefile comment says project-level advisories are
informational per D-07) plus the fail-closed `comply-bindings-check`, and neither reads a per-crate
contract YAML. So the rule's step 1 currently has no destination.

This is exactly the class of question that needs an owner, not an inference. Two defensible answers
exist and this plan does not pick between them — it measures the ground truth, states both options
with their real costs, and stops for the owner.

Output: `114-CONTRACT-DECISION.md`, carrying the measurement, the options, and the recorded decision.

**Scope:** this plan writes NO source code and touches no source file. It is deliberately wave 1 with
no dependencies and no file overlap with any other plan, so it can be answered in parallel with the
other wave-1 work rather than serializing the phase.
</objective>
