<objective>
Add the two type-level prerequisites for extension negotiation: an `extensions` field on
`ClientCapabilities` (F6 — the client-declares half is literally unimplementable without it) and
a typed, structure-ready `TasksExtensionCapability` plus the reverse-DNS key constant (D-03).

Purpose: F6 measured that `ServerCapabilities` has `extensions` (Phase 112) but
`ClientCapabilities` does NOT — so a client's declaration is silently dropped by serde today.
Every downstream decision that reads "did the client declare the tasks extension?" (D-04's client
gate, DQ1's v2 create trigger, DQ3's `-32021` refusal) is blocked on this field existing.

Output: one additive field, one const, one struct, and five serde lock tests.

**Why this is semver-safe:** PATTERNS measured that both `ClientCapabilities` and
`ServerCapabilities` are `#[derive(Default)] #[non_exhaustive]` with every field
`Option<_> + skip_serializing_if`. A field on a `#[non_exhaustive]` struct is semver-additive —
in deliberate contrast to Fact 1's `ClientRequest`, where a variant on a public exhaustive enum
would be MAJOR.
</objective>
