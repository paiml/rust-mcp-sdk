<objective>
Vendor the authoritative `modelcontextprotocol/ext-tasks` draft schema into this repo at a
pinned commit, with the Phase-112 `error_codes.rs` PROVENANCE discipline, and write the
phase's hold record.

Purpose: 114-RESEARCH's primary recommendation. Every wire value the next 17 plans write is
provisional (the schema lives in a `draft/` directory of a repo labelled *Experimental*).
Vendoring converts a decaying network finding into a reviewable, offline, diff-able artifact —
and it removes the network from every downstream plan's critical path.

Output: `schema/vendored/ext-tasks/{schema.ts,schema.json,PROVENANCE.md}`, a provenance
tripwire test, and `114-SPEC-RECHECK.md` recording the D-18 hold plus its resolved
open question.

**Resolved scope decision recorded here (DQ6, from 114-RESEARCH Q6):** D-18 inherits Phase
113's hold *condition* ("a versioned schema directory exists"), but 113's policy was written
before tasks moved to a separate repo. This phase amends it: the hold clears only when a
versioned (non-`draft`) schema directory exists in **BOTH** `modelcontextprotocol/modelcontextprotocol`
(for `resultType` and the error-code values) **AND** `modelcontextprotocol/ext-tasks` (for the
tasks wire shapes). Six `[~]` requirements must not flip on a core-only publication event.
</objective>
