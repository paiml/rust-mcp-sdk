<objective>
Make a tasks-backed v2 server advertise the tasks extension through the extensions map, and
project capabilities per era so v1 bytes are frozen (D-01, D-02, D-03).

Purpose: TASK-01's server half. One knob, not two — a configured `TaskStore` **or** `TaskRouter`
auto-populates the entry through the SAME endpoint-backed rule that already drives
`capabilities.tasks`, so no existing tasks server needs a code change and no v2 server with a
working store can silently serve nothing. The projection is what keeps the promise that v1 wire
bytes do not move: the struct carries everything, the serialization boundary decides what each era
sees.

Output: a v2 arm in `apply_tasks_capability_rule`, an era projection in
`discover_result_from_capabilities`, corrected rustdoc on `V2_TASKS_NOT_NEGOTIATED`, and a
live-socket negotiation matrix.
</objective>
