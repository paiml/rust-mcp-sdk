<objective>
Give the resources half of HTTP-08's opt-in surface the same live-socket coverage the
tools/prompts half already has.

Purpose: HTTP-08 mandates that four capability opt-ins gate the `subscriptions/listen` stream —
`toolsListChanged`, `promptsListChanged`, `resourcesListChanged`, `resourceSubscriptions`. Two
of those four are exercised end-to-end over a real loopback socket by `tests/v2_subscriptions.rs`
today. The other two are exercised nowhere outside `#[cfg(test)]` unit tests in
`src/types/subscriptions.rs`. That asymmetry is invisible in a green suite: every existing test
passes, and the ones that would fail do not exist.

The resources half is also the half with the most logic behind it. `resourceSubscriptions` is
the only filter field that is not a boolean — it is a `string[]` of URIs, it carries a
per-stream truncation bound, and its delivery decision is a linear URI scan under the registry
read lock rather than a flag read. `SubscriptionFilter::covers`'s `ResourceUpdated` arm,
`intersect_with_capabilities`'s truncation, and the `ServerNotification::ResourceUpdated`
fan-out have never been proven to compose over HTTP.

Output: four to six new live-socket tests in the existing suite, each with a recorded negative
control, and no production change.
</objective>

THE PRODUCTION CONTRACT UNDER TEST (from `src/types/subscriptions.rs`, verified)

  `SubscriptionFilter` fields, camelCase on the wire, all four optional:
    `toolsListChanged: Option<bool>`, `promptsListChanged: Option<bool>`,
    `resourcesListChanged: Option<bool>`, `resourceSubscriptions: Option<Vec<String>>`.
    `resourceSubscriptions` is `string[]` — an array of resource URIs. NOT a bool, NOT a map.

  `intersect_with_capabilities(&self, capabilities)`:
    each boolean field survives only when the matching capability is advertised; an unsupported
    request is OMITTED (`None`), never `Some(false)` — see `agreed_flag`.
    `resource_subscriptions` survives only when `resources.subscribe` is advertised AND the
    requested list is non-empty; otherwise it becomes `None`. When it survives it is TRUNCATED
    with `.take(MAX_AGREED_RESOURCE_SUBSCRIPTIONS)`.
    `pub const MAX_AGREED_RESOURCE_SUBSCRIPTIONS: usize = 1024;` — public, so a test can name it
    rather than hardcoding 1024.

  `covers(&self, kind)` for `SubscriptionNotificationKind::ResourceUpdated(uri)` is
    `self.resource_subscriptions.as_ref().is_some_and(|uris| uris.iter().any(|c| c == uri))`
    — EXACT string equality on the URI. No normalisation, no prefix matching. A test asserting
    prefix behaviour would be asserting a behaviour that does not exist.

  `subscription_kind_of` maps `ServerNotification::ResourcesChanged` →
    `ResourcesListChanged` (method `notifications/resources/list_changed`) and
    `ServerNotification::ResourceUpdated(params)` → `ResourceUpdated(params.uri)`
    (method `notifications/resources/updated`).

  `ResourceUpdatedParams` lives at `crate::types::notifications::ResourceUpdatedParams` and is
  re-exported through `crate::types::protocol::ResourceUpdatedParams` (both spellings appear in
  the tree; use whichever the test file's existing imports make cleanest). Confirm its field set
  before constructing one — the URI field is `uri`.

  `SUBSCRIPTION_ID_META_KEY` = `"io.modelcontextprotocol/subscriptionId"`, already imported by
  the test file.
