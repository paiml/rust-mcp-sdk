<objective>
Make the `subscriptions/listen` route agree with the MRTR ingress about what an
unauthenticated caller is, and settle Finding 5 by measuring pmcp's actual `subscriptionId`
emission instead of assuming HTTP-07's wording.

Purpose: two ingress paths on the SAME server currently disagree. `resolve_mrtr_principal`
(`src/server/core.rs:1489`) refuses when an auth provider is configured and no `AuthContext`
arrived; `assemble_subscriptions_listen` (`src/server/streamable_http_server.rs:2935`) invents
`anon#N` — a fresh, unique principal per request. Where a provider admits unauthenticated
requests, that makes `MAX_LISTEN_STREAMS_PER_PRINCIPAL` (4) structurally unreachable for the
unauthenticated caller, who can then hold all 64 global slots and starve authenticated
subscribers. The second half of this plan discharges the addendum's open Finding 5: the draft
schema makes `io.modelcontextprotocol/subscriptionId` REQUIRED on the teardown result but
OPTIONAL on a notification's `_meta`, so HTTP-07's "every delivered notification carries
`subscriptionId` tagging" needs checking against what pmcp actually emits before anyone treats
it as met.

Output: a fail-closed principal on the listen route, the deliberate no-auth divergence written
down with its reason, tests including the budget-exhaustion regression and a negative control,
three-class emission pins, and Finding 5 answered in the addendum.
</objective>

WHY THE NO-AUTH CASE IS DELIBERATELY NOT UNIFIED (this is a decision, implement it as written):
  The MRTR path needs a STABLE principal string on a no-auth server because that principal is
  AEAD additional-authenticated-data: a per-request `anon#N` would make every round-2
  `requestState` fail to verify. The listen route has no such binding — its principal is only
  a concurrency-accounting key. Unifying them onto the single shared `ANONYMOUS_PRINCIPAL`
  would silently drop a no-auth server's concurrent listen capacity from 64 to 4 (the
  per-principal cap), which is the common local/dev configuration and the one the shipped
  `s47_v2_stateless_mrtr` / `s48_v2_mrtr_client` examples use. So: fix ONLY the fail-closed
  case; keep `anon#N` when no provider is configured; and write the reason down at both sites
  so the next reviewer reads a decision rather than inferring an oversight.
