<toolchain_reality>
Recorded by 113-03 and re-confirmed during Phase 113 close-out — the executor
must not rediscover this the hard way:

- `cargo fuzz run` passes `-Zsanitizer=address`, which **stable rustc rejects**.
  A campaign therefore requires `cargo +nightly fuzz run`.
- `cargo fuzz build --sanitizer=none <target>` DOES work on stable, and is the
  cheap "does it still compile for everyone" check. It is not a campaign.
- 113-12 additionally found that `$(rustup which cargo)` does **not** pin the
  compiler: it leaves `RUSTUP_TOOLCHAIN` unset, so the `rustc` proxy honours
  `rust-toolchain.toml` files vendored inside published crate sources. If a
  command behaves as though it is on the wrong toolchain, `export
  RUSTUP_TOOLCHAIN=nightly` explicitly rather than trusting the proxy.
- `cargo +nightly` requires the nightly toolchain to be installed. If it is
  absent, `rustup toolchain install nightly` is in scope for this plan — it
  installs a toolchain, it does not change project configuration.

113-03's recorded evidence line, as the format to match:

  <action>
1. If `decode_listen_chunk_for_fuzz` builds its parser internally with
   `SseParser::new()`, give it a bounded sibling or a `max_buffer_size`
   parameter so the fuzz target can specify a small bound.
   **Visibility, precisely:** it is already an unconditional `pub fn` at
   `src/client/subscriptions.rs:577` inside the `pub mod subscriptions`
   (`src/client/mod.rs:48`), carrying `#[doc(hidden)]` — which is a
   documentation convention, NOT a visibility restriction. It is therefore
   reachable API. It post-dates the `2.17.0` baseline, so a signature change
   still reads as additive to `cargo semver-checks` today, but do not treat it
   as private. PREFER adding a bounded sibling over changing the existing
   signature, and confirm the semver verdict rather than assuming it (see the
   acceptance criteria).

   libFuzzer's short inputs reach the overflow branch — 64 bytes. State in a
   comment WHY the bound is small: the production bound is 256 KiB, and a fuzzer
   that must synthesise 256 KiB of newline-free input to reach the branch will
   effectively never reach it.
3. Add the latching assertion: track whether `overflowed()` has been observed
   true, and assert it never returns to false on a later feed within the same
   input.
4. Keep the existing no-panic invariant and the existing arbitrary-bytes entry
   point unchanged.
  </action>
