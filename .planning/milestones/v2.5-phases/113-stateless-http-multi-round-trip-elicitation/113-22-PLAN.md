<objective>
Make the O(n) clause of HTTP-09 mechanically true: give the two scans that run over
peer-chosen bytes a budget that FAILS when the quadratic shape returns.

Purpose: `take_utf8_prefix` is the incremental UTF-8 decoder that runs BEFORE every byte-count
bound this phase added, on both incremental feeders (`connect_sse`'s reader task and the
`subscriptions/listen` client). Review CR-02 measured its pre-`5f045086` shape at 1.17 CPU
seconds for 400 KiB of `0xFF`, self-sustaining because a peer that newline-terminates each
garbage frame keeps the buffer drained so the overflow latch never fires. `5f045086` rewrote
it as a single-pass cursor scan and added
`take_utf8_prefix_is_linear_over_a_large_invalid_run` — but that test asserts only the OUTPUT
(one U+FFFD per invalid byte) and its rustdoc's falsifiability claim is arithmetically wrong:
256 KiB under the quadratic shape costs about half a second, so the test passes on the defect
it names. HTTP-09 requires an enumerable check, and a guard that cannot fail is not one.

Output: an absolute time budget over 1 MiB of invalid bytes (linear ≈ 1 ms, quadratic ≈ 7.7 s,
ceiling 1 s), a growth-ratio assertion over a 4x input step, the same treatment for the public
`SseParser::feed`, a `proptest` pinning the ≤3-byte retained tail over arbitrary bytes, and a
corrected rustdoc on the existing guard so nobody re-trusts the claim this plan disproves.
</objective>

MEASURED ARITHMETIC that fixes the budget constants (from 113-REVIEW.md CR-02: 400 KiB of
`0xFF` = 1.17 CPU-seconds under the quadratic shape, on the reviewer's machine):
  - quadratic cost scales with n²: 256 KiB → ~0.48 s (which is why the existing test passes
    on the defect), 1 MiB → ~7.7 s, 2 MiB → ~30.7 s.
  - the single-pass shape is one `from_utf8` validation plus one `String` build: 1 MiB is
    sub-5 ms on any machine that can run this suite.
  - therefore an absolute ceiling of 1 SECOND at 1 MiB sits ~200x above linear-on-a-slow-CI-box
    and ~7x below quadratic. That is the load-bearing assertion. A machine slow enough to take
    1 s for a linear 1 MiB scan cannot run this test suite at all.
