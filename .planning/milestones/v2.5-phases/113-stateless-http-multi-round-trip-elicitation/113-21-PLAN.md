<objective>
Build the HTTP-09 tripwire: a test that mechanically enumerates every peer-controlled
whole-body read and every peer-byte accumulation in the v2 transport scope, and fails by name
when a new one appears or an existing bound is removed.

Purpose: HTTP-09 exists because "memory-bounded" was a *narrative* criterion. It reopened
three times, and each round closed the sites that round's findings happened to name. The
2026-07-26 review found a 4th uncapped `collect()` in `rejection_error`, an uncapped
`HttpTransport::send_request`, and an O(n²) decoder sitting upstream of every bound the phase
had added — all in code the phase had just declared bounded. Commit `5f045086` fixed those
three. That does **not** satisfy HTTP-09: the requirement is stated as an invariant with a
mechanical check precisely so round four cannot miss a site by omission. This plan is that
check.

Output: `tests/v2_bounded_reads_tripwire.rs` — a source-scanning integration test with
(1) runtime file discovery so a new `src/shared/*.rs` is in scope automatically, (2) a
structural rule that every `.collect().await` in scope be `Limited`-wrapped in the same
statement, (3) a count+justification allowlist for accumulations that fails on both addition
and deletion, and (4) unit tests for the scanner's own stripping/classification logic so the
tripwire cannot pass vacuously.
</objective>
