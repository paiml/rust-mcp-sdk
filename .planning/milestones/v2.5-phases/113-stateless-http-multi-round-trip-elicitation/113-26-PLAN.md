<objective>
Delete the AAD collision: stop digesting over-deep params to a constant and refuse them
instead, so a `requestState` minted for one request can never verify against another.

Purpose: `salient_param_digest` is the sole enforcement of the spec's replay-prevention clause
5c — "an identifier for the originating request, e.g. the method name and a digest of its
salient parameters, rejecting state presented on a request that does not match". Today
`write_canonical` substitutes the literal `"__mrtr_depth_capped__"` for everything below depth
64, so any two `tools/call` requests whose `arguments` agree to depth 64 hash identically. The
AEAD then authenticates a continuation against an AAD that does not distinguish them, and a
token minted for A is accepted on B. `serde_json`'s own default recursion limit is 128, so the
64-to-128 band where this bites is reachable over the wire — this is not a theoretical depth.

Output: a fallible canonicaliser with the marker literal removed from the source, a fallible
`RequestBinding::from_request`, typed refusals at both the verify and the mint path, an
end-to-end cross-request test, and a negative control that restores the marker and watches the
collision test fail.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| remote client → `salient_param_digest` | the client chooses the `arguments` shape and depth that the AAD is computed over |
| minted `requestState` → a later request | the AAD is the only thing binding a continuation to the request it was minted for (clause 5c) |
| canonicaliser recursion → the stack | peer-chosen nesting depth drives recursion, which is why the cap exists (T-113-14) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-113-122 | Spoofing | a `requestState` minted for request A accepted on request B | mitigate | the depth-cap marker is deleted; distinct params can no longer share an AAD, proven by a regression whose negative control shows the equal digests |
| T-113-123 | Tampering | replay-prevention clause 5c silently unenforced for a whole equivalence class of requests | mitigate | over-deep requests are refused at both the verify and the mint path rather than digested to a constant |
| T-113-124 | Denial of Service | removing the cap to fix the collision, reintroducing unbounded recursion | accept, avoided by design | the cap is RETAINED and the behaviour at it changed from alias to refuse; the decision and its reasoning are recorded in the plan and in the constant's rustdoc |
| T-113-125 | Denial of Service | the wire-visible refusal breaking ordinary deep-`arguments` calls | mitigate | the digest is computed only on MRTR mint/verify paths; a blast-radius test proves a non-MRTR deep call is unaffected |
| T-113-126 | Tampering | reintroducing the marker branch in a later edit | mitigate | the literal is deleted from `src/` entirely and the aliasing regression fails if it returns |
</threat_model>
