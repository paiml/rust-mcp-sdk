<objective>
Wire the server-side EGRESS half of MRTR: detect a handler's "I need more input" signal, check
declared client capabilities BEFORE doing any work, mint the continuation into a `requestState`
token, emit `resultType: "input_required"` with `inputRequests`, confine the whole mechanism to
the three eligible methods with an exhaustive compile-time tripwire, take SERVER OWNERSHIP of
every reserved envelope field, guarantee the internal signal never reaches the wire on any path,
and fix the `serverInfo` placement Phase 112 got structurally right but nested wrong.

Purpose: this is the half that makes HTTP-02 real. Phase 112 scaffolded
`ResponseDisposition::InputRequired` with an `#[allow(dead_code)]` specifically for this plan;
CLAUDE.md's zero-SATD rule means that allow must disappear when it is wired.

Cross-AI review rated the original version HIGH on four counts, all fixed here and all variations
of one theme — **reserved fields must be server-owned**: (1) a handler-supplied `resultType` was
PRESERVED by the collision-safe `entry().or_insert`, letting a handler emit `input_required` on
`tools/list` and walk straight past the exhaustive tripwire; (2) a handler-supplied `serverInfo`
was likewise preserved, enabling server-identity spoofing; (3) on v1 a signal-bearing result was
"left untouched", publishing `dev.pmcp/mrtr` and the plaintext continuation on the wire; (4) the
same leak occurred on a non-eligible v2 method via an early return. Review also required the
capability check to run BEFORE minting and to distinguish elicitation form/URL submodes.
Output: the egress path, the eligibility tripwire, reserved-field ownership, the capability
precheck, and the `serverInfo` fix.
</objective>

2. **RESERVED FIELDS ARE SERVER-OWNED (Codex Plan-09 HIGH #3/#4 — the review's top consensus
   item).** The current `inject_v2_result_envelope` uses `entry().or_insert()`, which PRESERVES a
   handler-supplied value. That is exactly backwards for a reserved field: a handler could set
   `resultType: "input_required"` on `tools/list` and sail past the tripwire above, or spoof
   `serverInfo`. Replace the collision-safe behavior with OWNERSHIP for this closed set of keys:

   | Reserved key | Location | Server behavior when a handler already set it |
   |---|---|---|
   | `resultType` | top-level result | OVERWRITE with the disposition the server computed |
   | `io.modelcontextprotocol/serverInfo` | `result._meta` | OVERWRITE with the server's real `Implementation` |
   | `requestState` | top-level result | REMOVE unless this egress minted it |
   | `inputRequests` | top-level result | REMOVE unless this egress produced it |
   | `dev.pmcp/mrtr` | `result._meta` | REMOVE always (Task 1's `strip_mrtr_signal`) |

   Implement this as one `pub(crate) fn own_reserved_result_fields(result: &mut Value, ..)` that
   runs on the v2 path before serialization, emitting a `tracing::warn!` per field it overwrote or
   removed so a handler author sees the mistake. Every OTHER `_meta` key a handler set is
   preserved untouched — ownership applies to this enumerated set only. Document the list as the
   authoritative reserved-field registry and cross-reference it from `MRTR_SIGNAL_META_KEY`'s doc.

   containing only the reserved keys). One helper, three result shapes, no per-type special cases.
