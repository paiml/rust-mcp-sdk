<objective>
Deliver HTTP-04's CLIENT half: a v2 pmcp `Client` can open a `subscriptions/listen` stream and
receive change notifications, and the two RPCs the v2 schema retired
(`resources/subscribe`, `resources/unsubscribe`) fail fast with a typed, actionable error on the
v2 path instead of producing a request the server answers with 404.

Purpose: HTTP-04's requirement text is "**v2 clients get change notifications** via a
`subscriptions/listen` long-lived stream". Plan 10 implements the server route and proves it with
raw `reqwest`, which does not demonstrate that a pmcp CLIENT can consume it — cross-AI review
scored HTTP-04 "not fully covered" for exactly this reason and additionally flagged that the
existing `subscribe_resource`/`unsubscribe_resource` methods stay callable on v2 while pointing at
RPCs that no longer exist.

This is judged as WITHIN the requirement rather than scope creep: the requirement's grammatical
subject is the client receiving notifications, and D-13 scopes the SERVER ADVERTISEMENT as opt-in
without saying anything about the client API. Kept deliberately minimal — one stream type, one
method, one era gate — so it does not expand into a subscription-management subsystem.
Output: `src/client/subscriptions.rs`, one client method, one era gate, and a live test.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| server → client stream frames | A remote server (or an intermediary) supplies the frames the client parses and tags |
| caller → retired RPCs | An application may still call APIs the v2 wire no longer defines |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-113-66 | Spoofing | a frame tagged with a DIFFERENT `subscriptionId` being passed to the caller as their own | mitigate | The stream validates `_meta[SUBSCRIPTION_ID_META_KEY]` against its own id on every frame and yields an `Err` on mismatch instead of forwarding it |
| T-113-67 | Denial of Service | a malformed or hostile SSE frame panicking or wedging the client | mitigate | The shared frame parser is reused (no second tokenizer), a malformed frame yields an `Err` item without terminating, keep-alives are skipped, and every test poll is timeout-bounded |
| T-113-63 | Denial of Service | leaked server registry slots because the client never signalled disconnect | mitigate | Dropping `SubscriptionStream` drops the HTTP response, which triggers plan 10's `ListenGuard` on the server; `client_stream_drop_releases_server_slot` proves the end-to-end reclaim |
| T-113-68 | Repudiation | a v2 application silently relying on retired RPCs | mitigate | `subscribe_resource`/`unsubscribe_resource` fail fast on v2 with a typed error naming `subscriptions/listen`, rather than emitting a request the server 404s |
| T-113-34 | Information Disclosure | receiving notification types the client never requested | mitigate | Server-side filter intersection (plan 10) plus a client-side live assertion that an unrequested type never arrives |
</threat_model>
