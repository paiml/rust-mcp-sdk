<objective>
Make the pmcp `Client` fulfil MRTR: parse `inputRequests`, preflight that every requested kind is
fulfillable, dispatch each entry through the already-registered Phase-106 host pipeline, splice
the resulting `inputResponses` plus the echoed `requestState` into a resend with a new JSON-RPC
id, and repeat under a bounded round limit — with a PUBLIC return type that can actually carry an
unfulfilled `input_required` result back to the caller.

Purpose: CLNT-02. D-06 locks handler REUSE and says that with no handler, or on a decline/error,
the client "returns the `input_required` result to the caller". Cross-AI review found that this
was not expressible: `call_tool` returns `CallToolResult`, whose `content` field carries
`#[serde(default)]`, so an `input_required` result deserializes into a SILENTLY EMPTY success —
and `ReadResourceResult.contents` has no default, so the same result fails to deserialize at all.
Neither outcome is "returns the result to the caller". This revision adds the additive
`MrtrOutcome` API (types defined in plan 02) plus a structured client-local error carrier so the
EXISTING methods stop lying.

Review also required: preflight before invoking any handler, reuse of the full host pipeline
(approval + result review), observable handler errors, and unit/mock-transport testing only —
live client↔server MRTR moved to plan 11, which depends on both 07 and 09.
Output: two typed client-local errors, an `inputRequests` classifier + preflight, the bounded
loop, and the `MrtrOutcome` methods.
</objective>
