<objective>
Implement `subscriptions/listen` as an opt-in, capability-gated long-lived SSE stream, with
pmcp's stateless enterprise default advertising no subscription-delivered capability — the
configuration for which answering `-32601` is recorded conformant — and a local tripwire
enforcing that advertising implies serving.

Purpose: D-13 resolves D-12. Research read the official conformance suite's gating logic
directly: a server advertising none of `tools.listChanged` / `prompts.listChanged` /
`resources.listChanged` / `resources.subscribe` may answer `subscriptions/listen` with `-32601`
and the check is SKIPPED; a server that DOES advertise one and then rejects the method FAILS.

Cross-AI review rated the original stream design HIGH risk on five production-robustness points,
all fixed here: registry entries keyed by the JSON-RPC id ALONE (different callers routinely
reuse `1`), an unbounded channel a slow subscriber can grow without limit, no disconnect-safe
unregistration (a dropped SSE response leaked entries and permits), per-principal limits with no
stated path for `AuthContext` to reach the registry, and stream frames bypassing the shared v2
envelope/header helpers. Review also flagged that HTTP-04's client half was missing entirely —
that is now plan 13, which depends on this plan.
Output: the subscription types, a capability-gated route, a robust stream, and the tripwire.
</objective>
