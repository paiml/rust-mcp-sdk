<objective>
Build the `requestState` token: a self-contained, AEAD-encrypted, principal-bound,
originating-request-bound, TTL'd blob that lets any instance behind a load balancer resume a
multi-round-trip operation while the server holds nothing between round trips — owned by the
SERVER INSTANCE, not by the process.

Purpose: This is the one place in the SDK where a cryptographic mistake is directly
exploitable by a remote party — the spec says servers MUST treat `requestState` as
attacker-controlled input. D-01/D-02/D-03/D-04/D-05/D-15 all land here.

Cross-AI review rated the original version HIGH risk on three architectural points, all fixed
here: (1) a `OnceLock` process-global codec cannot support builder configuration, multiple
differently-configured servers in one process, deterministic integration tests, or key
rotation — it is now an `Arc<RequestStateCodec>` on the server; (2) a malformed CONFIGURED key
was logged and replaced with a random fallback, which is not what D-04 says (D-04's fallback
covers the UNSET case only) — it now fails the server build; (3) lazy first-request
initialization made the required startup warning unreliable — it is now emitted at build time.
Output: `src/server/request_state.rs`, its builder wiring, property tests, and fuzz target.
</objective>

**`pub(crate) fn mint(&self, state: &serde_json::Value, binding: &RequestBinding<'_>, round: u8) -> Result<String>`**
— fresh 12-byte nonce per call from `getrandom` via the no-unwrap helper; `exp = self.clock.now_unix() + ttl`;

**`pub(crate) enum Verdict { Ok(Continuation), Expired(Continuation), UnknownKey, AuthFailed }`**
and **`pub(crate) fn verify(&self, token: &str, binding: &RequestBinding<'_>) -> Verdict`**.
Never returns `Result` — every failure is a verdict, so no caller can accidentally `?` a
security decision into a 500.

**`Expired` MUST carry the decrypted `Continuation`.** This is the fix for the consensus
finding both reviewers raised: an authentic-but-expired token has ALREADY passed the
constant-time tag check, so its plaintext is available, and plan 06 needs it to re-elicit
"cleanly" per D-15 while preserving the round counter (so a hostile server cannot reset a
client's D-09 bound by letting tokens expire). Do NOT collapse `Expired` into a payload-free
variant.

**The verdict table is LOCKED by D-15** (this overrides 113-RESEARCH.md Assumption A5):

| Condition | Verdict | Caller behavior (plan 06 wires it) |
|-----------|---------|-------------------------------------|
| token longer than `MAX_REQUEST_STATE_LEN`, not base64url, or too short to hold key-id+nonce | `AuthFailed` | JSON-RPC error |
| no accepting entry's key-id matches | `UnknownKey` | strip MRTR fields and RE-RUN the handler (D-04 degraded path) |
| a key-id matches but AEAD tag verification fails on every matching entry | `AuthFailed` | JSON-RPC error (conformance `sep-2322-reject-tampered-state`) |
| decrypts, `exp` in the past | `Expired(continuation)` | re-elicit cleanly, preserving `continuation.round` (D-15/D-05) |
| decrypts, `exp` in the future | `Ok(continuation)` | resume |

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → server (`params.requestState`) | Remote, unauthenticated-at-parse-time, attacker-controlled bytes enter the crypto path |
| process environment → server | `PMCP_REQUEST_STATE_KEY` carries the long-lived secret |
| instance A → instance B (via load balancer) | A token minted on one instance is verified on another |
| operator configuration → server startup | A malformed key must fail loudly, not degrade silently |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-113-01 | Tampering | `verify` on a mutated token | mitigate | `ring::aead` CHACHA20_POLY1305 constant-time tag verification; any mutation → `Verdict::AuthFailed` → JSON-RPC error; exact conformance `-TAMPERED` mutation has a dedicated test |
| T-113-02 | Spoofing | cross-principal token replay | mitigate | `AuthContext.subject` is the first AAD component via `RequestBinding`; a wrong principal fails the tag check, not a comparison — no oracle, no `==` |
| T-113-03 | Elevation of Privilege | same-principal replay onto a different tool/arguments | mitigate | `method` + `salient_param_digest` are the second and third AAD components (spec replay clause 5c); dedicated test replays a token across differing `arguments` |
| T-113-04 | Repudiation | long-window replay | mitigate | `exp` baked into the sealed plaintext, default 300s (D-05), configurable by env AND builder; documented that TTL bounds but does not prevent reuse — single-use is explicitly out of scope for a self-contained token |
| T-113-05 | Information Disclosure | key material in logs, `Debug` output, or process listings | mitigate | manual `Debug` prints only key ids and ttl; BOTH the decoded key buffer and the env `String` are zeroized after `UnboundKey` construction; no `tracing` field ever carries key bytes; key-id documented as non-secret |
| T-113-10 | Information Disclosure | verdict discrimination oracle | mitigate | principal/method/digest mismatches all collapse into `AuthFailed` because they live in the AAD; only `UnknownKey` is distinguishable and it carries no secret ("not my key") |
| T-113-14 | Denial of Service | oversized or malformed token parsing | mitigate | `MAX_REQUEST_STATE_LEN` (8192) checked before decode; every malformed shape returns a verdict rather than erroring; fuzz target proves no panic over arbitrary bytes |
| T-113-17 | Spoofing | misconfigured key silently degrading security | mitigate | UNSET → per-process random WITH a build-time `tracing::warn!` naming the consequence (D-04); MALFORMED → `ServerBuilder::build()` returns `Err`, so a production misconfiguration cannot boot into a degraded mode unnoticed |
| T-113-48 | Tampering | key-id collision producing a wrong verdict | mitigate | Every accepting entry with a matching key-id is tried; `UnknownKey` only when none matches; a colliding-but-different key yields `AuthFailed`, proven by a forced-collision test |
| T-113-49 | Repudiation | a hostile server resetting a client's round bound by letting tokens expire | mitigate | `Expired(Continuation)` preserves `round`, and plan 06 carries it into the re-elicited token rather than restarting at 0 |
