**Derive, never enumerate.** Parse the authoritative four-backtick JSON array out of
`.planning/WINDOWS.md` with `serde_json` — already a dependency; do not hand-roll a parser — and
select every entry whose `description` contains the `[CONSUMER-OBSERVABLE]` sentinel. That

next disclosure, which is precisely the rot this test exists to prevent. Phase 115 learned the
same lesson the hard way: a fence that restates the rule under test cannot detect a defect in that
rule, which is why `keyword_list_mirrors.rs` carries its own container literal rather than
importing the crate's.

**Assert the citation.** For each selected entry, assert the migration chapter contains a
searchable reference to that entry id, in the citation form plan 119-05 used. Read the chapter and
determine that form before writing the matcher; do not invent one. Prefer a matcher tight enough
that an unrelated occurrence of a bare number cannot satisfy it — an entry id of `12` must not be
satisfied by the string `12` appearing in a version number or a line reference.

**Add the positive control.** Assert the derived set is NON-EMPTY, with its own message. A test
that selects zero entries and then vacuously satisfies "every selected entry is cited" is the same
false green in a different shape, and this repository has a recorded history of exactly that. The
non-empty assertion is what makes the loop's success mean something.

**The two excluded-tree guards.** The test reads `.planning/WINDOWS.md` and a file under
`pmcp-book/src/`, and BOTH trees are in `Cargo.toml`'s `exclude`. Apply the
`tests/v2_conformance_pin.rs:96-111` guard shape twice, once per tree, with its rustdoc rationale
adapted: return early when the whole tree is absent (a downstream checkout genuinely has nothing
to read), but FAIL when the tree exists and the file does not. A silent skip on a present-but-empty
tree is the vacuous shape to avoid.

**Read at runtime.** Use `fs::read_to_string`, never `include_str!`: a ledger or chapter edit must
move these assertions without anyone remembering to rebuild. Use the ten-copy house `repo_root()`
helper shape — integration tests are separate binaries and cannot import across files, so
duplicating it is the documented house choice.

**Panic messages.** Every failure message carries two parts, in the house form: a `FAILURE MODE:`
explaining what went wrong and why it matters, and a `WHAT TO DO:` naming the literal edit that
fixes it. The `WHAT TO DO:` must name the `[CONSUMER-OBSERVABLE]` sentinel literally and name the
migration chapter's path, so a future recorder who trips this test is told exactly what to add and
where. Do not tell them to delete the assertion.

**The packaging decision — make it explicitly and record which.** Two defensible dispositions
exist in-tree. (a) Ship the test with the two guards, as `tests/v2_conformance_pin.rs` does. (b)
Add the test file to `Cargo.toml`'s `exclude` array, as four existing test files already are —
a four-instance house pattern that is strictly stronger, since it removes the downstream skip path
entirely. Choose one, act on it, and record the reason. If you choose (b), add a `# Why:` comment
beside the entry matching the surrounding style. Then run `cargo package --list` and confirm the
file's presence or absence matches the decision — an accidental disposition is the thing to avoid,
not either particular choice.
