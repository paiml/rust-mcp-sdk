<objective>
Ship the tasks-aware tool seam, the connector-client factory, and the package-config resolution seam:

1. **`ClientToolInvoker` (AGNT-08):** implements `ToolInvoker` over `pmcp::Client`. Each call reads `related_task` and, when present, drives the task to completion via `Client::wait_for_related_task(&meta, opts)` — VERIFIED at `src/client/mod.rs:847`, which merges the task's `TaskMetadata` poll hints (`or_from_metadata`) with caller options; the caller sets a host-configurable hard maximum (`WaitForTaskOptions::max_poll_duration_secs`) so it can NEVER poll forever (Codex HIGH — `wait_for_task` + `WaitForTaskOptions::default()` has no overall timeout). `invoke_batch` overrides the sequential default with BOUNDED-concurrency parallel dispatch (D-07), preserving input order and ToolCall ids.
2. **`ConnectorClientFactory` seam:** resolved endpoints can be URL or command transports (Codex HIGH — `Client<T>` is transport-generic, so "a client or a map of clients" is not a minor choice). A `ConnectorClientFactory` seam produces an object-safe connector client per endpoint; this plan ships the URL/HTTP-transport impl and documents the command-transport impl as a narrow, justified follow-up.
3. **`SlotResolver` seam + `resolve_agent` (AGNT-09):** resolves an `AgentPackage`'s slots (D-14) via two impls (env-var + programmatic); deviation from `tested_value` warns and runs (D-15); connector refs resolve via `resolve_endpoint(name)` into an endpoint map (D-16). `resolve_agent(&AgentPackage) -> ResolvedAgentConfig` is the end-to-end composition path (Codex HIGH — resolving slots alone did not show the package fully constructs the runtime).

Output: `invoker/{client,factory}.rs`, `config/{resolver,endpoint}.rs` + `resolve_agent`, and integration/unit tests including an end-to-end AGNT-09 composition test.
</objective>
