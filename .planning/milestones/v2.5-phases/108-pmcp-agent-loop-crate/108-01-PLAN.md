<objective>
Land the paired `pmcp` core changes the hosted-agent flow depends on, shipped as the `pmcp` 2.17.0 minor bump (D-04). All three changes are ADDITIVE — existing servers/clients/PeerHandle-implementors behave identically.

1. **D-106-A fix (D-01/D-02) via a Transport Actor.** `Server::run`'s transport is refactored so the receive/drain path NEVER blocks on request execution, request-queue capacity, or a transport write-lock. A single owner task owns the transport and interleaves receive + send through `tokio::select!`; inbound Responses route to the peer dispatcher IMMEDIATELY (unblocking an awaiting `peer.sample()`/`.list_roots()`), inbound Requests go to a SINGLE sequential worker via an UNBOUNDED channel (request handling stays serialized — zero behavior change), and ALL outbound frames (responses, server-requests, notifications) funnel through one mpsc `send_tx`. This closes BOTH reviewer-identified failure modes: the bounded-channel re-deadlock (Codex) and the `Arc<RwLock<T>>` write-guard starvation (Gemini — verified: today `receive_message_from_transport` holds `transport.write()` ACROSS `t.receive().await`, so a naive loop-split would starve `spawn_server_request_drain`'s `transport.write()`).
2. **End-to-end WithTools sampling.** The client host surface gains a `HostSamplingHandlerWithTools` path returning `CreateMessageResultWithTools` (so `on_sampling_with_tools` can return `ToolUse` blocks — the legacy `HostSamplingHandler` returns single-content `CreateMessageResult` and CANNOT, verified `src/client/host/sampling.rs:44`). Legacy handlers keep working through a default adapter that lifts their single `Content` into a one-element `Vec<SamplingMessageContent>`. The server-side peer gains `sample_with_tools` returning `CreateMessageResultWithTools` with a legacy single-content decode fallback (Gemini), added as a DEFAULT trait method so downstream `PeerHandle` implementors do not break (verified `pub trait PeerHandle`, `src/shared/peer.rs:50`).

Purpose: without the never-block pump the hosted agent deadlocks; without an end-to-end WithTools path the `SamplingSource` (AGNT-04) can never carry tool calls and the plan-108-04 test cannot compile. Both must land together for the D-03 real-loop proof.
Output: refactored transport actor in `Server::run`, WithTools client-host surface, `PeerHandle::sample_with_tools` (+ DispatchPeerHandle impl), real-loop integration tests (incl. saturation + shutdown), version bump to 2.17.0, and the cargo-pmcp scaffold-pin updated in lockstep (D-04 tripwire).
</objective>
