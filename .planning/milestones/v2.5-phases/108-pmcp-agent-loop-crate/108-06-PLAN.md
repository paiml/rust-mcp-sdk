<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → agent-as-server tool | Untrusted tool input (the conversational message + optional run_id) crosses into the adapter's tool handler |
| agent run → downstream connectors | The spawned run invokes connector tools; results are untrusted |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-108-06-01 | Tampering / Input Validation | adapter tool input (message + run_id) | mitigate | Input validated against the package `input_schema` (serde typed); run_id is an opaque string keying the ConversationStore; malformed input → tool error, not panic (ASVS V5) |
| T-108-06-02 | Denial of Service | runaway agent run (cost/loops) | mitigate | Run bounded by ResolvedAgentConfig max_iterations/max_tokens via `check_limits` (108-03); fresh run per call bounds per-call state; task lifecycle is store-backed and terminal |
| T-108-06-03 | Information Disclosure | error/log surface of the hosted run | mitigate | Handler errors sanitized (host surface maps to -32603); no secrets in logs; example never prints keys (SecretString) |
| T-108-06-04 | Broken Access Control | run_id resuming another caller's session | mitigate | run_id is namespaced to the adapter's ConversationStore instance (per-server); cross-tenant isolation is host policy (documented); no ambient authority granted by an arbitrary run_id beyond that store |
| T-108-06-05 | Repudiation | prompt-injection via connector output | accept | Out of SDK scope (host/model policy); rustdoc notes the loop treats tool output as data and takes no privileged action beyond declared tools |
| T-108-06-SC | Tampering | crates (supply chain) | accept | No new package installs (uuid already vetted in workspace; RESEARCH Package Legitimacy Audit) |
</threat_model>
