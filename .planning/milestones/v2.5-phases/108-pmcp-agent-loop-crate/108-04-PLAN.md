<objective>
Ship the three `CompletionSource` implementations (sampling-first; the trait is the extension point):

1. **`SamplingSource` (AGNT-04, zero-dep):** implements `CompletionSource` over the agent's server-side peer using `PeerHandle::sample_with_tools` (added in plan 108-01), so a hosted agent drives tools through spec sampling. Rides the D-106-A fix (completes on the stock server loop). Now UNBLOCKED — the 108-01 WithTools client-host path means `on_sampling_with_tools` can actually return ToolUse blocks.
2. **`OpenAiCompatSource` (AGNT-05, feature `openai-compat`):** any OpenAI-compatible `/chat/completions` endpoint (Ollama/vLLM/OpenRouter/xAI/DeepSeek) via reqwest.
3. **`AnthropicSource` (AGNT-06, feature `anthropic`):** the Anthropic Messages API via reqwest.

Review-driven hardening: HTTPS-only is relaxed to ALLOW plain HTTP for loopback/localhost (Ollama is a named AGNT-05 use case — Codex/Gemini) while requiring HTTPS for non-local hosts unless an explicit insecure-local opt-in is set; both HTTP sources apply a request timeout and a bounded response body; API keys live in a `SecretString` newtype whose custom `Debug` redacts (not just tested); provider mappings get table-driven edge-case tests; `AnthropicSource` normalizes history (Gemini — merge consecutive same-role, pack tool_results into one user message after the matching tool_use, hoist system to the top-level param) or the Messages API 400s on parallel-tool histories; and a LOCAL MOCK server verifies URL/path/headers/auth/timeout/status (not only pure transforms).

Output: `sources/{secret,sampling,openai_compat,anthropic}.rs`, a real-loop SamplingSource test, and a feature-gated mock-server test.
