<objective>
Implement `cargo pmcp team dev` (CLI-03): a thin CLI over the Phase 109 `TeamRuntime`
wiring API (D-02 — the DEFAULT flow MUST NOT re-implement composition). Default behavior
runs the doc-review E2E scenario on a `FixedSource` and prints a labeled transcript of the
7-step flow, fully offline and deterministic, from a loaded `TeamPackage` (`--package` +
`--data-dir`, defaulting to the built-in doc-review fixture). `--serve` (D-02a) exposes
team-mcp over HTTP by reusing the shipped `team-mcp` binary's PUBLIC serve recipe
(`build_team_mcp_server` + `dev_bin::serve_streamable_http`) on loopback `127.0.0.1:<--port>` —
NOT through `TeamRuntime` (which only exposes in-memory `Client<DuplexTransport>` clients, not the
server), and with NO upstream API change (Codex 110-04 HIGH). `--llm <endpoint>` (D-02b) swaps
FixedSource for an `OpenAiCompatSource` wrapped in the already-exported `FixedSourceFactory`
(the `CompletionSourceFactory` trait is sync + infallible, so a custom fallible factory is the
wrong shape — Codex 110-04 HIGH). Fills the plan-110-01 stub in team/dev.rs.

Purpose: The "watch the team collaborate offline" first-run demo; the sanctioned migration
template replacing the platform's raw-JSON-RPC team dispatch — a real dev verb, not a canned demo.
Output: A wired `team dev` handler + an offline transcript test + a --serve ephemeral-port test +
a --llm mock-endpoint test.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| shell → team dev | User-supplied `--serve`/`--port`/`--llm`/`--package`/`--data-dir` flags |
| team dev --serve → network | Binds a loopback HTTP listener exposing team-mcp on 127.0.0.1:<port> |
| team dev --llm → LLM endpoint | Outbound HTTP to a user-named endpoint |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-110-04-01 | Information disclosure | `--serve` HTTP listener | mitigate | Reuse the shipped team-mcp binary's serve recipe (`serve_streamable_http`) which the SDK owns DNS-rebinding/CORS/security-headers for; bind loopback `127.0.0.1:<port>` by default; default (no `--serve`) stays fully in-process with no listener |
| T-110-04-02 | Tampering / EoP | `--llm` endpoint URL | mitigate | Parse `--llm` with `url::Url`; construct via `OpenAiCompatSource::with_options`, whose `validate_endpoint` rejects remote plain-http unless `--allow-insecure-http` → actionable bail (Consensus concern #1) |
| T-110-04-03 | Information disclosure | `--llm` API key | mitigate | Key sourced from `--llm-api-key-env <VAR>` (env-backed), carried as `SecretString`; never `println!` a raw key |
| T-110-04-04 | Denial of Service | default flow | accept | Default flow is offline FixedSource over a tempdir data root — no external dependency, deterministic; low risk |
</threat_model>
