<why_the_invariants_changed>
<!-- Verified against the repository during the 2026-08-01 `--reviews` replan. -->

**The pre-review fuzz invariant was FALSE.** It asserted `!(v2_conforms && !v1_conforms)` for every
schema declaring a legacy `$schema` — i.e. that the 2020-12 pin is never MORE permissive than v1's
auto-detect. But `115-03-PLAN.md` Task 3 test 3 deliberately constructs exactly that case: it uses
the `dependencies` keyword BECAUSE 2020-12 split it into `dependentRequired` / `dependentSchemas`,
so `dependencies` stops applying under the pin. A draft-07-declared `{"dependencies": ...}` schema
therefore rejects on v1 and accepts on v2 — `v2_conforms && !v1_conforms` — and the fuzz target would
report the phase's own intended, tested behaviour as a regression. **Do not assert cross-dialect
monotonicity anywhere.** 115-03 Task 3 test 3's rustdoc says so at the code as well.

**The pre-review seam's return type could not express its own skip condition.** It returned
`(bool, bool)` built from `schema_mismatch(..).is_none()`, while its invariant 2 said "skip when the
schema fails to COMPILE under either era". `is_none()` collapses *invalid schema* and *valid schema
with a violating instance* into the same `false`, so the skip is unimplementable at that signature.
The seam now returns an explicit three-state verdict.

**What IS true, and what this target now asserts instead:**
  1. **Totality.** No input pair panics. A panic inside emit-time validation is a remotely reachable
     unwind.
  2. **Normalization idempotence and surgical scope.** `normalize_schema_dialect` applied twice
     equals once, and the result differs from the input only at the ROOT `$schema` key.
  3. **Dialect-neutral era AGREEMENT.** For a schema whose keyword set is drawn ONLY from keywords
     with identical meaning in draft-07 and 2020-12, the two eras must produce the SAME verdict —
     equality, not an inequality. This is the correct generalization of the vacuous-validator fence:
     a vacuous v2 validator would return `Conforms` where v1 returns `Violates`, which this equality
     catches, while genuinely divergent keywords are excluded from the neutrality predicate rather
     than asserted about.

The dialect-neutral keyword allowlist (identical semantics in both drafts):
  `type`, `properties`, `required`, `enum`, `const`, `minimum`, `maximum`,
  `minLength`, `maxLength`, `pattern`, `additionalProperties`, `minItems`, `maxItems`
The EXCLUDED keywords, each with a named reason, to be listed in the target's module doc:
  `dependencies`            — split into `dependentRequired`/`dependentSchemas` in 2020-12
  `items` (array form)      — replaced by `prefixItems`; array form is a COMPILE ERROR under 2020-12
  `exclusiveMinimum` / `exclusiveMaximum` (boolean form) — became numeric in draft-06
  `definitions`             — replaced by `$defs`
  `$ref` alongside siblings — sibling keywords are ignored in draft-07, honoured in 2020-12
  `id` (vs `$id`)           — draft-04 spelling
</why_the_invariants_changed>

**(c) A LENGTH-PREFIXED input format, so the target reaches compilation.** Do NOT split raw bytes
arbitrarily — the cross-AI review measured that both halves then seldom parse as JSON and the target
degenerates into a JSON-parser fuzz. Define and document this byte layout at the top of the target:

    byte 0                  : case selector — 0 means RAW pair, anything else means JSON pair
    bytes 1..5              : u32 little-endian schema_len
    bytes 5..5+schema_len   : schema bytes
    bytes 5+schema_len..    : instance bytes (the remainder)
