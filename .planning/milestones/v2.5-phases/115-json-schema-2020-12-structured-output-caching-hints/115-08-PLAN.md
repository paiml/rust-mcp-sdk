<objective>
Fence the invariants this phase establishes but cannot defend by configuration alone: SEP-2106's
no-external-`$ref` property (D-03), D-12's single-projection-point property, the wasm dispatcher's
strip call that no native gate compiles, and the measured projection-versus-middleware ordering.

Purpose: D-03 explicitly rejected "config alone" — *"it is exactly the rot condition the 114-16
instrument exists to catch."* 115-RESEARCH § Finding 2 sharpened WHY: cargo feature unification is
graph-wide, so ONE workspace member, example or dev-dependency declaring `jsonschema` with default
features turns `resolve-http` on for the entire graph and silently converts the measured 60 µs
refusal into a live network fetch. **A behavioural test would still pass** — it would pass *better*,
because the fetch would succeed. Only a dependency-graph check catches that, and no test in this repo
does one today.

**What the cross-AI review changed about this plan.** The pre-review version scanned `Cargo.toml`
dependency LINES with string matching. That misses table-style declarations, multiline declarations,
a dependency renamed via `package = "jsonschema"`, and any future `[workspace.dependencies]`
inheritance. This plan parses cargo's own output instead, in two layers:
  - `cargo metadata --format-version 1 --no-deps` → every workspace package's DECLARED dependency
    on `jsonschema`, normalized, with `rename`, `optional`, `uses_default_features` and `features`
    as structured fields;
  - `cargo metadata --format-version 1 --features validation` → the RESOLVED graph's
    `resolve.nodes[].features` for `jsonschema`, which is the definitive unification answer.
Both were probed during the `--reviews` replan and produce exactly the needed shape. This requires no
new dependency: `std::process::Command` plus `serde_json`, which every test crate already has.

Two more fences the review's findings added: the wasm dispatcher's `project_caching_hints` call is
compile-checked ONLY by `make wasm-build` and, as 115-06's negative control demonstrates, its removal
does NOT break that build — so a source assertion is the only thing that catches it. And the
projection is not the final mutation of the response, so the measured ordering must be pinned.

Output: `tests/v2_schema_tripwires.rs` — a new instrument in the proven 114-16 shape (runtime
discovery, comment/literal stripping, two-kind justified allowlists, per-check anti-vacuity).
</objective>
