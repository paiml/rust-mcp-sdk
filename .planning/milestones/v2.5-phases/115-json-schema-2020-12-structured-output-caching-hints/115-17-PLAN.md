<which_fence_catches_what_here>
This module now contains four kinds of assertion and they have different powers. Getting them
confused is how the last three rounds shipped, so state it once:

- **Surgical scope** (`strip_dialect_declarations` on both sides) — RESTATES the shipped rule.
  Catches a normalizer that touched a non-`$schema` key. It CANNOT catch a rule defect, and per
  `115-REVIEW.md` WR-06 it cannot even false-positive from a blind strip, because the same strip is
  applied to both sides of the comparison.
- **Dialect purity** (`collect_dialect_declarations`) — RESTATES the shipped rule. Catches a
  detector/rewriter DISAGREEMENT, and — this is the part worth keeping — catches a crate-list
  omission WHEN THIS MIRROR IS CORRECT AND THE CRATE IS NOT, because the mirror's scan reaches a
  position the crate's walk skipped. It passes vacuously when both share the defect. It is also the
  half that genuinely CAN false-positive from a blind scan (WR-06's correction).
- **Rename invariance** — DERIVED from a JSON Schema 2020-12 vocabulary fact, consults no keyword
  list. It is the instrument for a defect in the RULE. But its CONTAINER selection is drawn from
  `arb_container()`, so it is only as reachable as the generated space: that is exactly CR-01's
  *"gated by a crate-derived list one line earlier"*, and it is why widening `arb_container()` is
  half of this task rather than a nicety.
- **Mirror equality** (new) — a compiled check that this file's restatement equals the shipped
  values. It is the only thing in this module that catches drift, in either direction.
</which_fence_catches_what_here>
