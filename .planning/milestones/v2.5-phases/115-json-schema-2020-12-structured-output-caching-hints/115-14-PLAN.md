<why_position_and_not_an_allowlist_rewrite>

current walk is deliberately a SUPERSET of what `jsonschema` honours (a nested declaration on an

Change the member dispatch in BOTH `first_legacy_dialect` and `pin_dialect_in_place` to a
three-way decision on the member key, keeping both function signatures byte-identical:

1. Key is in `SUBSCHEMA_MAP_KEYWORDS` AND its value is a JSON object → recurse into every VALUE of

2. Key is in `SUBSCHEMA_MAP_KEYWORDS` but its value is NOT an object (a malformed document) → fall
   through to ordinary recursion, so no coverage is lost relative to today's walk. CR-01's sketch
   omits this and silently stops descending; do not copy that.
