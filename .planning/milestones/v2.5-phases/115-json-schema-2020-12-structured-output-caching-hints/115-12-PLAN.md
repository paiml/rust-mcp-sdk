Add two private helpers next to it, both `#[cfg(feature = "validation")]`, both with rustdoc:

- `fn first_legacy_dialect(node: &Value) -> Option<&str>` — walk order root-first; returns the FIRST
  dialect declaration whose string differs from `DRAFT_2020_12`, or `None`.
- `fn pin_dialect_in_place(node: &mut Value)` — rewrites EVERY dialect declaration to
  `DRAFT_2020_12`.

Both walks MUST use one traversal rule, stated once in rustdoc and implemented identically in both,
because a disagreement between them yields a `Cow::Owned` that still carries a legacy declaration —
exactly the "ignored nothing while claiming to ignore" failure the current `expect` was written to
prevent:

1. At an object node, the key `$schema` is a DIALECT DECLARATION **only when its value is a
   `Value::String`**. A non-string value is not a declaration and must be left alone — this is what
   distinguishes a real declaration from a `properties` map entry for an instance property literally
   named `$schema`, whose value is a subschema (object or boolean), never a string.
2. Recurse into every member value EXCEPT the values of `const`, `enum`, `default` and `examples`.
   Introduce `const DATA_ONLY_KEYWORDS: &[&str] = &["const", "enum", "default", "examples"];` for
   this. Those keywords carry INSTANCE DATA, not subschemas; rewriting a `$schema` string inside one
   changes which instances conform, which is a semantic corruption, not a normalization.
3. At an array node, recurse into every element. Scalars terminate.

`normalize_schema_dialect` becomes: `first_legacy_dialect(schema)` is `None` ⇒ `Cow::Borrowed`
(unchanged zero-allocation common case, including the already-2020-12 and undeclared documents);
otherwise clone once, run `pin_dialect_in_place` on the clone, return `Cow::Owned`. The
`.expect("a document with a root $schema key is a JSON object")` disappears — the walk handles a
non-object root naturally. Its REASON must not disappear: state in rustdoc that the postcondition
`first_legacy_dialect(&owned) == None` is what now guarantees an `Owned` return really was rewritten,
