<interfaces>
The seam this target drives, gated `all(feature = "fuzzing", feature = "validation")` and enabled by
`fuzz/Cargo.toml`'s `[dependencies.pmcp]` entry:

- `pub fn normalize_bytes(schema_bytes: &[u8]) -> Option<(Value, Value, Value)>`
- `pub fn validate_bytes(schema_bytes: &[u8], instance_bytes: &[u8]) -> Option<(SchemaVerdict, SchemaVerdict)>`
- `pub enum SchemaVerdict { Conforms, Violates, InvalidSchema }`
- **NEW in 115-16:** `pub const DATA_ONLY_KEYWORDS` / `pub const SUBSCHEMA_MAP_KEYWORDS` re-exports.
  **Do NOT import them here — see the next block for why.**

The rule as of 115-16: a `$schema` key is a dialect declaration ONLY when its value is a
`Value::String`; the walk never descends into the values of `const` / `enum` / `default` /
`examples`; and the VALUES of a `properties` / `patternProperties` / `$defs` / `definitions` /
`dependentSchemas` / **`dependencies`** map are descended into UNCONDITIONALLY, with that data-only
exclusion NEVER applied to those maps' own keys.

Seed byte layout (from the corpus README): one selector byte, then the little-endian `u32` schema
length, then the schema bytes, then the instance bytes. `HEADER_LEN = 5`; `SELECTOR_RAW = 0`, so any
non-zero selector is the JSON family.
</interfaces>
