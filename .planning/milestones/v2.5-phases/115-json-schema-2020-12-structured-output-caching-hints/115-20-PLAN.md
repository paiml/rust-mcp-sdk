## The defect, restated from measurement

`allOf` / `anyOf` / `oneOf` / `prefixItems` hold their subschemas in a JSON **array**. The
descent IS implemented and IS correct — `src/server/output_validation.rs:269` (detector
`Value::Array` arm) and `:325` (rewriter `Value::Array` arm), stated as rule 4 in the module
rustdoc. What is absent is every layer around it:

- **Deleting both `Value::Array` arms passes the entire suite.** Measured independently twice
  (round-4 reviewer; round-4 verifier, who recorded `output_validation` 25/25,
  `binary(property_tests)` 21/21 and a clean fuzz `cargo check` with the descent disabled).
- No test, no property draw, no corpus seed reaches an array position.
- The contract's `SCHEMA POSITION` definition, its `walk:` clause and its POSTCONDITION
  enumerate only the six **map** containers. The array axis is unstated.

**Why this is a FENCE-and-PROSE gap, not a behaviour defect** (D-115-AM (2), ratified): there is
no author-chosen name at an array position, so there is nothing for a `DATA_ONLY_KEYWORDS`
collision to hide behind — the shape that reopened SCHM-01 in rounds 1, 2 and CR-01 structurally
cannot occur here. This plan therefore adds no behavioural change. **If any task below changes a
verdict or a borrow/own decision on an existing case, stop — that is a regression, not a fix.**

## Design decisions

**D-115-20-A — no new SHIPPED constant.** A `SUBSCHEMA_ARRAY_KEYWORDS` list would be dead
weight: the shipped descent is *unconditional* at an array node and consults no list, so a
constant would be a fourth mirror to keep in lockstep for zero implementation benefit — and it
would import the exact list-incompleteness defect class (CR-01, WR-02) into a position that
cannot suffer from it. The fences carry their **own** literals, which is this phase's standing
rule (`D-115-AI(4)`: *a fence's reachability must not be derived from the same artifact as the
rule it checks*).

**D-115-20-B — `EmbeddedPointer` is reused unchanged.** `/allOf/0/$schema` is a well-formed RFC
6901 pointer, so an array position is addressed by setting `name` to the decimal index. No
struct change, no new pointer builder.

**D-115-20-C — the rename-invariance property keeps drawing MAP containers only.**
`arb_embedded_schema_document()` exists to prove a document's meaning does not change when an
author-chosen name changes. An array position has no name to rename, so widening that draw would
generate cases where the "renamed" pair is byte-identical — vacuous passes that inflate the
sample count while proving nothing. Only `arb_schema_document()` widens.

**D-115-20-D — the new fence's anti-vacuity assertion is a HARD-CODED count.** `115-REVIEW.md`
WR-01 showed `assert_eq!(examined, containers.len() * NAMES.len(), …)` recomputes the loop bound
from the loop bound and cannot fail. The new fence asserts against a literal `8`, so shrinking
its container literal FAILS the fence. (WR-01's own site is out of scope here and stays booked
under D-115-AM (3).)

## Tasks

### T1 — `src/server/output_validation.rs`: fixture + case row + grid fence

1. Add `embedded_legacy_resource_in_array(container: &str, index: usize) -> Value` beside
   `embedded_legacy_resource_in_container`, delegating to one shape: an `$id`-bearing embedded
   resource carrying `DRAFT_07`, filed at `container[index]`, with `index` inert `{}` fillers
   ahead of it so a non-zero index is reachable. Same `example.test` non-resolvable `$id` and
   same no-`$ref` rationale as its map twin (SEP-2106).
2. Add ONE row to `normalization_cases()` — `(embedded_legacy_resource_in_array("allOf", 1), true)`
   — so the array position flows through BOTH the structural fence
   (`normalize_schema_dialect_changes_only_dollar_schema_keys`) and the idempotence fence
   automatically, exactly as rows (e)–(k) do. Index **1**, not 0, so a fence that only ever
   visits the first element fails.
3. Add `v2_pin_rewrites_an_embedded_resource_at_every_spec_defined_array_position`: sweep the
   fence's own literal `["allOf", "anyOf", "oneOf", "prefixItems"]` × indices `[0, 2]`, assert
   `rewritten == true` and `pointer("/{container}/{index}/$schema") == DRAFT_2020_12`, collect
   violations rather than aborting in-loop (same rationale as the map grid fence), and assert
   `examined == 8` per D-115-20-D.

**Verify:** `cargo test --features full --lib output_validation` — count must RISE from 25.

### T2 — `tests/property_tests.rs`: widen the generated space

2. Give `embed_resource` an ARRAY branch keyed on `ARRAY_CONTAINER_DRAW.contains(&container)`:

3. Widen `arb_schema_document()`'s container draw to `CONTAINER_DRAW ∪ ARRAY_CONTAINER_DRAW`,
   and set `EmbeddedPointer.name` to `"0"` on the array branch (D-115-20-B).
4. Leave `arb_embedded_schema_document()` and `keyword_lists_mirror_the_shipped_ones`
   **untouched** — the superset guard is over `SUBSCHEMA_MAP_KEYWORDS`, which array keywords are

### T4 — the contract's position definition

   position.
3. The `invariants:` entry that enumerates the six map containers — add the array-position
