<objective>
Bring the two server-side identity providers onto the same discovery behavior 116-06 gave the client:
the SEP-2351 ordered candidate probe, the RFC 8414 §3.3 issuer-anchor check, and bounded whole-body
reads (D-13, Pitfall 1, D-15).

Purpose: `generic_oidc.rs:394` and `cognito.rs:270` build the same wrong single URL by naive
concatenation that `client/auth.rs:137` did. Fixing one of three leaves a multi-tenant IdP broken in
the other two and leaves two more unvalidated anchors in the tree. `cognito.rs` is additionally worse
than its siblings: it does not even `trim_end_matches('/')`, so a trailing-slash issuer produces a
doubled slash today.

**Scope note:** this plan touches the server-side *identity provider* discovery clients only. It does
NOT touch the MCP resource-server side — no JWT validation change, no `ProxyProvider` change, no
`oauth_passthrough` change. A pmcp server behind a platform gateway is unaffected, which CONTEXT
states as a phase boundary.
Output: two providers on the shared derivation, with the Cognito TTL cache preserved.
</objective>

Apply the same three changes 116-06 made in `src/client/auth.rs`, to `fetch_discovery_doc` in
`src/server/auth/providers/generic_oidc.rs`. Treat `src/client/auth.rs` as the reference
implementation and mirror its structure so the two are reviewable side by side.

1. Replace the single `format!` discovery URL with `discovery_url_candidates(issuer)?` and probe in
   order. Every failure is mapped to a `DiscoveryFailure` and passed through
   `classify_discovery_failure` — `Retry` re-attempts this candidate within the existing retry budget,
   `Fallback` moves to the next candidate, and `Terminal` ABORTS the whole discovery immediately.
   `IssuerMismatch`, `BodyOverCap` and `MalformedSecurityMetadata` are the terminal classes: falling
   through on them would turn a security failure into a silent downgrade. Copy 116-06's loop shape
   exactly, including its comment naming that risk, so the three call sites stay reviewable side by
   side. When all candidates fail, the error must enumerate every candidate tried, not just the last.
   Also build the request through `hardened_discovery_client` so a cross-origin discovery redirect is
   refused here too.
2. After deserializing, compare the document's `issuer` against the issuer used to build the URL with
   `issuer_matches_metadata`, BEFORE the value escapes the function. On mismatch, classify as
   `DiscoveryFailure::IssuerMismatch` (terminal) and return an error naming both. Note this provider
   deserializes into its own `OidcDiscovery` type rather than `OidcDiscoveryMetadata` — read that
   type's `issuer` field, and if it does not have one, add the comparison against the raw parsed JSON
   instead. Do not skip the check because the type is different. A missing or non-string `issuer` is
   `MalformedSecurityMetadata`, also terminal — an absent anchor must not read as "nothing to check".
3. Replace every whole-body read with
   `collect_reqwest_body_within_cap(response, DEFAULT_AUTH_RESPONSE_BYTES)` + `serde_json::from_slice`
   (or a lossy UTF-8 conversion on error-message paths). Error paths count: a hostile IdP controls the
   error body too. After this task,
   `grep -c '\.text()\.await\|\.bytes()\.await\|\.json()\.await\|\.json::<' src/server/auth/providers/generic_oidc.rs`
   must be 0.

anchor check). Record in the summary which providers got one and why.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| network / DNS → provider discovery document | Attacker-influenceable; the document's `issuer`, `jwks_uri` and endpoints feed downstream trust decisions |
| discovery document → Cognito TTL cache | A cached bad document persists a one-shot spoof for the whole TTL |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-116-23 | Spoofing | provider discovery-document issuer | mitigate | RFC 8414 §3.3 comparison before the document escapes the fetch helper, in BOTH providers; each proven by a lying-issuer mockito fixture observed failing pre-fix |
| T-116-24 | Tampering | persistence of a spoofed document in the Cognito TTL cache | mitigate | Anchor-rejected documents are never written to the cache; asserted by a test that a second call re-attempts the fetch |
| T-116-25 | Denial of Service | oversized provider response body | mitigate | All whole-body reads routed through `collect_reqwest_body_within_cap` at 1 MiB; grep count of reqwest needles must be 0 in both files |
| T-116-26 | Denial of Service | multi-tenant IdP unreachable due to wrong discovery URL | mitigate | Shared `discovery_url_candidates` ordered probe; trailing-slash defect closed with an explicit test |
| T-116-26a | Elevation of Privilege | silent downgrade at a provider — a security failure at candidate 1 steering to a candidate the attacker serves | mitigate | Both providers drive the probe loop with `classify_discovery_failure`; `IssuerMismatch`, `BodyOverCap` and `MalformedSecurityMetadata` abort, proven by `expect(0)` on a well-formed candidate 3 |
| T-116-26b | Spoofing | provider discovery following a cross-origin redirect | mitigate | Both providers issue discovery through `hardened_discovery_client`, whose policy refuses any redirect leaving the origin |
| T-116-SC | Tampering | cargo installs | mitigate | Zero packages added |

**Explicitly out of scope, and therefore not in this register:** the MCP resource-server side — JWT
validation, `ProxyProvider`, `oauth_passthrough`. None of the six SEPs pushes work there, and CONTEXT
records that a pmcp server behind a platform gateway is unaffected by this phase.
