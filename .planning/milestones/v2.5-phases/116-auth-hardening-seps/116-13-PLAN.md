<objective>
Converge cargo-pmcp onto core's credential store (D-19) and migrate its on-disk cache from schema 1 to
schema 2 (D-17, cargo-pmcp half), preserving `auth logout` semantics exactly.

Purpose: today a single machine can carry TWO unrelated OAuth caches with different formats and
different semantics — core's flat issuer-less `~/.pmcp/oauth-tokens.json` and cargo-pmcp's multi-entry
`~/.pmcp/oauth-cache.json`. Core now owns the trait and the default file impl; cargo-pmcp drops its
parallel implementation, keeps its own file as the surviving path and the migration source, and its
`auth` subcommands become thin wrappers over exactly the seam a hosting platform would implement.
Unlike core's cache, cargo-pmcp's records an `issuer` per entry — which is what makes a lossless
re-key possible for every entry that has one.
Output: one store, one file, and a version/pin pair that is coherent at publish time.
</objective>

Drop cargo-pmcp's parallel implementation and route every `auth` subcommand through core's store.

**cache.rs.** Remove `TokenCacheV1`, `TokenCacheEntry`, `read`, `write_atomic` and the local
`normalize_cache_key`, and replace the module with thin adapters over
`pmcp::shared::credential_store` and `pmcp::shared::credential_file`. Keep `default_multi_cache_path`
(or its equivalent) resolving `~/.pmcp/oauth-cache.json` — D-19 keeps that FILE and its DATA; it is
the implementation that moves. Do NOT re-implement the migration here: it lives in core's pure
`parse_credential_snapshot` (116-05), used by core's `FileCredentialStore` (116-16), so that a
platform and the CLI cannot diverge.

**The key is three-part.** Every `CredentialKey` this crate builds passes
`(issuer, "", normalize_server_key(server_url))`. The account is empty — the single-user CLI case; do
not invent an identity concept in the CLI, the account scope exists for multi-tenant platform callers.
The SERVER component is what makes `auth logout <url>` mean "this server" rather than "everything from
this authorization server", which is exactly the bug D-116-R1 was raised against.

Carry the surviving crate-local tests across rather than deleting them. `write_sets_0600_perms_on_unix`
and the `normalize_cache_key` idempotence property are the two that must not be lost — the first
because permissions are the file's whole security story, the second because it is the only thing
stopping `https://x/` and `https://x` becoming two logins.

**The five subcommands.** Each becomes a thin wrapper over the traits:
- `login` — `OAuthHelper` with `with_credential_store` / `with_account_scope`; persistence happens in
  core via `save_with_issuer`.
- `token` — `normalize_server_key`, resolve the issuer from `last_issuer`, build the three-part key,
  `load`.
- `status` — `CredentialStoreAdmin::list_keys`, plus a `load` per key for the details it prints today.
- `logout <url>` — `CredentialStoreAdmin::delete_by_server(normalize_server_key(url)?)`, printing the
  returned count; a `0` is the friendly no-op, not an error.
- `logout --all` — `CredentialStoreAdmin::clear_all()`, printing the returned count.
- `refresh` — the core refresh path (116-12), which now survives an omitted `refresh_token` and sends
  only the granted scope.
