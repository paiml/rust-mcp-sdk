<objective>
Close the gap that makes AUTH-01 bypassable, and make discovery follow the spec's ordered probe.

Purpose: RESEARCH Pitfall 1 is the most consequential finding in the phase. AUTH-01 compares the
callback's `iss` against `metadata.issuer` — but `OidcDiscoveryClient::fetch_discovery`
(`src/client/auth.rs:170-197`) fetches, checks status, deserializes and returns with NO comparison
between the document's `issuer` and the issuer used to build the URL. An attacker who can influence
discovery serves a document whose `issuer` is whatever they like, and the RFC 9207 comparison then
trivially succeeds against the attacker's own value. The spec says it in as many words: the `iss`
validation "provides no protection if the expected issuer was obtained from an unvalidated source."
Output: a bounded-read helper, the ordered probe, the §3.3 anchor check, and the RFC 9207 flag seam.
</objective>

**1. Ordered probe (SEP-2351 / D-13, corrected by A3), driven by the outcome matrix.** Replace the
single `format!("{}/.well-known/openid-configuration", issuer_url.trim_end_matches('/'))` at :136-140
with `discovery_url_candidates(issuer_url)?` from the pure tier, and probe the candidates IN ORDER.
This is a fallback ORDER, not a replacement: today's appended form becomes candidate 3 (or 2), and
RESEARCH Pitfall 2 measured that deleting it 404s Microsoft Entra ID, whose URL is in this file's own
doctest at :127. When all candidates fail, the error must enumerate every candidate tried.

**Every failure is classified before it is acted on.** Map the concrete failure to a
`DiscoveryFailure` value and pass it to `classify_discovery_failure` from the pure tier; the returned
`DiscoveryOutcome` decides what happens next, and there is no other branch:
- `Retry` — re-attempt THIS candidate within the existing `while attempts < self.max_retries` budget;
  when the budget is exhausted, treat it as `Fallback`.
- `Fallback` — move to the next candidate, accumulating the error for the final enumerated message.
- `Terminal` — ABORT the whole discovery immediately and return the error. Do NOT try further
  candidates.
The three terminal classes are `IssuerMismatch`, `BodyOverCap` and `MalformedSecurityMetadata`.
Cross-AI review is explicit about why: falling through on "any" failure turns a security failure into
a silent DOWNGRADE — an attacker who can make candidate 1 fail in a security-relevant way steers the
client onto a candidate they can serve. Write a one-line comment at the classification site naming
that, so nobody "simplifies" the match back to `if !ok { continue }`.

**Remember the candidate that worked, per issuer.** A path-bearing issuer such as
`https://login.microsoftonline.com/common/v2.0` pays two 404s before candidate 3 on EVERY probe.
Add a private per-issuer cache on `OidcDiscoveryClient` — a `parking_lot::RwLock<HashMap<String,
usize>>` mapping the issuer string to the index that last succeeded — and, when an entry exists,
attempt that index FIRST. Three constraints, all of them security constraints, and all stated in the
field's doc comment:
- the cache holds an INDEX, never a document, so a poisoned entry cannot supply metadata;
- a cache-hit attempt that fails restarts the FULL ordered sequence from candidate 0 (not from the
  next index), so a stale or hostile entry cannot pin discovery to one path;
- a cache hit runs the SAME anchor validation as a cold probe — the cache short-circuits URL choice,
  never trust.
Clear or overwrite the entry on a successful probe at a different index.

Reframe `test_discovery_url_construction` at :434-461 rather than deleting it: its third case
(`https://auth.example.com/oauth` → appended) is not wrong, it is the LAST candidate. Update it to
assert the ordered list.

changing its signature to accept the expected issuer is free. Note the subtlety the probe introduces:
the value compared against is the ISSUER, not the candidate URL — all candidates for one issuer share

| Boundary | Description |
|----------|-------------|
| network / DNS / hostile `mcp_server_url` → discovery document | Every byte is attacker-influenceable; the document supplies the value AUTH-01 later trusts as its anchor |
| authorization server → response body size | A hostile or compromised IdP controls how many bytes it sends, on success AND error paths |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-116-19 | Spoofing | discovery-document spoofing — forging AUTH-01's own anchor | mitigate | RFC 8414 §3.3 comparison via `issuer_matches_metadata` inside `fetch_discovery`, before the metadata escapes the function; proven by a mockito fixture that LIES about its issuer and was observed failing pre-fix |
| T-116-20 | Denial of Service | memory exhaustion from an oversized discovery/token body | mitigate | Every whole-body read routed through `collect_reqwest_body_within_cap` at 1 MiB, streaming with a running total checked before each append; grep count of reqwest needles in the file must be 0 |
| T-116-21 | Information Disclosure | refusal message echoing refused bytes | mitigate | Helper's refusal names only the limit and observed size; asserted by a test that plants a marker in the oversized body and requires its absence from the message |
| T-116-22 | Denial of Service | discovery regression for ASes serving only the appended form | mitigate | Ordered probe keeps the appended form as a candidate; probe-order tests assert the fallback actually happens |
| T-116-22a | Elevation of Privilege | silent downgrade — a security failure at one candidate steering the client to a candidate the attacker serves | mitigate | `classify_discovery_failure` makes `IssuerMismatch`, `BodyOverCap` and `MalformedSecurityMetadata` TERMINAL; three integration tests put a well-formed candidate 3 behind an `expect(0)` mock so a fall-through would fail the test |
| T-116-22b | Elevation of Privilege | a malformed `authorization_response_iss_parameter_supported` becoming `None` and RELAXING strictness | mitigate | A present-but-non-boolean value aborts discovery as malformed security metadata; the same rule covers a missing or non-string `issuer`, which is AUTH-01's anchor |
| T-116-22c | Spoofing | a discovery redirect leaving the issuer's origin, defeating every upstream issuer check | mitigate | `hardened_discovery_client`'s custom redirect policy refuses any cross-origin or https-to-http redirect and bounds the redirect count; four tests |
| T-116-22d | Tampering | a poisoned or stale candidate-index cache pinning discovery to an attacker-favoured path | mitigate | The cache holds an index only; a failed cache-hit restarts the FULL ordered sequence from candidate 0; a cache hit runs the same anchor validation as a cold probe. Three tests |
| T-116-SC | Tampering | cargo installs | mitigate | Zero packages added; `mockito` is a pre-existing dev-dependency |
