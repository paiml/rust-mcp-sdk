<!-- Facts the prose must be accurate about (VERIFIED against the tree + reviews). -->

Two directions to contrast:
- LLM-server pattern (legacy, kept, NOT deprecated): `Client::create_message` (src/client/mod.rs:1846) sends `sampling/createMessage` TO a server; the server answers via its server-side sampling handler, whose REAL public path is `pmcp::SamplingHandler` (defined src/server/mod.rs:353, re-exported at src/lib.rs:80; also reachable as `pmcp::server::SamplingHandler`). There is NO `pmcp::server::traits::SamplingHandler` — do not write it. Direction: client -> server.
- Spec host sampling (new in phase 106): a server asks the client via `sampling/createMessage`; the client answers via `pmcp::client::host::HostSamplingHandler`, registered with `ClientBuilder::on_sampling(..)`. A `on_sampling_approval(..)` PREFLIGHT hook can deny the request BEFORE the LLM runs (default allow); an optional `on_sampling_result_review(..)` can deny after generation. Also covers `elicitation/create` (`HostElicitationHandler` via `on_elicitation`) and `roots/list` (`on_roots`). Direction: server -> client. Limitation to mention: today the client answers these only while one of its own requests is in flight (nested flow); a pure idle host needs a background receive loop, deferred.

Book conventions: Chapter 17 pages are short (e.g. ch17-03-sampling-tools.md). SUMMARY.md lists Chapter 17 sub-pages under "- [Chapter 17: Complete Examples](ch17-examples.md)" (~line 53) with two-space-indented `  - [Title](file.md)` entries; the last existing sub-entry is "  - [Tool with Sampling](ch17-03-sampling-tools.md)" (~line 56).
