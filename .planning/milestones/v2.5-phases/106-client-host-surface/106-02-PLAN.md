Layer the human-in-the-loop approval hook (HOST-04) and capability derivation (HOST-05) onto the host dispatch built in plan 01, fuzz the actual routing path, and execute the phase-end pmcp 2.15.0 -> 2.16.0 minor bump.

Per the cross-AI review (`106-REVIEWS.md` consensus), approval is redesigned: **preflight approval is the mandatory gate** — it receives OWNED (cloned) `CreateMessageParams` and runs BEFORE the handler, so a denial prevents the LLM call entirely (fixes T-106-05 for real and closes the denial-of-wallet hole). Capability derivation keeps the locked registry-authoritative anti-lie rule (handler absent => field None) while preserving caller-configured sub-capability detail when a handler IS registered. The fuzz target drives `parse_request -> classify_host_request` (real routing) instead of standalone serde. All verify commands drop the failure-masking `| tail` pipes.

| Boundary | Description |
|----------|-------------|
| server -> client (inbound sampling) | A server can push sampling requests that drive the host's LLM and bill its account. Preflight approval is the gate before the LLM call. |
| server -> client (malformed params) | Server-controlled JSON is parsed and classified before dispatch. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-106-05 | Elevation of Privilege / Denial of Wallet | server coerces client into an unapproved/billed LLM call | mitigate | PREFLIGHT approval runs BEFORE the handler (Task 1); Deny prevents the LLM call entirely — no tokens billed. Unit test proves the handler is not invoked on Deny; duplex test proves the connection survives. |
| T-106-06 | Spoofing/Repudiation | client advertises a host capability with no handler (caller-set) | mitigate | HOST-05 forces the field to None when the handler is absent (Task 2, locked anti-lie); caller sub-capability detail preserved only when a handler is present. |
| T-106-07 | Denial of Service | malformed inbound params / routing panic or hang | mitigate | Routing fuzz drives parse_request -> classify_host_request + param serde (Task 3); typed deserialization, no panic. |
| T-106-08 | Denial of Service | denial tears down the connection | mitigate | Deny returns a JSONRPCResponse::error (not Err); receive loop continues — duplex denial test proves a subsequent request completes. |
| T-106-11 | Information Disclosure | deny reason leaks local host policy to the remote server | mitigate | Deny returns a generic "request denied by host policy" message; the callback's reason is logged locally via tracing::warn!, not forwarded. |
| T-106-SC | Tampering | npm/pip/cargo installs | accept | No packages installed — additive code within existing pmcp + fuzz + cargo-pmcp crates (RESEARCH Package Legitimacy Audit: N/A). |
