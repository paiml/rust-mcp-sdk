<objective>
Sever the CLIENT half of the v1 session lifecycle and SSE resumability, so `full-v2` proves the whole
of SMPL-01/SMPL-02 rather than its server half.

Purpose: plans 117-06 / 117-09 / 117-12 / 117-13 isolate the SERVER's session state, event store and
replay path. The client transport still carries the mirror image of all of it. Measured on the
current tree, `src/shared/streamable_http.rs` (2,677 lines) holds `SendOptions::resumption_token`
(`:52`), `StreamableHttpTransportConfig::session_id` (`:107`) and `::on_resumption_token` (`:111`),
their builder fields and setters (`:162-164`, `:192-194`, `:212-213`, `:224-225`), their two `Debug`
impls (`:122-124`, `:174-176`), the `Last-Event-ID` request-header writer (`:636-647`), the
`session_id()` / `set_session_id()` accessors (`:582-588`), the `Mcp-Session-Id` capture (`:946`) and
the DELETE session-teardown block (`:1412-1428`) — 55 matching sites in one file. None of it is
gated by any other plan in this phase.

SMPL-01's wording is "v1-only machinery (initialize/session lifecycle, SSE resumability) is isolated
behind a clearly severable era-gated layer", with no server-only qualifier, and SMPL-02's is "the v2
code path carries no session/SSE-resumability baggage". A green `full-v2` build that compiles all of
the above satisfies neither as written.

Output: a client transport whose v1 session and resumability surface vanishes on `full-v2`, a derived
inventory tripwire, and a runtime proof on the severed build.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| MCP server → client transport | `Mcp-Session-Id` and resumption tokens are server-controlled inputs the client stores and echoes |
| client transport → network | A DELETE on close is a request the severed build must not make at all |
| public client API → downstream crates | Gating public fields and methods changes the API under `full-v2` |
| documentation → user expectation | A sunset policy claiming full severance while the client still carries session state misleads a 3.0 migration |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-117-51 | Repudiation | the SMPL-01/02 severance claim | mitigate | SMPL-01 names "initialize/session lifecycle" with no server-only qualifier. This plan closes the client half; anything that cannot be severed is recorded as a NAMED limitation that plan 117-13's policy must carry, so the claim can never exceed the code |
| T-117-52 | Information Disclosure | client-stored `Mcp-Session-Id` | mitigate | The stored session id, its accessors and its capture site are gated, so the `full-v2` client holds no session identifier to echo.
