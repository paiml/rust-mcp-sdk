## Why Task 3 is a SEMANTIC check and NOT a substring blacklist — MEASURED, do not "simplify"

An earlier draft of this plan forbade the substrings `sessions`, `sse_streams`, `event_store`,
`EventStore`, `HashMap`, `RwLock`, `Last-Event-ID`, `LAST_EVENT_ID` in `v1_session_off.rs`. FOUR of
those eight are mechanically impossible, because plans 117-09 / 117-12 / 117-13 require the null twin
to carry signatures that are TEXTUALLY IDENTICAL to their real counterparts. Measured against
`src/server/streamable_http_server.rs`:

| Forbidden substring | Required identifier that contains it | Required by | Source |
|---|---|---|---|
| `sessions` | `sessions_active_for`, `sessions_active`, and the `sessions_on: bool` parameter of `apply_session_header` | 117-09 Task 2 | `:416`, `:433`, `:463` |
| `event_store` | the parameter names `cfg_has_event_store` (`resumability_active_for`) and `event_store` (`replay_sse_events_from_header`, `sse_event_for_message`) | 117-09 Task 2, 117-12 Task 2 | `:523`, `:4377`, `:4408` |
| `EventStore` | `EventStoreHandle` in the return type `Option<&EventStoreHandle>` and in two parameter types | 117-09 Task 2, 117-12 Task 2 | `:509`, `:558`, `:4377`, `:4408` |
| `sse_streams` | the surviving `build_response` read at `:1936` must reach v1 state through the pair on BOTH feature sets | 117-09 Task 1 | `:1936` |

`HashMap`, `RwLock`, `LAST_EVENT_ID` and `Last-Event-ID` have NO such collision and stay forbidden.

The invariant SMPL-02 actually needs is not "these words are absent" — it is "no state is held and no
state or header is touched". That is what Task 3 asserts. **Do not restore a substring blacklist**:
it would make Wave 3 unlandable behind a Wave 2 tripwire, which is exactly the defect this revision
removes.
