<objective>
The tracer: prove the whole attestation carriage path end-to-end on one thin slice before expanding it. Attestation bytes attach at `pack_server`, travel as an OPAQUE layer whose metadata rides in the layer descriptor's annotations, come back out of `unpack_server` byte-identical, and are rendered by `cargo pmcp package inspect` — all offline, all from a fixture.

This is the phase's architectural risk in one commit: if the optional-layer-plus-annotation shape is wrong (wrong annotation scope, wrong media type spelling, a digest that cannot be compared), it is wrong here, after one task, not after four plans of layered work.

Purpose: land D-01 (6th optional positional parameter), D-04 (metadata in descriptor annotations), D-05 (suffix-free media type) and D-14 (absence is the layer's absence) as one mechanism, and pin D-01's accepted two-digest consequence with a test rather than leaving it as a side effect.
Output: one new media type, three annotation-key constants, one new pack-side type and helper, one new unpack-side type and field, attestation rendering in `inspect`, and every `pack_server` call site in the repo updated.
</objective>

This overrides the literal string written in `122-CONTEXT.md` D-05 and `122-RESEARCH.md`; the DECISION D-05 records — suffix-free, because the attestation format is platform-owned and expected to churn — is honored unchanged and is in fact what drives the kind-neutral spelling too. Write the following four reasons into the constant's rustdoc so the next reader meets them at the constant rather than reconstructing them:

1. Two carrier kinds exist in this same phase. D-08 puts attestation carriage on `pack_server` AND `pack_team`, so a `mcp-server`-namespaced media type would make a team package carry a layer whose type says `mcp-server` — a claim that is simply false on disk. The kind qualifier was already wrong at the moment it was written.
2. Kind-specificity elsewhere in this file tracks a kind-specific PAYLOAD. `MT_TEAM_CONFIG`'s bytes ARE a `TeamPackage`; `MT_SERVER_ENVELOPE`'s bytes ARE server envelope fields. An attestation payload is platform-owned opaque bytes whose shape does not vary with the carrying kind, so a kind qualifier here would be false precision rather than the existing convention.
3. D-05's own reasoning generalizes. A suffix was omitted so that a format change would not become a media-type change, and a media-type change is a wire break for every already-published CLI. A kind qualifier has the identical failure mode one axis over: adding the second carrier kind would force either a second constant or a lie. One neutral spelling avoids both.

## Decision record — the attestation media-type noun (settled during reviews-mode replanning)

**Trigger.** Cross-AI review (`122-REVIEWS.md`) raised, and the Consensus Summary verified, the one finding both reviewers touched: this plan defined a `mcp-server`-namespaced attestation media type while 122-07 reuses the same constant for `TeamPackage`. Independently, the phase's assumption-delta check flagged a `pluralization` signal — this phase turns one attestation carrier kind into two — and asked whether the media-type identity model still names the right noun.

**Answer: it did not.** The noun that is now primary is `attestation`, unqualified by carrier kind.

- **Decision: `promote`.** The noun moves up a level, from `pmcp.mcp-server.attestation` to `pmcp.attestation`.
- **Constant:** `MT_ATTESTATION`.
- **Wire string:** `application/vnd.pmcp.attestation.v1`.
- **Rationale (one line):** an attestation is a claim ABOUT a package rather than a part OF one kind of package, and the second carrier kind arrives in this same phase — so the kind qualifier was already false when it was written, and removing it keeps one constant, one read helper and zero kind dispatch.
- **Rejected:** `MT_SERVER_ATTESTATION` + `MT_TEAM_ATTESTATION` with a shared annotation vocabulary — buys nothing over `artifactType`, costs a kind-keyed lookup at every read site.
- **Supersedes:** the literal string in `122-CONTEXT.md` D-05 and its restatements in `122-RESEARCH.md` (lines 74, 391, 435, 548, 867, 877) and `122-PATTERNS.md` (line 661). D-05's actual DECISION — suffix-free, because the format is platform-owned and expected to churn — is honored unchanged and is the same reasoning applied one axis over.
- **Frozen by:** this plan's tracer, which writes the string to disk. Downstream plans 122-03, 122-06 and 122-07 have been updated to the new name in the same replan.
