## Measured cargo output shapes — the evidence the guard design rests on

A three-binary probe crate was built and run at plan time (cargo 1.98.0, `--test-threads=1`). These
are the observed lines, not assumptions:

| Binary shape | `Running` line | `running N tests` | `test result:` |
|---|---|---|---|
| single `#[test]` (real) | `     Running tests/real_suite.rs (target/debug/deps/real_suite-<hash>)` | `running 1 test` | `test result: ok. 1 passed; 0 failed; 0 ignored; ...` |
| single `#[test] #[ignore]` | `     Running tests/all_ignored.rs (...)` | **`running 1 test`** | **`test result: ok. 0 passed; 0 failed; 1 ignored; ...`** |
| `#![cfg(any())]` — compiles to nothing | `     Running tests/cfg_empty.rs (...)` | `running 0 tests` | `test result: ok. 0 passed; 0 failed; 0 ignored; ...` |
| lib unit tests | `     Running unittests src/lib.rs (...)` | `running 0 tests` | `test result: ok. 0 passed; ...` |
| doctest trailer | *(no `Running tests/...` line at all)* | `running 0 tests` | `test result: ok. 0 passed; ...` |

Four design consequences follow directly, and each is load-bearing:

1. **The `Running` line proves nothing about execution.** It prints for all four executed shapes,
   including the two that run zero tests. This is CR-02 point 1.
2. **`running N tests` is the WRONG field to gate on.** The all-`#[ignore]` case prints
   `running 1 test` — a nonzero-`running` check passes it. Only `test result:`'s **passed** count
   (field 4) reports 0 there. `scripts/run-era-matrix.sh` gates on `running [1-9]`, which is correct
   for ITS failure mode (a `#![cfg]`-emptied file) but would NOT catch an `#[ignore]` sweep. This
   guard must use field 4 of `test result:`, matching the idiom the existing summed count guard at
   `Makefile:337` already uses.
3. **Anchoring must be structural, not substring.** Under awk's default field splitting the cargo
   line is `$1 == "Running"`, `$2 == "tests/<name>.rs"`, `$3` = the binary path in parens. A rustc
   diagnostic for the same file is `  --> tests/<name>.rs:12:5`, whose `$1` is `-->`. `unittests
   src/lib.rs` has `$2 == "unittests"`. So a two-field equality test discriminates all of them
   without any regex escaping — and `tests/<name>.rs` contains `.` characters that a regex would
   treat as wildcards, which is a live escaping hazard a field test avoids entirely.
4. **The doctest trailer emits a bare `test result:` with no preceding `Running tests/...` line.**
   The extractor must stop at the FIRST `test result:` after its match, or a later block can be
   mis-attributed.

## Why the extractor lives in `scripts/`, not inline in the Makefile

CR-02's root cause is a guard that shipped with no proof of its own sensitivity, and nothing that
re-proves it. Fixing only the pattern repeats the shape one level up.

Putting the awk program in `scripts/named-test-binary-count.awk` and having BOTH the gate and a
self-test consume it via `awk -f` gives three things an inline program cannot:

- The self-test exercises the *same bytes* the gate runs, so a green self-test is evidence about the
  gate rather than about a copy of it.
- No `$$` escaping. A Makefile recipe would need `$$1`/`$$2`/`$$4` for every awk field reference,
  and every one is a chance to write a silently-wrong program.
- It matches this repo's own precedent: `scripts/run-era-matrix.sh` holds gate logic in a script for
  exactly these reasons, and `scripts/check-release-coverage.sh` does the same.

## Extractor contract

`awk -v want="tests/<name>.rs" -f scripts/named-test-binary-count.awk <captured-output>` prints
exactly one integer:

| Output | Meaning |
|---|---|
| `N` >= 1 | the named binary ran and passed N tests |
| `0` | the named binary ran and passed ZERO tests — the CR-02 failure |
| `-1` | no `Running <want>` line was found — the binary never ran at all |
| `-2` | a `Running <want>` line was found but no `test result:` line followed it — truncated output or an aborted harness |

`-2` exists because the obvious spelling of this extractor prints NOTHING in that case, and an empty
string flows into a shell numeric comparison as `[: : integer expression expected` — which returns a
non-zero status that an `if` treats as false, so the guard would pass vacuously in exactly the
scenario where the output is untrustworthy. A gate that cannot see must say so, never pass.
