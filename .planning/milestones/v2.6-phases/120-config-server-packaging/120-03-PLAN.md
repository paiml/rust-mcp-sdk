## Planner resolution

- **PR-03 — `ConfigSlot` gains `config_key: Option<String>`.** D-01 declares slots by the
  config KEY they fill and D-04 validates "the key named by a `[[config_slots]]` entry", but
  `ConfigSlot { slot: SlotType }` carries only a slot NAME (for `Secret` that is an env-var
  name like `TFL_APP_KEY`, not the TOML path `backend.auth.query_params.app_key`). Without
  the key, D-04's validation is unimplementable and `required_slots` cannot tell a target
  environment WHERE to put the value. Adding
  `#[serde(default, skip_serializing_if = "Option::is_none")] pub config_key: Option<String>`
  lands inside the same 0.2.0 break and — because of `skip_serializing_if` — leaves the four
  existing golden digests byte-identical.

  **PR-03 correction (Codex HIGH, incorporated).** The first version of this resolution called
  the change "strictly additive". That is true on ONE axis and false on the other, and the
  distinction is load-bearing:
  - **Serde / wire: additive.** `#[serde(default)]` means old slot JSON with no `config_key`
    still deserializes; `skip_serializing_if` means nothing new is emitted, so no fixture byte
    and no pinned digest moves.
  - **Rust source: BREAKING.** `ConfigSlot` has exactly one field today
    (`slot/types.rs:105-107`). A second public field invalidates every struct literal in the
    language, everywhere. Measured this session: 43 construction sites across `pmcp-package`
    (including `src/oci/unpack.rs`, `src/package/{team,workflow,agent}.rs`, and the
    `tests/{roundtrip,negative,digest_stability}.rs` fixtures), `pmcp-agent`,
    `pmcp-team-servers`, `cargo-pmcp`, plus examples and integration tests in each. The
    original plan scoped Task 2's edits to "every in-crate literal" while its phase gate is
    `make quality-gate`, which builds the ROOT workspace — so the plan as written guaranteed a
    workspace-wide compilation failure. Task 2 and `files_modified` now cover all 43.
