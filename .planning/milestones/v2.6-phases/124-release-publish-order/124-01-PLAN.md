Step A — extend `scripts/check-release-coverage.sh` in place. Do not rewrite the file and do
not restructure the existing root-member loop. Insert a second discovery loop AFTER the

**Step A1 — the discovery loop.** It:

  - iterates `for m in "$CRATES_DIR"/*/Cargo.toml`, skips non-files, and skips any manifest
    that does not carry its own `[workspace]` table. `CRATES_DIR` defaults to `crates` and is
    overridable from the environment purely so Task 3's self-test can point discovery at a
    synthetic tree; it is never a list of crates. Match the table header
    whitespace-tolerantly — `^[[:space:]]*\[[[:space:]]*workspace[[:space:]]*\]` — because
    that spelling is valid TOML even though no in-tree manifest currently uses it. That
    regex plus the `.publish == null` classification below is the whole of the discovery
    rule (D-01). There is no list of names and no list of paths.
  - increments a counter `excluded_seen` for every manifest that passes the discovery test.
  - classifies via `cargo metadata --no-deps --format-version 1 --manifest-path "$m"` into
    `EX_META`, then `jq -r '.packages[] | select(.publish == null) | .name'` into `EX_NAME`.
    Each of those two invocations gets its own explicit failure arm in the same shape as the
    existing arms at :35-45 — a `::error::` line naming the manifest and stating that
    coverage was NOT checked, then `exit 1`. Reuse the `.publish == null` predicate exactly:
    it is the same rule the root half uses, so a filesystem heuristic can never disagree with
    Cargo about what "publishable" means. (Measured: `crates/pmcp-package/Cargo.toml:20` says
    `publish = true` and Cargo reports `publish=null` for it, so the predicate transfers.)
  - `continue`s when `EX_NAME` is empty (a publish-restricted crate is correctly not this
    gate's problem).
  - increments the shared `total`, then matches with a here-string against `$PUBLISH_LINES`
    — never a pipe into `grep -q`, for the SIGPIPE reason documented at :65-72. The matcher
    is the `--manifest-path` form, not the `-p <name>` form: the crate NAME never appears in
    that command. Search for `cargo publish --manifest-path ${m}` with a trailing-space
    boundary, deriving `${m}` from the loop variable so the scan and the matcher cannot
    disagree about the path spelling (Pitfall 3). A miss appends to the shared
    `missing_list` with a message that names `EX_NAME` and states that the crate is
    workspace-excluded and needs a `--manifest-path` step.

**Step A2 — close D-01's scan-scope hole by declaring the three qualifying manifests.**
D-01's stated rule is "a manifest carrying its own `[workspace]` table without
`publish = false`", but a `crates/*/Cargo.toml` glob is narrower than that rule. Measured at
replan across the whole repository (`git ls-files` + `grep -lE '^\[workspace\]'`): **32
manifests carry their own `[workspace]` table, and exactly 5 of them do NOT declare
`publish = false`** — the root `Cargo.toml` itself, `crates/pmcp-package/Cargo.toml` (the
target), and three others that match the rule while lying outside the glob:

  - `deploy/cloudflare/Cargo.toml` (`mcp-server-cloudflare-adapter` 0.1.0)
  - `examples/wasm-mcp-server/Cargo.toml` (`mcp-cloudflare-worker` 0.1.0)
  - `examples/wasm-mcp-server/deployments/fermyon-spin/Cargo.toml` (`mcp-fermyon-spin` 0.1.0)

Left as-is, the gate would print full excluded-crate coverage while three qualifying
manifests stayed invisible — precisely the `pmcp-tasks` shape the script header cites as the
reason the gate exists.

Resolve it by **declaring, not by widening**: add `publish = false` to each of the three
`[package]` tables. That uses the script's OWN single documented opt-out (`:11-12`: "A crate
that should NOT publish declares `publish = false` in its Cargo.toml. That is the single
opt-out"), turns three accidental invisibilities into three deliberate declarations, and
leaves the scan honest. Change nothing else in those manifests.

Do NOT instead widen the glob to the whole repository. Measured: that pulls in the root
`Cargo.toml` (which would self-match and re-enumerate all 24 root members through a second
path), 18 gitignored-or-untracked spike copies under `.agents/`, `.claude/` and

manifests — making the gate's behaviour depend on which untracked directories a given
developer happens to have. None of those are release candidates.

**Step A3 — add the scan-scope tripwire, which is what stops the narrow glob from BEING the
allowlist.** After the discovery loop, assert repo-wide that nothing qualifying lies outside
the scanned directory: enumerate TRACKED manifests only (`git ls-files '*Cargo.toml'` — tracked,
so the check is identical for every developer and in CI), select those carrying a
`[workspace]` table, drop the root manifest and anything already under `$CRATES_DIR`, and
fail explicitly with a `::error::` naming each offender when any of the survivors lacks
`publish = false`. The message must say what to do: either declare `publish = false`, or move
the crate under `crates/`. Give the `git ls-files` invocation its own explicit failure arm in
the same shape as the existing `cargo metadata` / `jq` arms, and skip the tripwire with a
stated notice (not a silent pass) when `git` is unavailable or the tree is not a work tree —
the self-test runs the script against synthetic trees.

This is the assertion that makes the scan's narrow scope a CHECKED, DECLARED scope rather
than an implicit allowlist. The scope choice itself is recorded in the script header by
