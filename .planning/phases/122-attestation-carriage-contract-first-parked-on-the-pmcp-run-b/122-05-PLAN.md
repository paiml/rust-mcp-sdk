<objective>
Land the bounded format addition this phase carries, and the guard helper the team-side pack gate will use.

D-10: follow Cargo's model, explicitly because that logic is proven and will pass the same security reviews. Cargo keeps two artifacts — `Cargo.toml` holds the range (author intent, enabling reuse and upgrade), `Cargo.lock` holds the resolution (exact version plus checksum). Pinning never destroys the range. Today `ComponentRef` is either/or, so pinning discards the declared range and prod cannot distinguish "dev declared `^1.2` and resolved 1.3.0" from "dev declared `=1.2.0`" — and in the first case prod's existing 1.2.0 still satisfies the range and gets silently kept, which is the wrong reference. `resolved_from` closes that.

D-09 (helper half): `WorkflowManifest` is currently the ONLY package kind carrying `pinned_components()` / `validate_all_pinned()`. `TeamPackage` needs the same guard so plan 122-07 can refuse an attestation over an unresolved team. Generalize the existing helper's shape and error wording; do not invent a second one.

Purpose: land the two fan-out changes — a public struct field and a public method pair — on their own, before the pack-side wiring in 122-07 depends on them.
Output: one additive serialized field with its compatibility reasoning written down, one guard method pair on `TeamPackage`, and a measured proof that the golden fixtures do not move.
</objective>
