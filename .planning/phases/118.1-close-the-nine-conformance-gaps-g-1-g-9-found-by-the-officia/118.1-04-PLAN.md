<objective>
Close G-4: give `completion/complete` a real handler seam on BOTH native dispatchers and make it
answer the spec `CompleteResult` shape, instead of falling into a catch-all that returns
`json!({})` on `Server` and `METHOD_NOT_FOUND` on `ServerCore`.

Purpose: the suite's `completion-complete` scenario fails with `Missing completion field` because
`result.completion.values` is not an array. The endpoint never consults a tool — it needs its own
registered slot. The two dispatchers already DISAGREE on this method, which is a pre-existing defect
the gaps doc does not record.

Output: a builder registration slot, a dispatch arm in both dispatchers, and
`tests/completion_complete.rs` asserting the shape per dispatcher.
</objective>

`CompleteResult extends Result { completion: { values: string[] /* maxItems 100 */; total?: number; hasMore?: boolean } }`.

`{ref:{type:"ref/prompt",name:"test_prompt_with_arguments"}, argument:{name:"arg1",value:"test"}}`
and fails with `Missing completion field` unless `result.completion.values` is an array. Its own
comment says "For conformance testing, completion support can be minimal or return empty arrays" —
so an empty `values: []` PASSES.

Types that already exist and must be reused, never re-declared:
- `CompleteRequest { r#ref: CompletionReference, argument: CompletionArgument }` — `src/types/protocol/mod.rs:403-408`

The two catch-all arms this plan splits:
- `src/server/mod.rs:1897-1901` — `ClientRequest::Subscribe(_) | Unsubscribe(_) | Complete(_) | SetLoggingLevel{..} | Ping => Ok(serde_json::json!({}))`
- `src/server/core.rs:3909-3913` — the `_ =>` arm returning `METHOD_NOT_FOUND` with `"Method not supported"`

THERE ARE TWO BUILDER FAMILIES AND THIS PLAN TOUCHES BOTH. Do not conflate them:

- `src/server/builder.rs` defines **`ServerCoreBuilder`** (`pub struct ServerCoreBuilder` at
  `src/server/builder.rs:66`, `impl` at `:147`). Its `resources` method is at
  `src/server/builder.rs:327-339` and `resources_arc` at `:345`. It builds `ServerCore`
  (`src/server/core.rs`), whose completion arm sits before the `_ =>` `METHOD_NOT_FOUND` catch-all
  at `src/server/core.rs:3909-3913`.
- `src/server/mod.rs` defines the high-level **`ServerBuilder`** (`pub struct ServerBuilder` at
  `src/server/mod.rs:2861`, behind `#[cfg(not(target_arch = "wasm32"))]`), whose fields include
  `resources: Option<Arc<dyn ResourceHandler>>`. It builds `Server`, whose catch-all arm is at
  `src/server/mod.rs:1897-1901`.

Registration pattern for a SINGLE, non-keyed handler: the `resources` slot — one
`Option<Arc<dyn …>>` field plus a capability flip — as it appears in BOTH families
(`ServerCoreBuilder::resources` at `src/server/builder.rs:327-339`, and the `resources` field on
`ServerBuilder` at `src/server/mod.rs:2861+` with its setter). NOT the name-keyed `prompt` shape.

G-4 is only closed when a completion provider registered through EITHER family reaches its own
dispatcher. A slot on one family and a dispatch arm on the other's server is an unreachable seam.
