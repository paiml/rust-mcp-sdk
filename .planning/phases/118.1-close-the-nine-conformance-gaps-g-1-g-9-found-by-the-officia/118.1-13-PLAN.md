- `2026-07-28`: 124 passed, 54 failed, exit 1, 7 scored scenarios failing, 178 total checks

Reproducibility rules, both non-negotiable:
- `conformance -o <dir>` ACCUMULATES timestamped scenario directories. A second run into a populated
  tree DOUBLES every disk-computed count. `scripts/run-conformance-suite.sh:500` does
  `rm -rf "$RESULTS_ROOT"` at fence 10; an ad-hoc run must do it by hand.
- D-19: no verification command may mask the exit code of the thing it verifies. Use
  `bash -o pipefail -c '... 2>&1 | tee LOG'` and assert the exit code in a separate statement.
  Never pipe to `tail`.
- Node 22 is required (`conformance/package.json` declares `engines.node >= 22`); the local default is
  v20.8.1, so `nvm use 22` first. CI installs Node 22 explicitly.
- `RESULTS_ROOT="target/conformance-results"` (`scripts/run-conformance-suite.sh:204`).

Per-leg check counts are computed from disk by the script's own method: one `checks.json` per scenario
directory under `target/conformance-results/LABEL/`, counting `SUCCESS` and `FAILURE`.

The nine gaps and their owning plans and artifacts:
- G-1 nesting, G-2 blob — plan 03, `binary(embedded_resource_golden)`

- G-7 supportedVersions — plan 07, `binary(v2_discover_supported_versions)`
- G-9 v1 capabilities — plan 08, `binary(v1_handler_client_capabilities)`
- G-3 v1 half — plans 10 and 11, `binary(http_peer_roundtrip)` and `binary(era_matrix)`

  D-07 `PeerHandle::elicit` — plan 09, `binary(in_tool_peer_roundtrip)` and `binary(http_peer_roundtrip)`
