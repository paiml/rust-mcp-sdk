<objective>
Build the server-to-client channel the StreamableHTTP transport does not have: own a
`ServerRequestDispatcher` on `ServerState` (outside `Mutex<Server>`), drain its outbound requests
into the originating session's SSE stream, and route an inbound JSON-RPC response POST to it BEFORE
any code takes the server mutex.

Purpose: this is not a wiring change. `dispatch_request_or_retire` holds
`state.server.lock().await` for the ENTIRE duration of the tool handler, so a handler awaiting
`peer.sample()` holds it while waiting for the client's answer — and that answer arrives as a POST
whose first three stages (`resolve_v2_gate` taking the lock twice, then `extract_and_validate_auth`
taking it again) all block on the same mutex. That is a guaranteed deadlock, and it is also a
denial-of-service control: one malicious tool call would otherwise take the whole transport offline.

Output: a new `peer_channel` submodule, the early inbound classification on BOTH entrypoints, and a
timeout-bounded fence whose most important test is the concurrency guard.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| unauthenticated POST to the pre-gate classifier | Response classification now runs BEFORE `resolve_v2_gate` and `extract_and_validate_auth`, on fully untrusted input |
| session A's SSE stream vs session B's | Server-to-client requests are routed by session id; a misbinding delivers one client's `sampling/createMessage` to another |
| client-supplied correlation id to `ServerRequestDispatcher::handle_response` | A forged id could resolve a pending request the client never received |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-118.1-10-01 | Denial of Service | Deadlock as DoS — one parked handler holding `Mutex<Server>` stalls EVERY request on the transport | mitigate | Inbound responses are classified and routed before all three lock sites; the concurrency guard test is the executable proof and the verify command fails on any timeout language |
