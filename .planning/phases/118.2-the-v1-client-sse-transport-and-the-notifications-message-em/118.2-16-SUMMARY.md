### The two plan-file process defects (handoffs 2 and 4, absorbed)

A separate sub-section, `### Process defects this closure surfaced`, because these are defects in the
closure's own **plan files**, not in the reviewed source. Both are already booked as OPEN deviations
`10` and `11` in `.planning/WINDOWS.md` (which this plan did not edit), and neither plan file was
edited, by design.

1. **The pmat jq path is wrong for pmat 3.15.0.** `118.2-15-PLAN.md:391` and `118.2-17-PLAN.md:341`
   both specify `jq -e '[.violations[] | select(.path | startswith("src/"))] | length == 0'`. The
   top-level keys on 3.15.0 are exactly `["files", "summary", "top_files_limit"]`; there is no
   top-level `.violations`, and violation records key the path as `.file` with a `./` prefix. The
   command emits `Cannot iterate over null` and exits **5** — it fails CLOSED rather than
   false-greening, but it measures nothing. The verified-correct form
   (`[.summary.violations[] | select(.file | startswith("./src/"))]`) is recorded, as is the related
   genuine false green: `--files <path>` exits 0 while reporting `total_files: 1, total_functions: 0`.
2. **`--max-cognitive 25` in a plan verify is LOOSER than the CI gate it claims to predict.** Recorded
   as a plan-template defect that will recur wherever the spelling is copied. The **direction** is
   recorded as measured fact — plan 17 found `read_sse_body` at exactly 25, which passes
   `pmat analyze complexity --max-cognitive 25` and fails
   `pmat quality-gate --fail-on-violation --checks complexity`, the command CLAUDE.md names as
   PR-blocking — and plan 17 resolved its instance by **extracting** `end_of_frame_stop`, not by an
   `#[allow]`. The specific threshold **23** is marked **UNCONFIRMED** in the record, because pmat
   3.15.0's help output documents only `--max-complexity-p99` (default 50) and complexity-entropy
   (default 2.0) and lists no cognitive default. The record says: run the gate, not the report.
