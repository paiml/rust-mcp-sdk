## Two Behaviour Changes Disclosed at Full Severity, Not Softened

Entry 20 states the mismatch ceiling's blast radius **wider** than "wedged → bounded", because that is
what plan 20's own adversarial self-check measured and the plan text under-stated:

> The deadline is armed on the **first** mismatch and **stays armed for the life of that call**. So a peer
> that emits one stray frame at t=0 and then answers **correctly** at t=15 s previously **SUCCEEDED** and
> now **FAILS** at 10 s.

That is a **new failure mode for a previously-working slow-but-correct peer**, not merely a bound on a
hang. It is the mechanism the design requires — arming on the first mismatch is what makes the ceiling
un-extendable by a peer emitting a steady drip of wrong ids — but a downstream consumer with a slow and
slightly lenient peer will observe it. Recorded at that severity.

Entry 19 likewise records that a consumer relying on `receive()`'s immediate (stale) latched answer now
sees a **wait**, and that the rendered **text** of every terminal reason gains a stream-name prefix —
a user-visible message change. Every message **body** is preserved verbatim, so substring matchers still
match; whole-string matchers and log consumers see different text.

Neither change produces a semver event: every symbol is private, which the verdict below confirms. These
ledger entries are therefore the only place a consumer learns of them.

## Two Properties Neither Wave Recorded

**`binary(client_sse_stream)` is LOAD-SENSITIVE**, measured independently by the orchestrator: at full
parallelism on a loaded machine a **different** set of fences times out at ~27 s on each run (two
different failing pairs on two consecutive runs of identical source); at `--test-threads 4`, **24 run,

`--test-threads=1`. Recorded in `deferred-items.md` with the convention to quote the thread count
wherever the count is quoted, which this summary does.

### [Rule 3 — Blocking, tooling] `rtk` rewrites `grep` and `git diff` output, so every scripted count was wrong

- **Found during:** Task 1, and again in Task 3's provenance assertions.
- **Issue:** a shell hook rewrites bare `grep` to `rtk grep`, which prints `N matches in 1F:` plus
  match context instead of a bare integer, and rewrites `git diff --stat` output into its own
  `--- Changes ---` formatting. Every `test "$(grep -c …)" -eq 0` and every `git diff … | wc -l`
  assertion in this plan would have measured the wrapper's prose, not the file. Two `wc -l` results
  came back as **1** for genuinely **empty** diffs before this was caught.
- **Fix:** all scripted assertions use absolute binary paths — `/usr/bin/grep`, `/usr/bin/sed`,
  `/usr/bin/wc`, and `/opt/homebrew/bin/git` — which bypass the rewrite. Every count in this summary was
  taken that way. Recorded because it is a general hazard for any plan in this repository whose verify
  blocks parse tool output.
