# Phase 118.2 Plan 17: Stop parked readers and un-share the reconnect cursor (WR-01, WR-02) Summary

**Both defects are closed.** A pmcp transport that is dropped, or explicitly closed, now leaves no
live reader and no live socket behind — at the GET session-stream site AND at the detached
POST-response site — even against a peer that holds the stream open and sends nothing at all. And a
session-stream reconnect now resumes from the id **that session stream** delivered, never from one
minted on a streaming POST response.

Three fences pin it, all three RED-proven against the tree that shipped the defects, and the fence
whose crutch hid WR-01 no longer has it.

## What WR-01 actually was, measured

The phase's stated termination contract had three signals, and a single ordinary peer shape defeats
all three at once:

| Signal | What it needs | Why an idle-but-open stream defeats it |
|---|---|---|
| a failing `sender.send(..)` | a frame to send | the peer sends only SSE keep-alive comments, which the shared parser drops without producing an event |
| `is_closed()` before/after the backoff sleep | the loop to REACH the sleep | the reader is parked in `body.frame()` and never gets there |
| `close()`'s `abort_handle.abort()` | the reader to be THAT `JoinHandle` | every streaming POST spawns a DETACHED reader (`drop(spawn_sse_reader(..))`) with no bound on how many exist |

`abort_handle` holds a `JoinHandle`, and dropping a `JoinHandle` in tokio **detaches** rather than
aborts; there is deliberately no `Drop` impl on the transport. So a dropped transport left a live task
holding a live TCP connection until the **server** timed it out — an unbounded task and
file-descriptor leak in any process that creates and drops transports repeatedly (a pool, a CLI loop,
a test suite), whose duration the **peer** chooses.

The race, in `read_next_sse_frame`:

```rust
let polled = tokio::select! {
    biased;
    frame = state.body.frame() => Some(frame),
    () = delivery.sender.closed() => None,
    _ = shutdown.changed() => None,
};
let Some(frame) = polled else {
    state.done = true;
    return Some(SseFrameStop::Shutdown);
};
```

Three properties of that shape are load-bearing and each is commented at the site:

1. **`biased;` with the body arm FIRST** — a frame already available is always consumed before a
   shutdown observed in the same wakeup, so a burst-then-close server does not lose its last frames
   (T-118.2-17-04).
2. **The state mutation happens AFTER the select, not inside an arm.** `state.body.frame()` borrows
   `state` mutably and a match scrutinee's temporaries live to the end of the match, so writing
   `state.done` inside a sibling arm would be a second mutable borrow. Assigning the select's result
   to a local ends the borrow first.
3. **The shutdown `watch::Receiver` is a parameter, not a field on `SseReadState`.**
   `Receiver::changed()` also takes `&mut self`, and two mutable borrows of one `state` cannot coexist
   in one `select!`. It is owned as a local by `read_sse_body`.

`read_sse_body` also consults the LEVEL before it parks at all:

```rust
let mut shutdown = delivery.shutdown.subscribe();
if *shutdown.borrow() {
    return SseBodyEnd::Ended;
}
```

A reader spawned **after** `close()` exits immediately rather than parking on a body nobody will read
from it. `changed()` alone would never fire for such a reader.

`Transport::close` sets the flag with `send_replace(true)` **before** aborting the GET handle; the
existing abort and the existing `terminate_session()` call are byte-unchanged.

### The cursor promotion

`deliver_sse_event` now writes **both** slots:

```rust
*last_event_id.write() = Some(id.clone());
*cursor = Some(id.clone());
```

The shared write is unchanged in timing and in value — that non-change is the point. The transport-wide
accessor means *"the most recent id seen on any stream"*; the reconnect needs *"the last id THIS
stream delivered"*. `run_session_stream` owns its cursor as a local across reconnect iterations (a
re-opened body that delivers nothing before dropping again must still resume from the last id this
stream saw), and `spawn_sse_reader`'s detached POST reader gets its own local that nothing reads back
— a POST response stream has no reconnect and therefore no cursor consumer.

The paired accessor kept its name and its shape:

```rust
#[cfg(feature = "v1-compat")]
fn reconnect_cursor(cursor: Option<&str>) -> Option<String> { cursor.map(ToString::to_string) }

#[cfg(not(feature = "v1-compat"))]
const fn reconnect_cursor(_ignored_cursor: Option<&str>) -> Option<String> { None }
```

and the call site still carries no `#[cfg]`:
`self.open_sse_once(reconnect_cursor(cursor.as_deref()))`. The `full-v2` twin's rustdoc carries the
warning forward and extends it: do not "improve" it by returning the argument *or* by reading
`last_event_id`.

### 3. [Rule 1 — Bug in my own new fence] Fence 20's `last_event_id()` assertion was racy, and the whole-suite run caught it

- **Found during:** Task 3, the first whole-suite run — which failed at **3195 run, 3194 passed, 1
  failed** while the isolated binary run had passed:
  ```
  assertion `left == right` failed: StreamableHttpTransport::last_event_id() must still report the
  most recent id from ANY stream — the POST's.
    left: Some("get-stream-e11")
   right: Some("post-stream-e97")
  ```
- **Issue:** the fence pushed both frames and then drained both. Both readers write the **one** shared
  `last_event_id` slot and **nothing orders those two writes** against each other, so under suite load
  the GET reader's write landed last. The assertion was measuring the scheduler.
- **Fix:** the two deliveries are now observed **one at a time** — push the GET frame, drain until it
  arrives, assert the slot holds the GET's id; then push the POST frame, drain until it arrives, assert
  the slot holds the POST's id. Because `deliver_sse_event` writes the slot **before** the send that
  `receive()` pops, each assertion is a fact rather than a race. This is strictly **stronger** than the
  original (it now also pins the intermediate state) and it removed the flake.
- **The amended fence was re-proved RED.** Changing a fence after its fix lands voids its RED
  evidence, so the WR-02 source change was set aside (`git checkout -- src/shared/streamable_http.rs`
  against the WR-01-only commit, with the work preserved out-of-tree and restored immediately after)
  and the amended fence run against the unfixed tree:
  `target/118.2-17-red-fence20.log` → **20 run, 19 passed, 1 failed**, failing on its subject with
  `Observed cursors: [None, Some("post-stream-e97")]`. The intermediate GET-id assertion **passed**
  there, confirming the new sequencing is deterministic on both trees.

### 4. [Design, recorded not a defect] `Arc<watch::Sender<bool>>` rather than the plan's bare `watch::Sender<bool>`

- **Found during:** Task 2, writing the field.
- **Issue:** `StreamableHttpTransport` is `#[derive(Clone)]`, so every field must be `Clone`, and
  `watch::Sender`'s own `Clone` impl arrived in a tokio later than the `1.46` this manifest declares as
  its minimum — a minimum not vendored here to measure against.
- **Disposition:** wrapped in `Arc`, following 118.2-15 deviation 4's precedent for `terminal_signal`
  verbatim rather than re-litigating it. It costs nothing (`send_replace` and `subscribe` both work
  through `&`), and it keeps the declared version floor honest instead of resting on a version claim.
  The field's rustdoc cites the earlier field's reasoning rather than repeating it.
