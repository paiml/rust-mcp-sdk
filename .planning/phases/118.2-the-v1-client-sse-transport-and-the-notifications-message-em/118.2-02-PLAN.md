**(a) The bounded receive channel (D-04).**

**Call-shape rule — the deadlock this plan must not introduce.** Two classes of sender exist and they
get different treatment, and the reason must be in a comment at each:
- **The spawned reader task** (`start_sse`'s task, and plan 03's POST-stream task) uses
  `sender.send(msg).await`. Backpressure lands on the reader, the TCP window closes, and the server
  stops writing. This is D-04's stated design: "The reader is already its own spawned task, so
  backpressure lands on the reader, not the consumer."
- **The caller-task sites inside `post_body`** (`:1501`, `:1606`, `:1613`, `:1655`, `:1662`) use
  `try_send` and, on `TrySendError::Full`, return
  `Err(Error::Transport(TransportError::Send(..)))` naming `CLIENT_RECEIVE_QUEUE_CAPACITY`. They must
  NOT `.await` capacity: `Client::dispatch_request` calls `send()` and only then loops on `receive()`,
  so a caller-task site that blocks on a full queue can never be drained by the consumer that is
  inside it — a self-deadlock. Failing loudly with a named error satisfies D-04's "never silently
  drops a frame" while keeping the send path non-blocking. `TrySendError::Closed` maps to the same
  error variant it maps to today.
