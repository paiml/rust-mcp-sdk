## Planner resolutions (Open-for-planning items answered here)

- **PR-01 — where the referenced runtime digest comes from (CONTEXT.md Open item 1).**
  `BinaryMode::Referenced { digest: ManifestDigest, media_type: String }` takes the digest
  **verbatim from the caller, non-optional**. `pmcp-package` treats it as opaque (milestone
  Decision 2 forbids a registry client). The canonical producer is already in the tree:
  `cargo-pmcp/src/deployment/targets/aws_lambda/artifact.rs:330-337` derives it via
  `pmcp_package::digest::ManifestDigest::from_bytes` against the release `.sha256` sidecar.
  Rustdoc must state that a bare-hex sidecar needs the `sha256:` prefix.
- **PR-02 — `unpack_server`'s return shape (amends D-06's container, not its enum).**
  D-06 locks the *enum return* for the binary; a 2-tuple cannot also carry the restored
  config and spec files that PKG-01 criterion 1 requires. `unpack_server` therefore returns
  a single `UnpackedServer { package, binary: UnpackedBinary, config, spec }`. D-06's
  load-bearing half is preserved verbatim: `binary` is the two-arm enum and `Referenced`
  has no bytes field. Rejected: a 4-tuple (unreadable) and a second entry point (the exact
  "two paths to keep in sync" D-06 rejected).
