<objective>
Make the baked-versus-slot split enforced rather than merely written down, and pin the
config-only package's packed manifest so a later layer-set change cannot ship silently.

Purpose: PKG-03 criterion 3 asks for a machine-checkable split — one byte of the spec must
move the digest and `verify` must reject the stale one, while endpoint, credentials and auth
mode surface as `ConfigSlot`s with no spec-derived slot among them. PKG-01/PKG-02 criterion 4
asks for a golden that catches a layer-set, layer-order or media-type change. The four
existing goldens pin `manifest_digest(value)` over a STRUCT, which is blind to all three
(D-12).

Output: the `[[config_slots]]` block inside the packed config bytes made the source of truth
that `pack` reads and enforces (D-01), pack-time `${VAR}` placeholder validation scoped by an
exhaustive three-way slot split (D-04 as amended by D-17), the real london-tube fixtures
copied in with a drift guard, a packed-manifest golden plus the spec-byte-change assertion,
and a cross-crate env-ref grammar table.
</objective>

## Planner resolution

- **PR-04 — where D-04's placeholder validation lives.** D-04 is locked as "**`pack`**
  validates"; RESEARCH.md's Pitfall 1 recommended moving it to the caller because `toml` is a
  dev-dependency only. The locked decision wins over the research recommendation, so `toml`
  is **promoted to a runtime dependency** of `pmcp-package` and the validation lives in the
  crate. Rejected: an optional `config-validation` cargo feature — `make pmcp-package-gate`
  runs exactly ONE build configuration (`Makefile:871-877`), so a feature axis would create a
  gate blind spot on the very code that upholds "secrets never travel". `toml` is a
  15.2M-downloads/week crate audited clean in RESEARCH.md's Package Legitimacy Audit and is
  already resolved in the crate's dev tree at 0.8.23, so this adds no new supply-chain
  surface. The crate still parses NO schema — it reads the `[[config_slots]]` declaration
  table, resolves a dotted path, and inspects one string value, so it holds no opinion about
  the toolkit's config shape beyond those three things.

  **PR-04 amendment (post-review):** the `toml` promotion now happens in Task 1 rather than
  Task 2, because Task 1 (the declaration-agreement check the cross-AI review forced) is the
  first code that needs a parser. The decision, the rejected optional-feature alternative and
  the supply-chain rationale are unchanged. The reach of the parser is slightly wider than
  originally scoped — it now also reads the declaration table, not only a dotted path — which
  is exactly what D-01's "`pack` reads them" requires and is recorded in the rewritten
  dependency comment and the `src/lib.rs` scope fence.

## Cross-AI review responses (120-REVIEWS.md — Codex, source-grounded)

- **HIGH — "The plan still does not prove `[[config_slots]]` is read from the TOML."**
  INCORPORATED, as a new Task 1 and the largest design change in this replanning. The
  criticism was exact and it was the phase's central gap: plan 120-04 parses declarations into
  toolkit-local `ConfigSlotDecl`, this plan's tests hand-built matching `ConfigSlot`s, and
  NOTHING compared the two — so a declaration could be edited or deleted while the package
  slot list stayed put, a caller could pass slots contradicting the config it ships, and
  D-01's "pack reads them" was true of no code path. `pack_server` now extracts the
  `[[config_slots]]` table from the SAME config bytes it is packing and requires exact
  agreement on key / kind / name / tested_value. No cross-crate dependency is introduced in
  either direction: the comparison rides on `ConfigSlotKind`'s snake_case discriminators
  already matching `SlotType::key()`'s kind strings (plan 120-04 now pins that).
  Rejected alternative, and why: DERIVING `package.config_slots` from the config bytes instead
  of comparing. It removes the duplicate, but it also silently overwrites whatever the caller
  passed, converting a caller bug into invisible behaviour — the comparison surfaces the same
  bug as a named error.
- **HIGH — "The validator's 'all variants except AuthMode are value slots' rule is too
  broad."** INCORPORATED. Confirmed against `slot/types.rs:25-73`: the existing variants
  include `HumanRole` (which carries `role`/`description`/`responsibilities`/`channel_hints`
  and no simple value at all), plus `OauthClient`, `ChannelBinding`, `LlmProvider` and
  `BudgetOverride` — none of which is a config-server TOML value. The rule is now a THREE-way
  exhaustive match: value slots (`Endpoint`, `Secret`) require an environment reference;
  `AuthMode` is structurally exempt (D-17); every other variant is not a config-value slot and
  carrying a `config_key` on one is itself a violation.
- **MEDIUM — "'Failed validation leaves no layout behind' is not precisely testable as
  written."** INCORPORATED. Confirmed at `oci/layout.rs:44-58`: `OciLayout::create` writes
  `oci-layout`, an empty `index.json` and `blobs/sha256/` before anything is packed, so "no
  layout behind" was never literally true and testing only "no index entry" would miss leaked
  config bytes sitting in `blobs/sha256`. Task 2's Test 7 now snapshots the blob directory
  before and after and asserts the file set is unchanged AND the index holds zero manifests.
- **MEDIUM — "Dotted TOML traversal does not define escaped/literal-dot keys."** INCORPORATED.
  The supported grammar is now stated and enforced rather than left to `split('.')`'s
  accidental behaviour, with named errors for empty components, leading/trailing dots, and
  traversal through a non-table. A TOML key whose literal name contains a dot is explicitly
  out of scope and is rejected as unaddressable rather than silently mis-resolved.
- **MEDIUM — "`env:`/`${...}` validation may drift from runtime behavior."** INCORPORATED as

- **LOW — "Task 1 says 'write the eight tests first' but lists nine behaviors."** INCORPORATED

- **LOW — "Skipping validation when `config_key` is `None` weakens D-04."** INCORPORATED with
