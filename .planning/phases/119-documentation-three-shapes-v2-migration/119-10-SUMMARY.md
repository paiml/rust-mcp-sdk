# Phase 119 Plan 10: Closing Gate & Disclosure Tripwire Summary

A tripwire that derives its expected set from the broken-windows ledger's `[CONSUMER-OBSERVABLE]`
sentinel and fails CI when a marked entry is not cited in the v2 migration chapter — observed RED
twice before being trusted — plus the phase's closing gate, run and recorded with its coverage
gaps named rather than glossed.

## What Was Built

`tests/windows_disclosure_tripwire.rs`, one test function
(`every_consumer_observable_window_is_cited_in_the_migration_chapter`) that:

1. Parses the authoritative four-backtick ` ````json ` array out of `.planning/WINDOWS.md` with
   `serde_json` (an existing first-order dependency), **not** the rendered markdown table above it
   — the table is a derived artifact regenerated by `gsd-tools`.
2. Selects every entry whose `description` contains `[CONSUMER-OBSERVABLE]`. **That selected set
   IS the expectation.** No id is written down anywhere in the file.
3. Asserts each selected id is cited in `pmcp-book/src/ch12-17-migrating-to-mcp-2026-07-28.md`.
4. Asserts the selected set is **non-empty** first, with its own message.

Measured derived set on the merged tree: entries **12, 13, 19, 20, 23** — computed, matching what
plan 119-05 marked, with nothing enumerated to make it match.

### Why derived rather than enumerated

A `const IDS: [u32; 5] = [12, 13, 19, 20, 23]` would pass on the day it is written and go blind on
the very next disclosure — which is the entire failure the tripwire exists to prevent, reproduced
inside the tripwire. Control B below proves the derivation by observation, not by inspection: a
hard-coded implementation fails that control by construction.

### The two excluded-tree guards

Both trees the test reads (`.planning/` and `pmcp-book/`) are in `Cargo.toml`'s `exclude` array,
so the `tests/v2_conformance_pin.rs:96-111` guard shape is applied **twice**, once per tree, each
with its own `fs::read_to_string` call site and its own rustdoc. The fork in each: an absent
*tree* returns early (a sparse checkout genuinely has nothing to read); a tree that **exists**
with the file missing **FAILS** — that is a deleted gate, not a packaging artifact.

## Negative Controls — the tripwire was observed RED before it was trusted

Third and final negative control of the phase. A gate never observed failing is not known to work,
and this phase has already caught three verification commands that measured nothing.

### Control A — a marked entry loses its citation

Temporarily replaced `- **WINDOWS.md entry 19 — three timing/text changes in the transport.**`
with a bullet carrying no entry id. **RED**, literal output:

```
thread 'every_consumer_observable_window_is_cited_in_the_migration_chapter' panicked at
tests/windows_disclosure_tripwire.rs:215:5:
FAILURE MODE: `.planning/WINDOWS.md` entries [19] are marked `[CONSUMER-OBSERVABLE]` but are not
cited in `pmcp-book/src/ch12-17-migrating-to-mcp-2026-07-28.md`. Each such entry is a behaviour
change a downstream consumer can observe that ships with NO semver signal, and that chapter is
the only place they learn of it — an uncited entry is a change disclosed to nobody.
WHAT TO DO: add a bullet for each id under `## Behaviour changes & known limitations` →
`### Consumer-observable changes with no semver signal` in
`pmcp-book/src/ch12-17-migrating-to-mcp-2026-07-28.md`, in the existing form
`**WINDOWS.md entry <id> — <what a consumer observes>**`, stating the old behaviour, the new
behaviour and what the consumer must do. If an entry is NOT in fact consumer-observable, remove
the `[CONSUMER-OBSERVABLE]` marker from its `description` in `.planning/WINDOWS.md` instead — do
not delete this assertion.
```

All three required message properties confirmed present: the **uncited entry id** (`[19]`), the
**sentinel literally** (`[CONSUMER-OBSERVABLE]`), and the **chapter path to edit**. Restored →
`1 passed`.

## The Packaging Decision (D-119-10-A) — and two accidents found while reviewing it

**Decision: EXCLUDE `tests/windows_disclosure_tripwire.rs`** (option b), with a `# Why:` block in
`Cargo.toml` matching the surrounding style. **Verified**: `cargo package --list` (538 files) does
not contain it.

**Reason**, taken from `Cargo.toml`'s own existing commentary rather than invented: shipping is
right for `tests/v2_conformance_pin.rs` because that pin *may* degrade to a downstream no-op, but
this reader's whole job is to **fail** when a disclosure is absent, and a reader that silently
skips is exactly the vacuous gate the phase exists to prevent. Excluding removes the skip path
entirely rather than relying on it. Same disposition, same reason, as
`tests/ci_conformance_gate_wiring.rs`. The in-file guards remain, covering sparse checkouts.

**The review of the other two new test files found accidents, not decisions.** `cargo package
--list` ships `tests/docs04_examples_run.rs` and `tests/docs06_v2_examples_run.rs`, and no plan
recorded a disposition for either. Neither can pass on the published crate: `docs04` runs examples
from `crates/pmcp-agent` and `crates/pmcp-team-servers` (not part of the published `pmcp` crate),
and `docs06` runs three root examples whose `required-features` are absent from `default`, one of
which also needs a path-only dev-dependency stripped on publish. **Measured, not inferred** — this
worktree started with an empty `target/`, reproducing the downstream shape exactly: `cargo test
--test docs04_examples_run` failed **3 of 3** legs with `… is missing. This leg FAILS rather than
skipping, by design`.

**Not fixed here** — it is a pre-existing repo-wide pattern, not something phase 119 introduced:
`tests/embedded_resource_example_run.rs` and `tests/log_records_example_run.rs` already ship today
with the identical hazard (both read `s54_v2_dual_conformance`, `required-features =
["streamable-http", "testing"]`). Fixing two of four instances would leave the convention less
consistent than it is now. Full record, with the fix options, in `deferred-items.md`.
