Move the loop into `scripts/run-example-builds.sh` and reduce the Makefile target to a delegation,
mirroring `test-severance`.

**The script.** `scripts/run-example-builds.sh`, `set -euo pipefail`, executable. Its header
explains, in the house style, three things: why it exists (the previous in-Makefile loop reported
a build failure as "skipped" and exited 0, so an example that stopped compiling was invisible);
why the count is load-bearing (a runner that builds nothing and reports success is the same false
green in a different shape); and which trees it covers and which it deliberately does not.

Behaviour:
  - Build examples in three trees: root, `-p pmcp-agent`, `-p pmcp-team-servers`. Prefer one
    `--examples` build per tree over a per-example loop — it is faster, and cargo already reports
    each failing target. Keep `--all-features` as the primary attempt and `--features full` as
    the documented fallback ONLY if a tree genuinely needs it; do not add a fallback that exists
    only to hide a failure.
  - Do NOT redirect compiler stderr to `/dev/null`. The diagnostic is the point.
  - Count the examples discovered per tree and FAIL with exit 1 if any tree discovers zero — a
    zero-count run must be a failure, not a pass. This is the same guard
    `run-severance-proofs.sh` carries.
  - On any build failure, print a summary naming the tree and the failing target and exit 1.
  - On success, print a counted summary of the form "N examples built across 3 trees, 0 failures".
  - Do NOT build any workspace-excluded sub-crate under `examples/<dir>/Cargo.toml`. Add a
    comment naming that exclusion and pointing at this phase's `deferred-items.md` record, so the
    next reader finds the measured reason rather than guessing.

**The Makefile target.** Replace the body of `test-examples` with an echo, the script invocation,
and a success echo — the `test-severance` three-line shape. Above it, add a comment block in the
`lint-plans` style recording: that this target IS chained into `quality-gate` through `test-all`
and must stay chained, because `test-integration` depends on it having built the example binaries
the run tests assert against; that it was previously non-blocking and the change is deliberate;
and that the baseline it lands against is recorded in this phase's `deferred-items.md` rather
than being zero by assumption. Update the stale "Examples are built but not run to avoid blocking
on I/O" echo — it is no longer the whole truth now that `tests/docs04_examples_run.rs` and
`tests/docs06_v2_examples_run.rs` run them.

Do not change `test-all`'s or `quality-gate`'s target lists.
