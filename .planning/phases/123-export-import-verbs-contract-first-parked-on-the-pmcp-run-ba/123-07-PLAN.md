`cargo-pmcp/fuzz/Cargo.toml` with the same `[[bin]]` shape the existing targets use.

**The boundary.** Arbitrary bytes go straight into `read_verified` through the lib seam — that is the
real untrusted-input boundary this phase created, and it is the direct analogue of the manifest-parse
boundary `fuzz_package_kind` already campaigns. The target body should be small: take the raw slice,
call the reader, discard the result. Do not pre-shape the input into a valid tar; the point is the
adversarial-bytes path.

**Assert a non-tautological invariant — and scope the campaign to what fuzzing actually proves (review
finding M4).** The weak version — "it returned `Ok` or `Err`" — is a tautology a broken implementation
passes. Assert instead, on any `Ok`:

- every returned blob key is exactly 64 lowercase hexadecimal characters; and
- every blob's content hashes to its own key; and
- the descriptor graph is closed — every descriptor `VerifiedArtifact` carries resolves to a present
  blob, and every present blob is referenced.

A reader that stopped re-deriving digests, or that admitted an orphan blob, violates those and the
campaign catches it. Those are the properties fuzzing is well suited to: they hold over EVERY accepted
input, so any accepted input is a test case.

**Do NOT try to prove the byte caps from this campaign, and do not add an uninstrumented "peak
in-memory retention" property.** The reviewed draft proposed disabling the per-entry cap and running a
short campaign to demonstrate falsifiability. That experiment is not credible and must not be run as
evidence: arbitrary bytes are overwhelmingly unlikely to produce a multi-megabyte well-framed tar entry
within a short campaign, "peak in-memory retention" has no instrumentation behind it, and the
key/digest invariant is unrelated to the cap — so disabling the cap could not falsify the thing being
asserted. A green campaign against a disabled cap would be evidence of nothing, and recording it as
falsifiability evidence would be worse than recording nothing.

Cap falsifiability is discharged DETERMINISTICALLY, in plan 01, by the `ArtifactLimits` /
`read_verified_with_limits` pairs: the same input refused under a tiny injected cap and accepted under
a large one, with the refusal asserted by message. Point at those tests from this target's module
header rather than duplicating the claim here, so a reader can see where each property is actually
established.

**Prove THIS target's invariant is load-bearing, with an experiment that can actually fail.** Disable
the per-blob digest re-derivation in `read_verified` and re-run a short campaign seeded with the
conformant golden fixture from plan 04 plus a copy of it with one blob byte flipped. The invariant must
fail on the flipped input. Restore, observe a clean campaign. Record both runs in the SUMMARY. Seeding
matters: an invariant that only arbitrary bytes can reach is an invariant nobody has watched fail, and
this repo has a recorded case of a campaign staying green while the gap it was meant to cover was open.

**Module header.** Copy `fuzz_package_kind.rs`'s structure: the phase and requirement it serves, the
boundary it campaigns, the invariant in one sentence, the threat model IDs it exercises (the tar
traversal, symlink, duplicate-entry and allocation-bomb threats this phase registered), the full run
command, and a quick-smoke command with a bounded total time.

**Run a real campaign, not a build check.** Execute at least 20,000 runs and record the run count, the
elapsed time, the corpus size and that the artifacts directory is empty. Use absolute binary paths when
proving the artifacts directory is empty — this project has a recorded case of a shell proxy reporting a
spurious count for a demonstrably empty directory.

If the nightly toolchain `cargo fuzz` requires is unavailable in this environment, do not fake the
evidence: record that the target and its `[[bin]]` entry are in place, that `cargo +nightly fuzz build
fuzz_package_artifact` was attempted, and exactly what blocked it. A truthful blocked note is worth more
than an asserted campaign.
