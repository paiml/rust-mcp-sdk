<objective>
Reverse the Phase-113 DRIFT-1 adjudication for the `Mcp-Name` header, per locked decision **D-13**:
`Mcp-Name` becomes REQUIRED only on name-bearing methods, matching the MCP 2026-07-28 transport
spec and the official `@modelcontextprotocol/conformance` suite. The strict name/body cross-check
is KEPT exactly where a name exists.

Purpose: RESEARCH Pitfall 1 measured that pmcp's presence-on-every-request rule rejects the
official suite's v2 `tools/list` (and every other non-name-bearing v2 request) with
`-32020 "v2 requests must carry Mcp-Method, Mcp-Name and MCP-Protocol-Version headers"` **before
dispatch**, which fails effectively the whole v2 scored set. CONF-01's v2 leg cannot go green
without this. The user explicitly authorized this ONE server-behaviour change as an exception to
the phase boundary.

Output: a relaxed, still-fail-closed v2 header gate; a rustdoc block that records BOTH
adjudications (113 DRIFT-1 and its 118 D-13 reversal) and why; and a wire-level integration test
that proves the new matrix over real HTTP.

   non-name-bearing method, so it needs NO edit — do not touch it.

     that names it would mislead operators);
