**Field — RENDER ONCE, not per request (REVIEWS fable (b)).** Add
`#[cfg(feature = "skills")] projected_skill_prepend: Option<String>` to
`WorkflowPromptHandler`, defaulting to `None` in every constructor. The field holds the
**already-rendered body**, not a bool. A `#[cfg]`'d field is safe here: the struct's `Debug`
impl is hand-written at `:105-118` so no derive needs updating, and every constructor is
in-file. A bare `#[cfg(feature = "skills")]` is the correct gate — `pub mod workflow` is
already `#[cfg(not(target_arch = "wasm32"))]` at `src/server/mod.rs:164-165`, so the two gates
compose to exactly `skills`'s own gate and no `all(...)` is needed.

Why a cached `String` rather than a `bool` consulted per request — three measured reasons, all
of which belong in the field's doc comment:
1. The D-15 slug-fallback `tracing::warn!` would otherwise re-fire on **every `prompts/get`**,
   turning a build-time diagnostic into a per-request log flood.
2. Message [0] would be re-derived from the handler's own clone of the workflow, while the
   digest published in `skills/list` is a snapshot taken at registry-build time. Two
   independently-derived strings that are *supposed* to be identical is exactly the drift this
   phase exists to prevent — caching makes them one string by construction.
3. Rendering is not free, and `handle` is a hot path.

**Setter.** `#[cfg(feature = "skills")] #[must_use] pub fn with_projected_skill_prepend(mut self, on: bool) -> Self`.
Keep the `bool` parameter — it is the ergonomic shape and matches `Skill::with_path` /
`with_description`'s spelling — but the body does the render: on `true`, set the field to
`Some(self.workflow.as_skill().body().to_string())`; on `false`, set it to `None`. **This is
the only place in the whole file that calls `as_skill()`.**
Its rustdoc must state the resulting transcript shape explicitly — `[0]` projected body,
`[1] create_user_intent`, `[2..]` guidance / resource / tool-call / tool-result messages
unchanged — and must state that `create_assistant_plan`'s MESSAGE is suppressed while
`create_user_intent` is kept because the latter's `Parameters:` block is the only place the
caller's actual argument VALUES appear, whereas the projected body carries argument SPECS.
It must also state that the body is rendered once, here, so a caller knows a later mutation of
the workflow value would not be reflected. Include a self-gated doctest.

Both handlers call THIS — one producer, so `TaskWorkflowPromptHandler` cannot drift from
`WorkflowPromptHandler`.

**Suppress `create_assistant_plan`'s MESSAGE — but keep its CALL (D-04a + REVIEWS fable (a)).**

`suppress_plan` is false.

only the message is dropped. Attach a `// Why:` comment to the `create_assistant_plan()?` line
